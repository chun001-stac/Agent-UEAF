# UEAF V1 持久化与事务映射规范

版本：`0.2.0-draft`  
规范状态：Draft  
Architecture Generation: `V1`  
Maturity: `Required for Implementation`  
Implementation: `Current`

## 1. 目的

本文定义 V1 权威对象、Projection、Telemetry、Artifact 与物理存储之间的 Reference Mapping，并规定事务、CAS、fencing、outbox、幂等和租户隔离边界。

原则：**Semantic Owner 决定事实语义；物理数据库不获得第二语义所有权。**

## 2. Reference Physical Components

首个 Reference Profile：

```text
PostgreSQL 16+
NATS JetStream behind queue/event adapter
OpenTelemetry-compatible telemetry backend
S3-compatible object/artifact store; local MinIO
secret provider adapter
```

不建设 Evolution 专用 Vector DB、Graph DB、TSDB 或 GenePool DB。

## 3. PostgreSQL 逻辑 Schema

```text
core_*        task/run/state/outbox
context_*     manifests/registry refs
model_*       invocation summaries/route metadata
action_*      actions/attempts/receipts/approvals
workflow_*    workflow runs/nodes where authoritative implementation requires
security_*    policy/security decision refs/tables owned by security domain
eval_*        eval configs/runs/results/quality gates
release_*     candidates/decisions/manifests
evolution_*   V1 five canonical objects
projection_*  summaries/windows/fingerprints/read models
```

Audit/Trace/Log 不因查询方便混入普通业务表成为第二权威存储。

## 4. 公共列与 `ContractMeta`

跨模块持久化对象的数据库映射必须能够完整重建核心 `ContractMeta`。ORM 可以拆列，但不能丢失：

```text
contract_name / contract_version
object_id
tenant_id
created_at
producer / producer_version
classification
purpose
provenance
integrity_ref when required
expires_at when applicable
extensions
```

对象领域 ID 与 `meta.object_id` 必须一致。

内部 DB-only 字段（revision、row lock version、lease、internal pk）不得反向污染公共 Schema。

## 5. Authoritative Table 最小集合

### Core

```text
task_states
run_records
run_admission_results
checkpoint metadata/refs
```

### Action

```text
action_records
execution_attempts
action_receipts
approval_requests
idempotency_reservations or equivalent unique reservation
```

### Eval / Security / Release

```text
eval_configs
eval_runs
eval_results
quality_gate_decisions
security_gate_decisions           owned by security domain
operational_readiness_decisions   owned by operations domain
release_candidates
release_decisions
release_manifests
```

物理上可分 schema/store；Release 只通过稳定 ref 消费其他 Owner 的决定。

### Evolution

V1 仅：

```text
evolution_triggers
evolution_runs
genome_manifests
mutation_proposals
evolution_authority_policies
```

禁止：

```text
fitness_records
gene_spaces
repair_history_authority
lineage_authority
evolution_budget_ledger
```

## 6. Projection Table

MAY 物化：

```text
run_summaries
rolling_aggregate_windows
error_fingerprints
trigger_candidate_views
fitness_comparison_views
lineage_views
repair_history_views
mutation_review_views
```

Projection 必须保存 source refs、projection version 和 rebuild marker；允许删除重建，不能反写权威对象。

## 7. Key / Tenant / Revision

tenant-scoped mutable authoritative row SHOULD 有：

```text
tenant_id
canonical object id
revision
created_at
updated_at
```

不可变 Manifest/Proposal/Genome 内容 append-only；生命周期变化用规范允许的状态字段/事件或新对象表达，不覆盖历史内容。

所有高风险查询强制 tenant 条件或 DB 级隔离；跨域 `*_ref` 在语义层验证存在性和兼容性。

## 8. Run Transaction

```text
BEGIN
  read current revision
  verify expected phase/revision/lease fencing
  apply legal state transition
  UPDATE run_records ... revision = revision + 1
  INSERT outbox row containing canonical EventEnvelope payload/ref
COMMIT
```

禁止：

```text
read state
remote call
blind UPDATE without revision guard
```

## 9. CAS / Lease / Fencing

```text
new lease -> monotonically larger fencing_token
checkpoint/state/action dispatch carries token
stale token -> reject
```

旧 Worker 恢复后不能覆盖新 Worker 已提交状态。

## 10. Action Identity 与 Transaction Boundary

动作身份必须在授权前稳定，但外部副作用执行必须在授权/审批/预留后发生。

### TX-A：创建稳定动作身份

```text
BEGIN
  server-side canonicalize tenant/principal/capability/resource/args/purpose
  compute action_fingerprint + stable action_key
  INSERT ActionRecord(proposed) including both
  INSERT outbox canonical action/domain fact when required
COMMIT
```

同一逻辑动作身份冲突按 `action_key + fingerprint` 处理；此阶段 **不执行外部副作用**。

### Policy / Approval

```text
ActionRecord proposed -> validating -> authorizing
PDP -> PolicyDecision
if require_approval:
  durable ApprovalRequest
  approved + unchanged -> re-evaluate PDP
```

### TX-B：预留执行权

只有最终 `PolicyDecision=allow` 后：

```text
BEGIN
  verify ActionRecord revision / current policy / approval
  reserve existing action_key + fingerprint idempotently
  ActionRecord -> reserved
  create/refresh execution lease + fencing token
  INSERT outbox
COMMIT
```

### External Call

事务外执行远程 Tool/API。

### TX-C：记录观察

```text
BEGIN
  append ExecutionAttempt
  append ActionReceipt(succeeded | failed | unknown)
  CAS ActionRecord
  if unknown -> reconciling
  else -> legal next/terminal state
  INSERT outbox
COMMIT
```

绝不把远程 API 调用包在 DB transaction 中。

## 11. Action Idempotency / Unknown

`action_key` 必须唯一且与 `action_fingerprint` 绑定。

```text
timeout / disconnect / crash after possible side effect
  -> outcome certainty unknown
  -> ActionRecord reconciling
  -> QueryAction / authoritative reconciliation
  -> only after certain outcome decide retry/terminal
```

不得新造不同 action_key 重试同义副作用。

## 12. Evolution Transaction

### Trigger

`EvolutionTrigger` row 必须保存：

```text
subject_ref / trigger class+type
threshold/profile refs
evidence/gate evidence refs
operational mitigation refs
observed_at / expires_at
```

当前 V1 模块化单体 MAY 在同一事务写内部 lifecycle metadata/outbox transport record；不得伪造尚未进入核心事件目录的 public `ueaf.evolution.*` EventEnvelope。

### EvolutionRun

创建时冻结：

```text
trigger_ref
baseline_genome_ref
budget_ref
mutable_scope
strategy_ref
active_working_set_ref
```

不得运行中静默切换。

### Mutation / Genome

```text
MutationProposal append-only
-> machine validation
-> materialize new immutable GenomeManifest candidate
-> CandidateBuildPort builds ReleaseCandidate
```

Proposal 修订产生新 proposal/version/attempt metadata，不覆盖旧提案。

## 13. Genome / Artifact

`GenomeManifest` 是不可变引用图。Prompt、代码、Workflow bundle、SBOM、Trace Payload 不复制进 Genome table，只存 Registry/Artifact refs、provenance 和 integrity refs。

## 14. Eval / Release

`EvalResult` append-only；重跑产生新结果。

`ReleaseManifest` 机器字段使用核心版本集合语义，例如：

```text
agent_versions
prompt_versions
schema_versions
model_route_versions
capability_versions
adapter_versions
knowledge_index_versions
memory_policy_versions
policy_versions
```

Manifest signing 前验证：

```text
required decision refs active
same candidate/environment/scope
integrity refs valid
rollback target/constraints present when required
```

## 15. Transactional Outbox

状态变更和可靠发布必须：

```text
business/domain row change + outbox insert = same local transaction
publisher async sends
consumer idempotently applies
```

Outbox 是 transport implementation，不定义第二套 Event Schema。建议存：

```text
outbox_id
canonical event_id
event_name
event_version
aggregate_type
aggregate_id
aggregate_version
sequence
payload_schema_ref
serialized EventEnvelope or immutable payload_ref
created_at
published_at
attempt_count
```

不得只存 `event_type/aggregate_ref/revision` 并让 publisher 猜核心 EventEnvelope 缺失字段。

## 16. Queue Consumer

至少一次投递；consumer：

```text
dedup by event_id
verify aggregate version/sequence
apply local transaction
commit local dedup/projection state
then ACK broker
```

sequence gap -> stop/repair projection，不宣称完整。Poison message 可 parking/DLQ，不无限阻塞。

## 17. Telemetry / Audit / Artifact

```text
Metric -> observability backend
Trace -> tracing backend
Log -> log backend
Audit -> independent integrity/retention store
Run Summary/Fingerprint -> projection store
large artifact/evidence -> S3-compatible object store
```

Audit 保留不受普通 Telemetry 成本策略削减。

## 18. Retention

必须分开：

```text
authoritative state
Audit/legal
Telemetry
sampled trace
Evolution active working set
Artifact
Projection rebuild lifecycle
```

统一 TTL 禁止用于所有数据。

## 19. Migration

Migration MUST：

- 有版本和 migration ref；
- CI/预生产验证；
- destructive change 有备份/恢复策略；
- 与 ReleaseCandidate/ReleaseManifest 对齐；
- 显式处理长运行版本共存。

## 20. Reference DB Checks

至少机器实现：

```text
Run nonterminal -> completion_disposition IS NULL
Run terminal -> completion_disposition IS NOT NULL
revision monotonic
stale fencing reject
action_key uniqueness
action_key/fingerprint conflict reject
receipt append-only
Genome immutable content
ReleaseManifest immutable content graph
tenant isolation
outbox event_id uniqueness
```

跨字段/跨表无法用 CHECK 表达的规则必须有 transaction validator + contract test。

## 21. Codex 实施规则

Codex MUST：

1. 先区分 authority / projection；
2. 不复制第二份权威状态；
3. mutable state 使用 CAS/revision；
4. action identity 在 PDP 前稳定，side effect 在 PDP/approval/reservation 后执行；
5. unknown 先对账；
6. 可靠事件使用 outbox，但 outbox 不重定义 EventEnvelope；
7. 不跨远程 API 保持数据库事务；
8. 不用 ORM cascade 隐式跨域删除事实；
9. 测试 tenant isolation、duplicate action、stale fencing、outbox replay、sequence gap。

## 22. 完成定义

- 每个 authoritative object 有明确物理映射；
- Projection 与 authority 分离；
- Run/Action/Evolution/Eval/Release 事务顺序与核心规范一致；
- action_key 创建、Policy、reservation、execution、reconciliation 顺序无歧义；
- Outbox 保留核心 EventEnvelope 语义；
- NATS/Postgres/MinIO 是 Reference Profile，而非 UEAF 语义依赖；
- Codex 不需要自行发明一致性模型。
