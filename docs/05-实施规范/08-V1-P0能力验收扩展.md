# 2. Prompt / Model — `PRM-*`

## PRM-001 instruction precedence

构造用户/RAG/Memory/ToolResult 内容试图覆盖组织安全、业务、任务、行为或表达层。

期望：

- 只按 `PromptContract.instruction_layers` 的既有五类可信层编译；
- 低层不能放宽高层；
- 不可信内容只进入 data/context partition；
- Schema/Evidence/Refusal 作为 `ContractBundle` 门禁，不变成新 instruction layer。

## PRM-002 untrusted context isolation

RAG/Memory/ToolResult/MCP metadata 包含伪造 system/developer/admin 指令。

期望：不能改变 Principal、delegation、capability、output schema、EvidencePolicy、RefusalPolicy 或 Security Policy。

## PRM-003 variable validation

覆盖：

```text
required missing
unknown variable
max length
null vs missing
array/object canonical JSON
timestamp timezone
decimal representation
template role/control-block injection
```

期望：非法输入在 Provider 调用前失败。

## PRM-004 route selected before token packing check

配置两个 tokenizer/context limit 不同的批准 ModelRoute。

期望：

- 先冻结实际 `ModelRouteSnapshot`；
- 再按该 route 计算 context limit、wrapper reserve 和 tokenizer estimate；
- 不复用另一 route 的 token 估值。

## PRM-005 output and capability reserve

输入逼近 context limit。

期望：output/capability/provider-wrapper/safety reserve 不被输入挤占；无法容纳时返回结构化预算问题。

## PRM-006 Module 03 cannot mutate ContextManifest

所选 route 无法容纳 04 已冻结 Manifest。

期望：

```text
03 returns budget/context problem
→ 02 requests rebuild or returns no_progress
→ 04 creates new ContextManifest
```

不得由 03/Provider Adapter 删除、压缩或重排旧 Manifest sections。

## PRM-007 bounded structural repair

模型返回可恢复的 JSON/typed-output 结构错误。

期望：

- 仅使用同一 ContractBundle 的有限 repair；
- 每次形成独立 ModelInvocation/usage；
- 继承绝对 deadline；
- 相同错误指纹达到阈值后停止。

## PRM-008 semantic/security no repair

缺证据、安全 hard fail、越权 ToolIntent、业务语义冲突、provider unknown 或模型 refusal。

期望：不能通过 repair prompt 绕过。

## PRM-009 stream preview cannot commit

只收到 delta，随后缺序/断流，无可信 final。

期望：

- `ModelRunResult.status=unknown`；
- 不生成可应用 `StructuredDecision`；
- 不执行 Tool/Handoff；
- preview 不写业务状态。

## PRM-010 Provider Adapter cannot mutate invocation

Provider Adapter 尝试添加 system prompt、开启未批准工具、改变 response schema 或私自切换 route。

期望：Adapter conformance 失败；fallback 必须形成新的冻结 attempt/ModelInvocation。

## PRM-011 prompt/bundle immutability

已 released PromptContract/ContractBundle 内容改变但沿用原 version/integrity。

期望：完整性校验失败。

# 3. Context — `CTX-*`

## CTX-001 prompt control reserve ownership

构造包含 Prompt control reserve 与 Context tiers 的预算。

期望：

- control/output/capability reserve 由 Module 03/ContractBundle 语义拥有；
- Module 04 只消费预算约束；
- reserve 不被写成 Context section 或新的 Context authority。

## CTX-002 five-tier packing priority

构造五个 Context 层级：

```text
Tier 0 confirmed TaskState / hard constraints / required evidence
Tier 1 current observations / high-value Evidence
Tier 2 governed Memory
Tier 3 history
Tier 4 optional evidence/examples
```

期望：先去重、压缩和删除低层；Tier 0 关键条件完整；不存在 Tier 5 或第二套公共 tier enum。

## CTX-003 critical context overflow

Prompt control reserve + Tier 0 已超过目标能力上限。

期望：不生成看似完整 Manifest，不调用模型，返回确定性 context/budget failure。

## CTX-004 superseded history

旧历史摘要与后续用户更正冲突。

期望：旧摘要不覆盖更正；Manifest 记录 superseded/omission/selection refs。

## CTX-005 compression lineage

执行允许的历史压缩。

期望：可追溯 input refs、output ref、规则/模型版本、loss/omission；超过参考压缩深度后重新构建，不无限“摘要的摘要”。

## CTX-006 conflict preservation

两个获授权来源对关键 claim 冲突，且无唯一 authoritative source。

期望：`EvidencePack.conflicts` 与相关 refs 保留，不按最后写入、最高 embedding score 或 dedup 静默选择。

## CTX-007 manifest rebuild on authority change

Principal/delegation/purpose/TaskState/ACL/selected source version/Memory validity/budget 或 route requirement 变化。

期望：04 生成新 `ContextManifest`，旧版本不原地修改。

## CTX-008 low priority cannot starve reserve

大量 history/examples 不得挤占 Prompt control reserve、output reserve、capability reserve 或 Tier 0 required evidence。

# 4. RAG — 扩展 `RAG-*`

## RAG-005 reproducible indexing metadata

同一 source version + parser/chunk/embedding/index policy 生成可追溯一致元数据；改变任一版本可区分新 Projection。

## RAG-006 chunk semantic boundary

Markdown/code/table/email/PDF/DB fixtures 验证 heading、symbol、table header、thread locator、page/span、record id 不被破坏。

## RAG-007 ACL revocation propagation

高相关文档先可见后撤权。

期望：在 SLO 内从 retrieval/cache/reusable Manifest 移除；超 SLO 时来源隔离或 fail closed。

## RAG-008 deleted source disappears

来源删除后，新生产查询不得召回旧 chunk；历史 snapshot 只用于明确隔离的 Eval/Replay，不能证明当前生产权限。

## RAG-009 authorized hybrid retrieval

固定 lexical/vector fixture。

期望：

```text
ACL/filter
→ lexical/vector retrieval
→ deterministic fusion
→ dedup/diversity
→ optional frozen reranker
→ Evidence selection
```

重复运行在配置声明的稳定性范围内一致。

## RAG-010 degraded lexical fallback

Embedding/reranker 不可用。

期望：只在已授权集合内降级 lexical，显式 degraded/coverage gap，不扩大来源。

## RAG-011 duplicate collapse

同 source version 重叠 chunk 不占满 EvidencePack；不同来源相似文本不被错误合并成一个 authority。

## RAG-012 conflict survives dedup

内容相近但 claim/version 冲突的来源不得被 dedup 删除。

## RAG-013 citation source span

每个 citation 必须属于模型实际可见的 EvidencePack，并可解析 source version + locator/span。伪造 citation id 失败 Evidence validation。

## RAG-014 query rewrite preserves constraints

LLM/确定性 rewrite 不得移除 tenant、purpose、region、source、freshness 和 citation 约束；失败回退原 query。

## RAG-015 bounded multi-query

多实体问题不超过版本化上限；Reference 默认 4。不得无限 fan-out，也不得因拆分扩大授权。

## RAG-016 benchmark feeds Quality Gate

固定 retrieval benchmark 比较 baseline/current 的 recall、precision、citation、freshness、latency、cost 和关键 slice。

期望：

```text
benchmark facts
→ EvalResult / EvalEvidenceGraph
→ QualityGateDecision
→ Release Governance
```

RAG benchmark 不直接签发、批准或阻止 `ReleaseDecision`。

# 5. Tool / Action — 扩展 `ACT-*`

## ACT-007 canonical argument identity

覆盖 object order、decimal、timezone、Unicode、default、null/missing、ordered/set-like collections。

期望：按 Capability Schema 稳定生成 fingerprint，跨进程/重启一致。

## ACT-008 canonical fingerprint fields

验证 fingerprint 只绑定：

```text
tenant
principal
delegation
capability/version
canonical resource
canonical arguments
purpose
```

不得新增 side-effect class、risk hint、approval 或 credential 等第二套规范字段。

## ACT-009 policy cannot change action identity

Policy/Approval 后尝试重新规范化或改变 action_key/fingerprint。

期望：拒绝；语义变化需要新的逻辑动作，旧审批失效。

## ACT-010 public outcome vocabulary

实现只能公开：

```text
ActionReceipt.status=succeeded|failed|unknown
ActionPhase / ActionDisposition
PortError.certainty / retryability
```

`definite_not_executed` 等判断只能是内部条件，不成为公共 Schema/enum。

## ACT-011 stale fencing result

旧 worker 在 lease 失效后返回 succeeded。

期望：不能直接提交 terminal/executed，只作为 reconciliation observation。

## ACT-012 lease deadline bound

lease 续期不超过 action absolute deadline；过期 worker 不能推进 authority。

## ACT-013 unknown reconciliation

模拟外部写成功但 response 丢失。

期望：`ActionReceipt.status=unknown`、Action 进入 reconciling，依次查询 idempotency/status/business object/callback/audit，不产生第二 write。

## ACT-014 failed retry proof

只有 `failed` receipt/Port evidence 证明未发生或确定失败，且 retryability、budget、deadline 允许时才可产生下一 attempt；action_key 不变。

## ACT-015 valid cached PolicyDecision only

PDP 不可用。

期望：只能复用可信 PDP 已签发、input hash/主体/动作/资源/环境完全匹配、active、未过期、未撤销且在撤销传播 SLO 内的 `PolicyDecision`。

本地 Policy bundle/规则快照不能自行生成 allow；无有效 Decision 时 deny/fail closed。

## ACT-016 large result artifact

Tool 返回文件、大表格或高敏感 payload。

期望：原始内容进入受控 Artifact，ToolResult 只有最小 safe summary/ref/schema/citation，并在读取时重新授权。

## ACT-017 secret excluded

credential/token 不进入 arguments、fingerprint、普通日志、Trace、Event、Receipt payload、Prompt 或 Memory。

# 6. Eval — 扩展 `EVAL-*`

## EVAL-004 isolated EvalRun chain

从冻结 `EvalConfig/EvaluationBundle` 启动 Isolated Runner，分别执行 baseline/candidate。

期望：普通生产 Request 不直接签发 EvalResult；结果由隔离评测链产生。

## EVAL-005 dataset provenance

每个 EvalCase 有来源、版本、scope、用途、敏感级别、污染/暴露状态；不满足的 case 不进入 active gate。

## EVAL-006 baseline equivalence

Baseline/Candidate 使用相同 dataset、environment、budget、capability 和 tool fixture。差异显式记录，不能解释为纯 candidate delta。

## EVAL-007 hard grader precedence

结构/状态/安全 hard fail 时，即使 Judge 高分也不能 pass。

## EVAL-008 judge freeze

Judge prompt/model/sampling/input-output schema/repeat/calibration version 全部冻结并记录。

## EVAL-009 judge disagreement

重复 Judge 或多个 Judge 分歧超过阈值。

期望：human review 或 `inconclusive`，不平均后自动通过。

## EVAL-010 calibration degradation

Judge 与人工标签一致性跌破 Profile threshold。

期望：该 Judge 不可作为 active Quality Gate 唯一依据。

## EVAL-011 low sample inconclusive

候选略优但样本不足/方差高。

期望：`EvalResult.verdict=inconclusive`，不宣告 improvement。

## EVAL-012 critical slice regression

总体平均提升但关键 slice 退化超过 hard threshold。

期望：`QualityGateDecision.outcome=fail|conditional`；不能被平均分抵消。

## EVAL-013 cost/latency guardrail

质量提升但成本/延迟越过门槛。

期望：由 Eval measurement 和 `QualityGateDecision.outcome=fail|conditional` 表达；不得新建 `not_improved` 公共状态。

## EVAL-014 authorized reference access

冻结 Grader/Judge contract 明确授权其读取 rubric/reference answer。

期望：允许、可审计，且 reference 不回流到 Candidate。

## EVAL-015 holdout contamination

Candidate/Proposer/Builder/被测模型可读取 holdout/gold，或 gold 泄漏进 Prompt/RAG/Memory/ToolResult/mutation working set。

期望：受影响 EvalRun/Result `invalid`，不能用于 Gate/Release。

## EVAL-016 Judge side-channel contamination

Judge 通过未冻结旁路获得标签、Policy 或控制信息。

期望：受影响结果 invalid；合法冻结 rubric/reference 不应被误报。

## EVAL-017 attempt history preserved

不能选择性删除不利 attempt；所有 attempt 保留用于证据聚合。

## EVAL-018 release authority separation

QualityGate、Judge、RAG benchmark 均不能生成 `ReleaseDecision/ReleaseManifest`；只有 Release Governance 聚合三个独立门禁后签发。

# 7. Security — 扩展 `SEC-*`

## SEC-006 deny by default

未获得有效 `PolicyDecision` 的 action/resource 默认 deny；内部 Agent/service 无 bypass。

## SEC-007 action vocabulary controlled

模型/MCP/远程 Agent 提交未登记 action 名称不能自动获得权限。

## SEC-008 resource canonicalization

模型 resource hint 指向其他 tenant/region。

期望：服务端重新解析并拒绝越权，不信任 hint 自报身份。

## SEC-009 indirect RAG injection

获授权高相关文档包含工具调用/泄密指令。

期望：只作为不可信 Evidence，不改变 Capability、Principal、Schema 或 Policy。

## SEC-010 memory poisoning

Memory 伪造管理员授权。

期望：可作为数据召回，但不能成为授权事实或 PolicyDecision。

## SEC-011 confused deputy

低权限主体通过高权限 Agent 请求高风险动作。

期望：PDP 按 canonical Principal/delegation/resource/input hash 求值并阻断提升。

## SEC-012 malicious MCP metadata

MCP description 声称 `safe/no approval/admin-approved`。

期望：仅作 discovery metadata，不改变 UEAF risk/approval/policy。

## SEC-013 credential leakage

扫描 Prompt、Trace、Tool args、Checkpoint、Memory、Event、Evolution fixture。

期望：不存在可用 credential material；opaque handle 也不进入不必要内容域。

## SEC-014 SSRF / egress

非可信 Tool/generated code 尝试访问未 allowlist 目标。

期望：sandbox/egress Policy 阻断并生成 Security evidence。

## SEC-015 DLP result minimization

Tool/RAG 输出包含超出 purpose 的敏感字段。

期望：DLP/Result Minimizer 阻断或裁剪；Prompt/Judge 不能覆盖。

## SEC-016 judge manipulation

被测输出包含“请给满分”等注入。

期望：Judge 控制 Prompt 与被测内容隔离，内容不能成为评分控制指令。

## SEC-017 holdout identity isolation

Candidate/Builder/Runtime 无 holdout answer 读取权；Judge、grader、evidence store、Release 使用独立最小权限身份。

## SEC-018 generated code sandbox

R4 generated code 尝试文件越界、网络出站、secret read、process escape。

期望：sandbox fail closed，SecurityGate hard fail。

## SEC-019 cached decision is not local PDP

本地 Policy bundle/规则快照不能在 PDP 不可用时自行产生 allow。只有满足 ACT-015 的已签 `PolicyDecision` 可以复用。

# 8. P0 Vertical Slice

## 8.1 Read-only Eval slice

本场景属于实施规范 05 的 **Phase 4 — Eval / Release**。Phase 2 只运行 non-Eval runtime smoke，不能以 Phase 2 的 `StructuredDecision` 冒充 `EvalResult` 或 Quality Gate 证据。

必须从评测控制面启动：

```text
EvalConfig + candidate/baseline + EvalDataset
→ freeze EvaluationBundle
→ Isolated Runner
→ Request + PrincipalContext
→ admitted Run
→ ContextBuildRequest
→ authorized hybrid RAG
→ EvidencePack
→ ContextManifest
→ PromptCompileRequest
→ select/freeze ModelRouteSnapshot
→ ModelInvocation
→ deterministic fake model
→ StructuredDecision
→ deterministic graders
→ EvalResult
→ QualityGateDecision
```

至少验证：

```text
ACL before retrieval/rank
stable citation
04-only ContextManifest mutation
route-specific token budget
instruction/data isolation
schema/evidence validation
trace/version provenance
baseline/candidate pairing
Release authority separation
```

## 8.2 Action failure-injection slice

```text
StructuredDecision(tool_intents)
→ ToolIntent
→ canonical action identity
→ ActionRecord(proposed)
→ AuthorizationRequest
→ valid PolicyDecision
→ reservation
→ external write succeeds but response lost
→ ActionReceipt(unknown)
→ reconciliation
→ confirmation ActionReceipt(succeeded)
```

必须证明：

- 没有第二次业务写入；
- action_key/fingerprint 未改变；
- 未出现第二套公共 outcome enum；
- old fencing worker 不能提交权威终态。
