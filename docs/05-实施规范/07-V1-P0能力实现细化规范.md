# UEAF V1 P0 能力实现细化规范

版本：`0.1.0-draft`  
规范状态：Draft  
Architecture Generation: `V1`  
Maturity: `Required for Reference Implementation`  
Implementation: `Current`

## 1. 目的

本文只细化 UEAF V1 当前已经存在的 P0 能力：

```text
Prompt
Context
RAG
Tool
Eval
Security
```

目标是把现有功能规范向下编译到“Codex/工程实现无需自行猜测默认算法、失败语义、版本绑定和验收方式”的粒度。

本文 **不新增 Canonical Object，不新增模块，不新增服务，不改变既有 State/Event/Port/Authority，也不扩大 V1 mutable surface**。若本文与更高优先级规范冲突，以 README 定义的规范优先级为准。

Memory 与 MCP 在本轮只描述与 P0 主链直接相关的边界，不把它们提升为新的 P0 领域；Multi-Agent 继续复用既有 Runtime/Context/Tool 语义。

---

## 2. 全局实现原则

### 2.1 Canonical 与实现配置分离

以下内容属于版本化实现配置或 Policy，不成为新的 Canonical Object：

- Prompt 模板语法、变量转义、repair 上限；
- Context slot 优先级、token safety margin、压缩策略；
- RAG chunk/retrieval/fusion/rerank 参数；
- Tool 参数规范化、lease/backoff 参数；
- Eval 采样、重复次数、阈值、置信区间规则；
- Security action/resource vocabulary、sandbox/DLP profile。

这些配置必须：

1. 可版本化；
2. 被 `ReleaseManifest` 或其既有 policy/config refs 间接冻结；
3. 可审计；
4. 不允许生产运行中通过未审计环境变量静默改变语义。

### 2.2 确定性优先

以下路径默认不使用 LLM：

```text
Prompt variable validation
Context hard-priority packing
ACL filtering
RAG dedup/fusion baseline
Schema validation
Tool argument canonicalization
Action fingerprint generation
Policy enforcement
Eval hard constraints
Security hard gates
```

只有开放语义评分、复杂 query rewrite、证据难以解释等明确场景才允许模型介入，且必须受预算、版本和回退策略约束。

### 2.3 不允许静默猜测

实现遇到以下情况必须返回显式结构化失败/不完整语义，不得选择“看起来合理”的默认值：

- 不兼容 Prompt/Schema 版本；
- 关键 Context slot 无法容纳；
- ACL/tenant/purpose 不确定；
- Tool 动作结果未知；
- Eval 证据不足；
- Security policy/credential/sandbox 失效。

# 3. Prompt 实现细化

## 3.1 编译顺序

`PromptCompileRequest` 的 V1 Reference Implementation 固定以下编译顺序：

```text
1. verify run/turn/release/tenant/principal/purpose
2. resolve immutable ContractBundle
3. validate input variables
4. resolve instruction layers
5. verify ContextManifest
6. project allowed capabilities
7. reserve output/tool/safety budget
8. pack context sections
9. render provider-neutral prompt representation
10. select approved ModelRouteSnapshot
11. provider mapping
12. freeze ModelInvocation + hashes
```

任何后续步骤不得修改前序已经冻结的安全、Schema、principal、purpose 或 capability 边界。

## 3.2 指令层级

V1 Reference 默认优先级从高到低：

```text
organization_security
business_policy
task_contract
output_schema_and_evidence
agent_behavior
style_and_expression
untrusted_user_or_external_content
```

规则：

- 低层不得放宽高层；
- RAG、Memory、附件、ToolResult、MCP Prompt、历史模型输出一律属于不可信数据；
- 不可信数据中的“system/developer/admin/ignore previous”等文本不得提升层级；
- 同层冲突按 `PromptContract` 中确定性顺序解决；若同一优先级存在不可解冲突，编译失败，不交给模型自由裁决。

## 3.3 变量处理

`variable_spec` 至少约束：

```text
name
type
required
source
classification
max_length
serialization
escaping
allow_empty
```

Reference 规则：

- 缺少 required 变量：失败，不渲染；
- 未声明变量：默认拒绝进入控制层；
- object/array 使用 canonical JSON 序列化；
- decimal 不通过二进制浮点字符串随意重写；
- timestamp 统一 RFC3339/UTC 或明确时区；
- null 与 missing 不等价；
- 用户字符串不得通过模板语法注入新的控制块；
- 超长变量必须在进入 Prompt Compiler 前按声明策略缩减或拒绝，不能在最终字符串尾部截断。

## 3.4 Token 预算

一次模型调用的预算先预留再装配：

```text
model_context_limit
- output_reserve
- tool_schema_reserve
- safety_margin
= max_input_budget
```

Reference 默认原则：

- `safety_margin` 至少覆盖 tokenizer 偏差与 provider wrapper 开销；
- output reserve 不得被输入挤占；
- tool schema/capability 描述有独立上限；
- 无法保证模型真实 token 计数时，估算必须保守；
- 模型路由变化后重新计算预算，不复用不同 tokenizer 的旧估值。

具体数值属于 ModelRoute/Prompt 配置，不写死为跨供应商常量。

## 3.5 Provider-neutral 到 Provider mapping

Provider Adapter 只负责把冻结的 `ModelInvocation` 映射到供应商请求：

```text
instruction partitions
context blocks
response format
tool capability projection
sampling config
streaming policy
```

禁止 Provider Adapter：

- 加入未登记 system instruction；
- 自动打开供应商工具；
- 重新选择 Prompt/Schema；
- 把 provider conversation state 当 UEAF Memory；
- 在 fallback 时改变 output schema 或安全语义。

## 3.6 Structured Output 校验顺序

固定为：

```text
transport completeness
→ parse
→ schema/type/enum/format
→ consumer compatibility
→ semantic rules
→ evidence/citation
→ refusal semantics
→ security output checks
→ normalization
→ StructuredDecision
```

若前序失败，后序不得伪造通过。

## 3.7 Bounded Repair

V1 repair 只处理“候选语义可能正确，但机器结构未满足既定 ContractBundle”的情况。

允许 repair：

- JSON/typed output 语法错误；
- 缺少可由原候选确定恢复的结构包装；
- enum/format 可由明确规范化规则修正；
- 模型明确给出内容但格式与 schema 不一致。

默认禁止 repair：

- 缺证据；
- 安全硬失败；
- 越权 ToolIntent；
- 业务语义冲突；
- 关键事实缺失；
- 需要修改 Schema 才能通过；
- 模型拒绝被强行改成成功；
- provider `unknown`。

Reference Implementation 默认最多 **2 次** repair attempt；每次形成独立模型调用/usage 记录并继承同一绝对 deadline 与 ContractBundle。相同错误指纹连续两次出现时停止 repair。

# 4. Context 实现细化

## 4.1 Context Packing 优先级

V1 Reference 默认将 Context section 分为五个保留层级；这是实现策略，不新增对象：

```text
Tier 0  security/refusal/schema/task objective
Tier 1  TaskState confirmed facts / hard constraints / required evidence
Tier 2  current observations / high-value Evidence
Tier 3  governed Memory
Tier 4  conversation/history
Tier 5  optional supporting evidence/examples
```

规则：

- Tier 0 不可因预算静默删除；
- Tier 1 关键否定、金额/时间/身份/权限条件不得被摘要掉；
- 低层不能挤占高层保留预算；
- 若 Tier 0 + Tier 1 + output reserve 已无法容纳，返回显式 budget/context failure，不继续调用模型。

## 4.2 Packing 流程

固定顺序：

```text
1. remove unauthorized
2. remove expired/revoked
3. remove superseded
4. exact/near duplicate collapse
5. preserve conflict groups
6. apply per-source/per-section quota
7. compress only compressible sections
8. drop lowest marginal-value optional items
9. verify critical coverage
10. freeze ContextManifest
```

## 4.3 历史处理

Conversation/history 不作为长期权威事实源。

Reference 默认：

- 最近必要 turn 保留原始结构化摘要/引用；
- 旧历史允许压缩为受控 artifact；
- 摘要必须记录输入 refs、摘要规则/模型版本、输出 ref、loss flag；
- 摘要不能覆盖后续用户更正；
- 当摘要与当前 TaskState/Evidence 冲突时，当前权威状态优先；
- 不允许“摘要的摘要”无限递归，默认最多两级压缩链。

## 4.4 冲突证据

Context Builder 不负责自由判断哪个冲突来源为真。

若两个获授权来源对同一关键 claim 冲突：

- EvidencePack 保留 conflict group；
- 高权威来源可有排序优势，但低权威冲突不能被完全隐藏；
- 若业务规则定义唯一 authoritative source，则按 BusinessFactRef/source authority 规则处理；
- 若无权威规则，必须让下游看到“存在冲突”，不能选最后写入值。

## 4.5 重建条件

以下任一变化要求生成新的 `ContextManifest`：

```text
principal/delegation/purpose
TaskState revision
PromptContract/Bundle
source version relevant to selected evidence
ACL/policy snapshot
Memory supersede/delete
index freshness outside declared bound
budget materially changed
```

不得原地修改旧 Manifest。

# 5. RAG 实现细化

## 5.1 Ingestion 与索引版本

V1 RAG 索引是来源系统的可重建投影，不是 authority。

每个可检索内容至少能追溯：

```text
source identity
source object version
parser/normalizer version
chunk policy version
embedding model/version when used
lexical index version
ACL/policy snapshot or resolvable ACL ref
indexed_at
region/classification/purpose
```

这些信息可以通过现有 metadata/ref 表达，不新增 Canonical Object。

## 5.2 Chunking Reference Profile

V1 不规定一个跨内容类型的固定 chunk size。Reference Implementation 至少区分：

```text
plain text / markdown
code
structured table
email/ticket
PDF/document pages
structured DB/API records
```

默认规则：

- Markdown 按 heading/paragraph 边界优先；
- Code 按 symbol/block 边界优先；
- Table 保持 row/column header 语义，不拆成无表头片段；
- Email/Ticket 保留 thread/message metadata；
- PDF 优先使用解析后的结构/页码定位，不能只依赖视觉页序；
- DB/API 记录按业务主键/版本作为来源定位。

chunk token 上限、overlap、parent-child 策略属于版本化配置，并必须进入索引可复现元数据。

## 5.3 Query 规划

`QueryIntent` 默认由确定性任务目标 + 可选 query rewrite 形成。

Reference 行为：

- 普通事实查询默认 1 个 primary query；
- 多实体/多约束问题 MAY 拆分有限子查询；
- 默认子查询上限为 4；
- query rewrite 不得移除 tenant/purpose/source/freshness constraints；
- LLM rewrite 失败时回退到原始 deterministic query；
- 不因 rewrite 失败扩大数据源范围。

## 5.4 授权顺序

强制：

```text
authorization scope
→ source executable filter / controlled projection
→ retrieval
→ rank/fusion
```

禁止：

```text
global top-k
→ ACL filter
```

任何无法可靠执行资源级过滤的数据源，不得直接进入生产统一索引，只能通过已经完成授权分区的受控投影或回源接口接入。

## 5.5 Hybrid Retrieval Reference Profile

首个 Reference Implementation 默认支持：

```text
lexical retrieval
+
vector retrieval
```

基线流程：

```text
authorized lexical top-k
authorized vector top-k
→ stable score/rank normalization
→ reciprocal-rank-style fusion or equivalent deterministic fusion
→ exact/near duplicate collapse
→ source quota/diversity
→ optional rerank
→ Evidence selection
```

具体 `top_k`、fusion 常数、rerank_k 不进入核心规范，必须版本化并通过 RAG benchmark 冻结。

若 embedding/reranker 不可用：

- 可以在已授权候选中降级到 lexical；
- 必须记录 degraded mode；
- 不得扩大候选集合或跳过 ACL。

## 5.6 排序因子

Reference ranking 至少可组合：

```text
relevance
freshness
authority/trust
source diversity
query constraint match
```

禁止将用户权限、tenant、purpose 作为“软排序分数”；它们必须是硬过滤条件。

## 5.7 Dedup 与多样性

- 同一 source version 的重叠 chunk 去重；
- 不同来源但近似文本不得直接视为同一权威事实；
- 同一文档不得无限占满 EvidencePack；
- 需要多来源验证的任务必须保留来源多样性；
- conflict items 不因 dedup 被误删。

## 5.8 Citation

每个引用至少能稳定定位到：

```text
source_ref
source_version
location/span/page/record locator
selected chunk/content ref
```

引用必须指向模型真正可见的 Evidence 成员；模型不得生成不存在的 citation id。

## 5.9 删除与 ACL 撤销

删除/权限收回优先级高于新增索引。

- source delete/ACL revoke 触发 index/cache invalidation；
- 超过删除传播 SLO 的来源进入隔离或 fail-closed；
- 旧 Manifest 到期后不得继续复用被撤销 Evidence；
- Eval/回放若使用历史 snapshot，必须在隔离测试用途下明确标记，不得作为当前生产权限证明。

# 6. Tool 实现细化

## 6.1 Action Argument Canonicalization

在生成 `action_fingerprint` 前必须完成确定性规范化：

```text
field ordering
numeric representation
decimal precision
timestamp/timezone
unicode normalization
default vs explicit value
null vs missing
resource canonical identity
set/list ordering according to schema semantics
```

规则来自 `CapabilityDescriptor` 的输入 Schema/normalization policy。

禁止：

- 使用不稳定的语言对象 `repr()` 作为 fingerprint 输入；
- 把浮点二进制噪声写进动作身份；
- 将模型提供的 tenant/principal/credential 纳入可信身份；
- 在 Policy/Approval 后重新生成不同 fingerprint。

## 6.2 Action identity payload

稳定 fingerprint 至少绑定：

```text
tenant
canonical principal/delegation identity
capability + version
canonical target resource
canonical arguments
purpose
semantic side-effect class where relevant
```

其 canonical serialization 必须测试跨进程/重启/语言运行时的一致性。

## 6.3 Lease 与 fencing

Reference Implementation：

- `reserved -> executing` 前获取 execution lease；
- fencing token 单调增加；
- 旧 worker 即使收到供应商成功响应，也不能直接覆盖较新协调器状态；
- 晚到观察进入 reconciliation/evidence，而非直接提交终态；
- lease TTL 必须短于总体 action deadline，并允许续租但不得越过绝对 deadline。

## 6.4 Retry / Reconcile

执行失败先分类 certainty：

```text
definite_not_executed
executed_successfully
executed_failed_definitively
unknown
```

只有 `definite_not_executed` 且 retry policy/budget 允许时，才允许新 execution attempt。

`unknown` 默认：

```text
executing -> reconciling
```

Reconciliation 顺序优先使用：

```text
provider idempotency/status API
business object lookup
callback/event receipt
audit/transaction reference
human reconciliation
```

退避、最大次数和人工升级阈值属于 Capability Policy，但不能通过生成新 action_key 绕过未知状态。

## 6.5 大结果与 Artifact

ToolResult 默认只返回最小安全投影。

超过配置大小、包含文件/表格/二进制或高敏感正文时：

- 原始结果进入受控 Artifact Store；
- ToolResult 保存 `result_ref`、schema、safe_summary、citation refs；
- 模型只获得任务所需最小片段；
- Artifact 权限仍按 tenant/principal/purpose 校验。

# 7. Eval 实现细化

## 7.1 Dataset 组成

V1 Reference EvalDataset 至少支持以下来源：

```text
golden curated cases
production-derived sanitized regressions
adversarial/security cases
state/recovery cases
tool/unknown failure cases
holdout cases
```

每个 case 必须记录来源/provenance、版本、敏感级别、适用 scope、暴露/污染状态。

## 7.2 Baseline / Candidate 配对

可比较评测默认要求：

- 同一 dataset version；
- 同一 environment profile；
- 同一预算上限；
- 同一工具 simulator/fixture；
- 相同允许 capability；
- 随机性配置可重放或记录；
- 无法等价时显式标记差异，不把结果解释为纯候选效果。

## 7.3 Grader 顺序

固定优先级：

```text
hard structural/state/security invariants
→ deterministic business rules
→ exact/semantic reference checks
→ optional calibrated model judge
→ human review when required
```

LLM Judge 不能覆盖 deterministic hard failure。

## 7.4 LLM Judge Reference Policy

使用 Judge 时必须冻结：

```text
judge prompt version
judge model route/version
input schema
output schema
sampling config
repeat count
calibration set/version
confidence/disagreement thresholds
```

默认：

- Judge 无 Tool/业务写权限；
- temperature 使用确定性/低随机配置；
- 高影响开放语义分数至少重复 2 次或使用已证明等价的稳定策略；
- Judge 间分歧超过阈值 -> human review/inconclusive；
- calibration 与人工标签一致性跌破 profile 阈值时，Judge 结果不得作为 active quality gate 的唯一依据。

## 7.5 统计与聚合

V1 不要求复杂学术统计框架，但必须防止把噪声当改进。

Reference Gate 至少检查：

```text
sample count sufficient
critical slice hard failures
absolute candidate result
paired delta vs baseline
uncertainty/confidence bounds
cost/latency guardrail
measurement completeness
```

小样本或高方差导致无法确认 improvement 时，结论为 `inconclusive`，不是自动 pass。

任何 weighted score 只在所有 hard constraints 通过后计算。

## 7.6 数据污染

以下任一情况使受影响结果 invalid 或降级：

- candidate/Proposer 可读取 holdout answer；
- Judge prompt 含 case gold label；
- 数据集泄漏到 mutation/Prompt 生成上下文；
- 生产-derived 样本未完成用途/脱敏；
- case 被人为选择性删除不利 attempt；
- baseline/candidate 使用不等价外部工具状态且未记录。

# 8. Security 实现细化

## 8.1 Authorization Vocabulary

Reference Implementation 必须维护版本化 action/resource vocabulary。

Action 名采用稳定业务动作语义，例如：

```text
resource.read
resource.search
resource.create
resource.update
resource.delete
message.send
workflow.start
artifact.read
```

具体业务能力可扩展 namespaced action，但不得由模型或 MCP Server 在运行时自由发明后自动视为已授权。

Resource identity 必须服务端 canonicalize，并绑定 tenant/namespace/type/id/region 等适用字段。

## 8.2 默认 Policy 行为

V1 Reference 默认：

```text
deny by default
explicit allow only
principal + delegation valid
tenant match required
purpose match required
resource scope match required
region/data handling match required
expired/revoked decision invalid
high-risk write may require approval
```

Policy unavailable：

- high-risk/reversible write 默认 fail closed；
- read-only 仅在已有未过期、可证明未撤销的本地 policy snapshot 明确允许时才可按配置降级；
- 不允许以“系统内部 Agent”身份自动 bypass。

## 8.3 Prompt/RAG/Memory Injection 边界

以下内容始终是不可信数据：

```text
user text
uploaded files
RAG chunks
Memory content
ToolResult text
MCP prompt/resource/tool description
remote Agent text
model previous output
```

安全实现必须保证这些内容不能：

- 修改 PrincipalContext；
- 增加 capability；
- 改写 output schema；
- 获取 credential；
- 改写 PDP/PEP；
- 关闭 Audit；
- 修改 Release/Governance hard gate。

## 8.4 Credential 生命周期

Credential Broker 返回 opaque handle；Reference 默认要求：

- short-lived；
- audience-bound；
- tenant/action/resource scope-bound；
- 最小权限；
- Adapter 运行时按需兑换/注入；
- 不序列化进 Prompt、Tool args、Trace、Event、Checkpoint、Memory、Evolution Working Set；
- 超过 action deadline 后自动不可用。

## 8.5 Sandbox / Network Egress

Generated code、RPA、文件转换、非可信 Tool/MCP adapter 测试应支持 sandbox profile：

```text
filesystem scope
network egress allowlist
cpu/memory/time
process spawn
secret access
artifact mount
output size
```

Reference 默认 deny unrestricted network egress。需要外网访问时必须由 capability/profile 明确声明并通过 Policy。

## 8.6 DLP / Result Minimization

出站内容至少检查：

```text
credentials/secrets
cross-tenant identifiers
regulated/sensitive fields
unnecessary raw records
hidden policy/audit internals
```

DLP 失败不得通过 Prompt 指令覆盖。

## 8.7 V1 Threat Suite 最小集合

P0 实现必须覆盖：


# 10. Typed Port 落地要求

当前 `src/ueaf/ports.py` 中的 `Any` 只是 Phase 0 skeleton。

P0 实现阶段必须逐步收敛为 typed request/result/error，但 **不改变核心 Port 名称和方法集合**：

```text
ContextBuildPort
ModelStepPort
ToolIntentPort
TelemetryPort
```

要求：

- request/response 有 canonical model/schema；
- Port error 使用 `PortResult<T>/PortError` 语义；
- deadline/cancellation/correlation 可传递；
- 不允许 Adapter 自定义同名第二接口。
