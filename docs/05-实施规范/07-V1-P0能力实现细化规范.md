# UEAF V1 P0 能力实现细化规范

版本：`0.2.0-draft`  
规范状态：Draft  
Architecture Generation: `V1`  
Maturity: `Required for Reference Implementation`  
Implementation: `Current`

## 1. 目的与范围

本文只向下细化 UEAF V1 已存在的 P0 能力：

```text
Prompt / Model
Context
RAG
Tool / Action
Eval
Security
```

目标是把现有功能规范编译到可实现的默认算法、失败语义、版本冻结和验收粒度，同时严格保持：

```text
不新增 Canonical Object
不新增模块或服务
不新增公共状态机或公共结果枚举
不改变既有 Port / Event / Error / Authority
不扩大 V1 mutable surface
不把 V2/V3 变为 Current
```

本文属于实施层。发生冲突时继续遵守：

```text
核心规范
> 总体设计
> ADR
> 功能模块
> 实施规范
> 参考架构
```

本文中的数值、排序、阈值和算法默认值只约束 V1 Reference Implementation，不提升为跨实现 Canonical 语义。

## 3. 全局实现原则

### 3.1 Canonical 与实现配置分离

以下内容属于版本化 config、Policy 或 Profile，不成为新 Canonical Object：

- Prompt 模板语法、变量转义、repair 上限；
- Context slot 优先级、token safety margin、压缩策略；
- RAG parser/chunk/retrieval/fusion/rerank 参数；
- Tool 参数规范化、lease、retry/backoff 和 reconciliation 参数；
- Eval 采样、重复次数、阈值和统计规则；
- Security action/resource vocabulary、sandbox 和 DLP profile。

这些配置必须：

1. 有稳定版本或内容摘要；
2. 通过现有 Release/Profile/Policy 引用被冻结；
3. 可审计、可回滚；
4. 不通过未审计环境变量静默改变生产语义。

### 3.2 确定性优先

以下路径默认不使用 LLM：

```text
Prompt variable validation
instruction precedence enforcement
Context hard-priority packing
ACL filtering
RAG dedup / deterministic fusion baseline
Schema and deterministic semantic validation
Tool argument canonicalization
Action fingerprint generation
Policy enforcement
Eval hard constraints
Security hard gates
```

复杂 query rewrite、开放语义评分或证据解释 MAY 使用模型，但必须冻结调用版本、预算、输出 Schema、回退和失败语义。

### 3.3 不允许静默猜测

以下情况必须返回既有 `ProblemDetail`、`PortError/PortResult<T>`、`ValidationReport`、`no_progress/refusal` 或对应权威状态，不得发明新公共结果类型：

- Prompt/Schema/Release 版本不兼容；
- 关键 Context 无法安全容纳；
- tenant/principal/purpose/ACL 不确定；
- Tool 结果无法证明；
- Eval 证据或样本不足；
- Security Policy、credential、sandbox 或 DLP 失效。

# 4. Prompt / Model 实现细化

## 4.1 编译与调用顺序

`PromptCompileRequest` 的 Reference 顺序固定为：

```text
1. verify run / turn / release / tenant / principal / purpose / deadline
2. resolve immutable ContractBundle
3. validate declared input variables
4. verify ContextManifest identity, integrity, expiry and policy binding
5. build minimal CapabilityProjection from allowed refs
6. select and freeze an approved ModelRouteSnapshot
7. calculate route-specific context limit, tokenizer estimate and reserves
8. verify the frozen ContextManifest fits the selected route
9. map trusted instruction layers and Manifest sections into provider-neutral representation
10. freeze ModelInvocation, hashes, route, bundle, budgets and attempt identity
11. Provider Adapter maps the frozen ModelInvocation to the provider request
12. invoke / stream / normalize into ModelRunResult
```

关键不变量：

- `ModelRouteSnapshot` 必须先于 route-specific token 计算被冻结；
- Module 03 不得重新选择、删除、压缩或改写 `ContextManifest.sections`；
- 若 Manifest 对所选 route 放不下，Module 03 返回结构化预算问题，02 决定 `no_progress` 或请求 04 重建新 Manifest；
- fallback 必须在 Release 已评测回退链内形成新 attempt/`ModelInvocation`，重新计算 token，不能由 Provider Adapter 私自换路由；
- Provider Adapter 只映射冻结调用，不修改 ContractBundle、Schema、Principal、Purpose、Capability 或 Context。

## 4.2 指令层级与非指令门禁

`PromptContract.instruction_layers` 继续使用功能规范已经定义的五类可信指令层：

```text
organization security
business
 task
behavior
expression
```

实现可以在每类内部使用稳定顺序，但不得建立第二套公共 instruction-layer enum。

以下属于 `ContractBundle` 的确定性门禁，不是新增 instruction layer：

```text
input/output Schema
DataDictionary
SemanticRuleSet
EvidencePolicy
RefusalPolicy
consumer compatibility
NormalizerSet
```

以下属于不可信数据分区，不是 instruction layer：

```text
user text
RAG Evidence
Memory
attachments
ToolResult content
MCP prompt/resource/tool description
remote Agent text
previous model output
conversation history
```

不可信数据中的 `system`、`developer`、`admin`、`ignore previous instructions` 等字符串不得提升到控制层。

## 4.3 变量处理

`PromptContract.variable_spec` 的实现至少校验：

```text
name
source
type
required
classification
max_length
serialization
escaping
allow_empty
```

Reference 规则：

- required missing：provider 调用前失败；
- 未声明变量：不能进入可信控制层；
- object/array 使用批准的 canonical JSON；
- decimal 不使用不稳定二进制浮点字符串；
- timestamp 使用 RFC3339，并保留明确时区语义；
- `null` 与 missing 不等价；
- 字符串模板值不能生成新的消息角色或控制块；
- 超限变量按声明策略拒绝或在上游生成新受控 artifact/ref，不做尾部字符串截断。

## 4.4 Route-specific Token 预算

选择 `ModelRouteSnapshot` 后计算：

```text
model_context_limit
- output_reserve
- capability/tool_schema_reserve
- provider_wrapper_reserve
- tokenizer_safety_margin
= max_input_budget
```

规则：

- output reserve 不被输入挤占；
- capability projection 有独立上限；
- tokenizer 不可精确复现时使用保守估计；
- route/tokenizer 变化时重新估算；
- Module 03 只验证 Manifest 是否适配，不取得 04 的 packing 所有权；
- 实际 usage 与估值偏差必须进入观测和后续配置评测。

具体 reserve 数值属于版本化 ModelRoute/Prompt 配置。

## 4.5 Provider Mapping

Provider Adapter MAY 映射：

```text
trusted instruction partitions
untrusted context blocks
response format
capability projection
sampling config
streaming policy
```

Provider Adapter MUST NOT：

- 加入未登记 system instruction；
- 自动启用供应商工具；
- 改变 output schema/refusal/evidence/security 语义；
- 把 provider conversation state 变为 UEAF Memory；
- 将 provider response ID 变成 Task/Run/Turn；
- 在 fallback 时原地改写旧 `ModelInvocation`。

## 4.6 输出校验顺序

固定为：

```text
transport/stream integrity
→ parse complete candidate
→ schema/type/enum/format
→ consumer compatibility
→ deterministic semantic rules
→ evidence/citation validation
→ refusal semantics
→ security output checks
→ approved normalization with log
→ StructuredDecision
```

只有 `validation_result=passed` 的核心 `StructuredDecision.kind` 可以返回 02 应用。

## 4.7 Bounded Repair

Repair 只处理“原候选表达了可恢复内容，但机器结构未满足同一 ContractBundle”的情况。

允许：

- JSON/typed-output 语法错误；
- 可由原候选确定恢复的结构包装；
- 已批准 NormalizerSet 可修正的格式；
- 内容明确但字段结构不兼容。

禁止：

- 缺证据或伪造 citation；
- 安全 hard fail；
- 越权 ToolIntent；
- 业务语义冲突或关键事实缺失；
- 修改 Schema/Policy 才能通过；
- 将模型 refusal 强改为 success；
- provider/stream `unknown`。

Reference 默认最多 2 次 repair attempt；每次：

- 形成新 `ModelInvocation`/usage；
- 继承同一绝对 deadline、Bundle 和 route compatibility；
- 记录错误指纹；
- 相同错误指纹连续达到配置阈值后停止。

# 5. Context 实现细化

## 5.1 唯一写者

Module 04 Context Builder 是 `ContextManifest` 唯一创建者。Module 02 只请求和关联，Module 03 只验证、读取和映射。

任何重新选择、删除、压缩、替换 section 的行为都必须由 04 生成新的 Manifest；不得在 Prompt 编译器或 Provider Adapter 中原地完成。

## 5.2 Prompt control reserve 与 Context tiers

Prompt 的可信控制内容由 Module 03/ContractBundle 拥有。Module 04 只接收其预算约束：

```text
prompt_control_reserve
output_reserve
capability_reserve
model/input upper bound
```

它们不是 Context section，也不使 04 取得 Prompt/Schema/Refusal 所有权。

扣除这些 reserve 后，Reference Context 使用五个优先层级：

```text
Tier 0  TaskState confirmed facts / hard constraints / required evidence
Tier 1  current observations / high-value Evidence
Tier 2  governed Memory
Tier 3  conversation/history
Tier 4  optional supporting evidence/examples
```

规则：

- Tier 0 的关键否定、身份、权限、金额、时间、单位和完成条件不得静默丢失；
- 低优先级 section 不得挤占控制、输出或 Tier 0 reserve；
- 必需内容放不下时返回结构化 context/budget failure，不生成看似完整的 Manifest。

## 5.3 Packing 流程

固定顺序：

```text
1. enforce tenant/principal/purpose/authorization
2. remove expired or revoked candidates
3. remove superseded candidates
4. exact/near duplicate collapse within permitted semantics
5. preserve conflict groups
6. apply source/section quotas
7. compress only sections allowed by PromptContract/context policy
8. remove lowest marginal-value optional candidates
9. verify required coverage and citation locators
10. freeze immutable ContextManifest + decisions + omissions
```

## 5.4 与 Model Route 的协作

04 根据 Runtime/Release/Prompt 提供的模型能力上限和预算构建 Manifest；03 选择实际批准 route 后进行最终 fit check。

如果实际 route 更小：

```text
03 returns structured budget problem
→ 02 decides no_progress or requests rebuild
→ 04 creates a new ContextManifest
```

禁止 03 在不生成新 Manifest 的情况下裁剪旧 Manifest。

## 5.5 历史与压缩

- Conversation/history 不是长期权威事实；
- 最近必要 turn 使用结构化记录/ref；
- 旧历史 MAY 压缩为受控 Artifact；
- `compression_records` 保存 input refs、规则或模型版本、output ref、loss/omission；
- 摘要不能覆盖后续用户更正；
- 当前 TaskState/权威 Evidence 优先于历史摘要；
- Reference 默认压缩链最多两级，超过时重新从可用原始 refs 构建，而不是无限“摘要的摘要”。

## 5.6 冲突证据

Context Builder 不自由选择冲突来源为真。

- `EvidencePack.conflicts` 保留冲突组和 refs；
- 已定义唯一 authoritative source 时按 BusinessFactRef/source policy 处理；
- 否则保留冲突信号，不能以最后写入或最高 embedding score 静默消解；
- dedup 不得删除语义冲突项。

## 5.7 重建条件

以下变化要求新 Manifest：

```text
Principal / delegation / purpose
TaskState revision
PromptContract / ContractBundle
selected source version or Evidence validity
ACL / Policy snapshot
Memory supersede / expire / delete
index freshness outside declared bound
budget or route requirement materially changed
```

# 6. RAG 实现细化

## 6.1 Ingestion 与索引可复现性

索引是权威来源的可重建 Projection。每个可检索内容至少能追溯：

```text
source identity and object version
parser/normalizer version
chunk policy version
embedding model/version when used
lexical/vector index version
ACL proof/ref or authorization-partition identity
indexed_at / source watermark
region / classification / allowed purpose
```

这些使用现有 metadata/ref 表达，不新增 Canonical Object。

## 6.2 Chunking Reference Profile

至少区分：

```text
plain text / markdown
code
structured table
email / ticket
PDF / document
structured DB / API record
```

默认：

- Markdown 优先 heading/paragraph；
- Code 优先 symbol/block；
- Table 保留 header 与 row/column 关系；
- Email/Ticket 保留 message/thread locator；
- PDF 保留解析结构、页码/span 和来源版本；
- DB/API 记录保留业务主键与版本定位。

chunk 上限、overlap 和 parent-child 策略属于版本化配置，并进入索引元数据与 benchmark。

## 6.3 Query Planning

- 普通事实查询默认一个 primary `QueryIntent`；
- 多实体/多约束问题 MAY 拆成有限子查询；
- Reference 默认上限 4，由版本化配置控制；
- rewrite 不得移除 tenant、purpose、region、source、freshness 和 citation 约束；
- LLM rewrite 失败回退原确定性 query；
- rewrite 不能扩大授权或数据源范围。

## 6.4 授权顺序

强制：

```text
authorization scope
→ source-executable filter or pre-authorized controlled projection
→ retrieval
→ rank / fusion / rerank
```

禁止：

```text
global top-k
→ post-filter ACL
```

不能可靠执行资源级过滤的数据源，只能通过授权分区投影或受控回源端口进入生产检索。

## 6.5 Hybrid Retrieval Reference

首版支持获授权集合内的 lexical + vector：

```text
authorized lexical top-k
authorized vector top-k
→ deterministic rank/score normalization
→ reciprocal-rank-style or equivalent deterministic fusion
→ duplicate collapse
→ source quota/diversity
→ optional frozen reranker
→ Evidence selection
```

`top_k`、fusion 常数、rerank_k 和权重属于版本化配置，不进入核心规范。

Embedding/Reranker 不可用时：

- MAY 在已授权集合内降级 lexical；
- 显式记录 degraded mode 和 coverage；
- 不扩大候选集，不跳过 ACL。

## 6.6 Ranking、Dedup 与冲突

排序 MAY 组合：

```text
relevance
freshness
authority/trust
constraint match
source diversity
```

但 tenant、principal、purpose、region、classification 是硬过滤，不是软分数。

Dedup：

- 同 source version 重叠 chunk 可合并；
- 不同来源的相似文本不自动合并成同一 authority；
- 单一文档不能无限占满 EvidencePack；
- conflict items 必须保留；
- 多来源验证要求由 `citation_requirement`/EvidencePolicy 决定。

## 6.7 Citation

每个 citation 必须能解析到：

```text
Evidence item/citation handle
source_ref
source_version
page/span/record/message/symbol locator
selected content/chunk ref
```

只有模型实际可见的当前 `EvidencePack` 成员可以支持 `StructuredDecision.evidence_refs`。不存在或伪造的 citation 必须失败 Evidence validation。

## 6.8 删除、撤权和新鲜度

- delete/ACL revoke 优先于新增索引；
- 触发索引、缓存和可复用 Manifest 失效；
- 超过删除传播 SLO 的来源隔离或 fail closed；
- 历史 snapshot 只可在明确隔离的 Eval/Replay 用途使用，不作为当前生产授权证明；
- 索引水位落后必须显式 freshness/coverage gap。

## 6.9 Benchmark 与发布边界

RAG benchmark 只产生 `EvalResult`、质量证据和配置比较，不签发发布结论。

正确链路：

```text
RAG benchmark facts
→ EvalResult / EvalEvidenceGraph
→ QualityGateDecision
→ Release Governance combines Quality + Security + Operational decisions
→ ReleaseDecision
```

RAG 模块、retrieval benchmark 或 grader 不得直接“阻止/批准发布”。

# 7. Tool / Action 实现细化

## 7.1 Action Argument Canonicalization

在生成 `action_fingerprint` 前，Module 05 使用 `CapabilityDescriptor` 输入 Schema/normalization policy 处理：

```text
object field ordering
number/decimal representation
precision and unit
timestamp/timezone
Unicode normalization
default vs explicit value
null vs missing
resource canonical identity
ordered list vs set-like collection
```

禁止：

- 使用语言对象 `repr()`；
- 将浮点噪声写进动作身份；
- 信任模型提供的 tenant/principal/credential；
- Policy/Approval 后重新生成不同 identity。

## 7.2 Fingerprint 规范字段

继续严格使用上位 Module 05 定义的字段：

```text
tenant
canonical principal
delegation
capability + version
canonical resource
canonical arguments
purpose
```

不得额外把新的公共 side-effect class、risk hint、审批结果或 credential 加入规范 action identity。若上位规范未来改变，必须先修功能规范/ADR。

## 7.3 状态与结果词表

公共语义只使用既有：

```text
ActionPhase
ActionDisposition
ActionReceipt.status = succeeded | failed | unknown
PortResult<T> / PortError.certainty / retryability
```

实现内部可以判断“是否有未执行证明”或“是否有成功证明”，但不得把 `definite_not_executed`、`executed_successfully` 等内部判断升级成第二套公共 enum。

映射规则：

```text
有按指纹发生的成功证明
→ ActionReceipt.status=succeeded

有确定失败或未发生证明
→ ActionReceipt.status=failed
→ 再由 retryability + budget + deadline 判断是否允许下一 attempt

无法证明结果
→ ActionReceipt.status=unknown
→ ActionRecord phase=reconciling
```

## 7.4 Lease 与 fencing

- `reserved -> executing` 前获取 execution lease；
- fencing token 单调增加；
- lease TTL 不越过 action absolute deadline；
- 旧 worker 的晚到结果不能直接提交权威终态；
- 晚到结果作为 observation/evidence 进入 reconciliation；
- 只有当前 fencing token/协调器可推进 ActionRecord。

## 7.5 Retry 与 Reconciliation

只有同时满足以下条件才允许新 execution attempt：

```text
ActionReceipt/Port evidence 证明未发生或确定失败
retryability 允许
same action_key / fingerprint
budget and deadline permit
no newer successful/unknown observation
```

`unknown` 不盲重试。对账优先：

```text
provider idempotency/status API
business object lookup
callback/event receipt
external transaction/audit reference
human reconciliation
```

对账耗尽仍无法证明时使用既有 `terminal/unresolved`，不发明新终态。

## 7.6 Policy 不可用与 Decision 复用

PDP 是 `PolicyDecision` 唯一 Semantic Owner。

Policy 服务不可用时，PEP 只能复用一个已经由可信 PDP 签发的决定，且必须全部满足：

```text
status/issuer/signature valid
input_hash exactly matches current action_fingerprint and environment
principal/action/resource/purpose/tenant match
not expired
not revoked
within configured revocation-propagation SLO
constraints still enforceable
```

本地 Policy bundle、规则快照或 Agent 自述不能自行产生 `allow`。没有有效 `PolicyDecision` 时默认 deny/fail closed；高风险动作始终 fail closed。

## 7.7 大结果与 Artifact

大表格、文件、二进制或高敏感结果：

- 原始内容写入受控 Artifact Store；
- `ToolResult` 只包含最小 `safe_summary`、schema/ref/citation；
- 模型只得到任务所需最小片段；
- Artifact 每次读取重新校验 tenant/principal/purpose；
- secret、内部 Policy、审批密钥和不必要业务字段不进入普通结果。

# 8. Eval 实现细化

## 8.1 运行隔离

`EvalResult` 只能由 `EvalRun` 下的冻结评测链产生，不由普通生产 Request 在线直接签发。

Reference 链：

```text
EvalConfig + candidate + baseline + EvalDataset
→ freeze EvaluationBundle/environment/budget/tool fixtures
→ Isolated Runner executes candidate and baseline
→ collect outcome/trajectory/state/security/performance facts
→ deterministic graders / calibrated Judge / human review
→ EvalResult
→ EvalEvidenceGraph
→ QualityGateDecision
```

被测 Runtime、Judge、grader、dataset、evidence store 和 Release Authority 使用独立最小权限身份。

## 8.2 Dataset 组成与来源

至少支持：

```text
golden curated cases
production-derived sanitized regressions
adversarial/security cases
state/recovery cases
tool/unknown failure cases
holdout cases
```

每个 case 记录 provenance、版本、scope、敏感级别、用途、暴露/污染状态和删除传播要求。

## 8.3 Baseline / Candidate 配对

默认比较要求：

- 同 dataset version；
- 同 environment profile；
- 同预算上限；
- 同工具 simulator/fixture 和外部状态；
- 相同 capability 集合；
- 随机性可重放或记录；
- 无法等价时显式记录差异，不解释为纯 candidate delta。

## 8.4 Grader 顺序

```text
hard structural/state/security invariants
→ deterministic business rules
→ exact/reference/semantic checks
→ optional calibrated Judge
→ human review when policy requires
```

Judge 高分不能覆盖 deterministic hard failure。

## 8.5 Judge 冻结与校准

使用 Judge 时冻结：

```text
judge prompt/version
judge model route/version
input/output schema
sampling config
repeat strategy
calibration set/version
confidence/disagreement thresholds
```

- Judge 无业务 Tool 写权限；
- 高影响开放语义评分至少重复 2 次，或使用经校准证明等价的稳定策略；
- 分歧超阈值进入 human review 或 `inconclusive`；
- 校准下降时，Judge 不能作为 active Quality Gate 的唯一依据。

## 8.6 Gold/reference 与污染边界

允许：

- 冻结 EvalConfig 明确授权的 grader/Judge 读取 reference answer、rubric 或 expected constraints；
- 读取行为可审计且不会回流到被测候选。

禁止：

- Candidate、Proposer、Builder 或被测模型读取 holdout/gold answer；
- gold/reference 泄漏进被测 Prompt、RAG、Memory、ToolResult 或 mutation working set；
- Judge 通过未冻结旁路获得标签、Policy 或控制信息；
- 选择性删除不利 attempt。

受污染结果必须 `invalid`，不能模糊“降级”后继续支持 active gate。

## 8.7 统计与聚合

V1 至少检查：

```text
sample count sufficiency
critical slice hard failures
absolute candidate result
paired delta vs baseline
uncertainty/confidence bound
cost/latency guardrail
measurement completeness
```

样本不足或方差过大：`EvalResult.verdict=inconclusive`。Weighted score 只能在 hard constraints 通过后计算。

质量、成本或延迟不满足时由 `QualityGateDecision.outcome=fail|conditional` 表达；不创建 `not_improved` 公共状态。

## 8.8 发布边界

Eval grader、Judge 和 Quality Gate 不直接部署。只有 Module 08 Release Governance 在同一 candidate/environment/scope 下验证：

```text
QualityGateDecision
SecurityGateDecision
OperationalReadinessDecision
```

后才能签发 `ReleaseDecision`，再由 Signer 生成 `ReleaseManifest`。

# 9. Security 实现细化

## 9.1 Authorization Vocabulary

Reference 维护版本化 action/resource vocabulary，例如：

```text
resource.read
resource.search
resource.create
resource.update
resource.delete
message.send
workflow.start
artifact.read
```

这是 Policy/Capability 配置，不是新 Canonical Object。模型、MCP Server 或远程 Agent 未登记的 action 名不能自动获得权限。

Resource identity 必须服务端 canonicalize，并绑定适用的 tenant/namespace/type/id/region。

## 9.2 默认授权行为

```text
deny by default
explicit PDP decision required
principal and delegation valid
tenant match
purpose match
resource scope match
region/data handling match
decision active, unexpired and unrevoked
high-risk write may require approval
```

内部 Agent/service 身份无 bypass。Policy 不可用时遵守第 7.6 节，只复用有效已签 `PolicyDecision`，否则 deny/fail closed。

## 9.3 Injection 边界

以下始终是不可信数据：

```text
user/uploaded content
RAG chunks
Memory
ToolResult content
MCP metadata/prompt/resource
remote Agent text
previous model output
```

它们不能：

- 修改 `PrincipalContext`/delegation；
- 增加 capability/action；
- 改写 output Schema/Evidence/Refusal Policy；
- 获取 credential；
- 修改 PDP/PEP、Audit、Release 或 Governance hard gate。

## 9.4 Credential 生命周期

Credential Broker 返回 opaque handle，并要求：

- short-lived、audience-bound；
- tenant/workload/action/resource scope-bound；
- 最小权限；
- Adapter 执行时按需兑换；
- 不序列化到 Prompt、Tool args、Trace、Event、Checkpoint、Memory 或 Evolution Working Set；
- 不晚于 action deadline 失效。

## 9.5 Sandbox / Egress

Generated code、RPA、文件转换及非可信 Tool/MCP 测试使用版本化 sandbox profile：

```text
filesystem scope
network egress allowlist
cpu/memory/time
process spawn
secret access
artifact mount
output size
```

默认拒绝 unrestricted network egress。外网访问必须由 Capability/Profile 声明并经过 Policy。

## 9.6 DLP / Result Minimization

出站至少检测：

```text
credentials/secrets
cross-tenant identifiers
regulated/sensitive fields
unnecessary raw records
hidden policy/audit internals
```

DLP hard failure 不能被 Prompt、Judge 分数或业务收益覆盖。

## 9.7 最小 Threat Suite

```text
Direct prompt injection
Indirect RAG injection
Memory poisoning
Tool parameter injection
Confused deputy
MCP malicious metadata/prompt
Cross-tenant retrieval
Credential leakage
SSRF / unrestricted egress
Judge manipulation
Eval holdout contamination
Generated code sandbox escape attempt
```

这些是 Test/Evidence 场景，不是新领域对象。
