
## 4. Cross-contract Convergence

### CON-001 `ContractMeta`

所有跨模块持久化对象带完整 `meta: ContractMeta`；领域示例省略公共字段不能让 Machine Schema 省略 `meta`。对象自身规范 ID 与 `meta.object_id` 一致。

### CON-002 single `EventEnvelope`

公共 Event 只能使用核心完整 `EventEnvelope`；删减版 `event_type + aggregate_ref + revision + correlation_refs` 不得成为 public contract。

### CON-003 event naming

公共事件名必须匹配：

```text
ueaf.<domain>.<past_tense_fact>
```

PascalCase alias 不能作为公共事件名。

### CON-004 event registry

不得发布未登记的 public `ueaf.*` event。未注册 Evolution lifecycle event 只能是 Module 11 internal metadata/event。

### CON-005 single error contract

API/cross-process 使用 `ProblemDetail`，Port 使用 `PortResult<T>/PortError`。公共 `ErrorEnvelope` 不得存在。

### CON-006 RuntimeAdapter SPI

公共最小 SPI：

```text
DescribeRuntime
StartRun
AdvanceRun
SuspendRun
ResumeRun
CancelRun
InspectRun
```

其他方法只能是 optional/private convenience。

### CON-007 core capability Port names

RuntimeExecutionContext 使用：

```text
ContextBuildPort
ModelStepPort
ToolIntentPort
HandoffPort
TelemetryPort
```

不得创建同名不同签名的第二接口。

### CON-008 canonical `PrincipalContext`

代码/Schema 只有核心字段版本的 `PrincipalContext`；`subject_id/identity_provider/assurance_level/...` 不得成为第二套顶层 Schema。

### CON-009 risk type separation

```text
TaskEnvelope.risk_class:
compute_only | read_only | reversible_write | high_risk_write

Evolution RepairLevel:
R0 | R1 | R2 | R3 | R4 | R5
```

两者不得混用。

### CON-010 ReleaseManifest version set

Machine Schema 使用 plural version-set 字段，禁止另建单数组件版 `ReleaseManifest`。

### CON-011 Evolution build chain

```text
MutationProposal
→ GenomeManifest candidate
→ ReleaseCandidate
```

直接跳过 Genome 的路径必须失败。

### CON-012 authority-preserving implementation detail

实施层的 Tier、算法步骤、内部判定词和配置不得升级为新 Canonical Object、公共 enum、第二 State Writer 或第二 Decision issuer。

## 5. Runtime / State — `RUN-*`

### RUN-001 queued 不可跳过 admitting

新 Run 必须 `queued -> admitting`，有效 `RunAdmissionResult(admitted)` 后才进入 running。

### RUN-002 phase/disposition 正交

非 terminal disposition 为空；terminal disposition 必填。

### RUN-003 stale fencing

旧 fencing token 写入被拒绝。

### RUN-004 crash recovery

Coordinator/Worker 强制终止后可恢复，不重复权威提交。

### RUN-005 edge reject no run

Edge pre-validation reject 不创建 RunRecord/RunAdmissionResult。

### RUN-006 task risk enum

新 writer 不输出 `R0|R1|R2|R3` 作为 Task risk；迁移 reader MAY 映射旧值。

---

## 6. Runtime Adapter — `ADP-*`

### ADP-001 Model Gateway 强制

Adapter model step 必须经 `ModelStepPort`。

### ADP-002 Tool Gateway 强制

function/tool candidate 只能变成 `ToolIntent`。

### ADP-003 unsupported capability

不支持必须显式 unsupported/rejected。

### ADP-004 第二 Adapter 等价

同一 read-only Agent Definition 在 LangGraph + Adapter #2 下 UEAF Task/Run/Context/Audit/Completion 语义等价。

### ADP-005 RuntimeEvent != authority event

Adapter 原生/归一 RuntimeEvent 不能伪造 Action、Policy、Audit、Release 等权威事实。

## 9. Tool / Action — `ACT-*`

### ACT-001 stable action identity before policy

服务端规范化后先稳定计算 `action_fingerprint/action_key` 并创建 `ActionRecord(proposed)`，再进入 PDP。

### ACT-002 action_key 幂等

并发提交同一逻辑动作只形成一个权威动作身份/记录。

### ACT-003 timeout unknown 不盲重试

写 API 可能成功但响应丢失：

```text
ActionReceipt.status=unknown
ActionRecord -> reconciling
no second write
```

### ACT-004 certain failure 才重试

只有权威证据证明失败/未发生且 retry policy/budget/deadline 允许，才有下一 Attempt。

### ACT-005 approval fail closed

高风险动作在审批/关键 Audit 不可用时 fail closed。

### ACT-006 permission denied 不自提权

PermissionDenied 可形成 Evidence，不能自动扩大权限。

### ACT-007..017 audited extensions

实施规范 08 进一步覆盖：

```text
canonical arguments and exact fingerprint field set
Policy/Approval cannot change action identity
only existing ActionReceipt/ActionPhase/ActionDisposition vocabulary
stale fencing and deadline-bound lease
unknown reconciliation
proof-based failed retry
only valid signed PolicyDecision may be cached/reused
large result Artifact projection
secret exclusion
```

## 10. Security / Identity — `SEC-*`

### SEC-001 trusted principal mapping

外部 body 中 tenant/role/scope/principal 无法覆盖 canonical PrincipalContext。

### SEC-002 delegation narrows

Handoff/Resume/Retry 后 scopes 只能保持或收窄。

### SEC-003 credential non-leak

credential/secret 不进入 Prompt、Tool args、普通 Log/Trace/Event、Checkpoint 或 Evolution Working Set。

### SEC-004 decisions orthogonal

`PolicyDecision`、`SecurityGateDecision`、`QualityGateDecision`、`OperationalReadinessDecision`、`ReleaseDecision` 不可互换。

### SEC-005 R5 no auto-elevation

Governance Root 无自动 Mutation path。

### SEC-006..019 audited extensions

实施规范 08 覆盖：

```text
deny by default
controlled action vocabulary
server-side resource canonicalization
RAG/Memory/MCP injection
confused deputy
credential leak
SSRF/egress
DLP
Judge manipulation
holdout identity isolation
generated-code sandbox
local Policy bundle is not a second PDP
```

## 11. Eval / Release

### 11.1 Eval — `EVAL-*`

#### EVAL-001 baseline pairing

Candidate/baseline 可比较；差异显式记录。

#### EVAL-002 hard safety first

安全 hard fail 不能被平均分抵消。

#### EVAL-003 inconclusive

缺证据/测量失败 -> inconclusive/invalid，不 auto pass。

#### EVAL-004..018 audited extensions

实施规范 08 覆盖：

```text
frozen EvalConfig/EvaluationBundle and Isolated Runner
Dataset provenance
baseline equivalence
hard grader precedence
Judge freeze/disagreement/calibration
low-sample inconclusive
critical slice and cost/latency gate
legitimate frozen reference access
holdout and side-channel contamination -> invalid
attempt history preserved
Quality/RAG/Judge cannot sign ReleaseDecision
```

### 11.2 Release — `REL-*`

#### REL-001 candidate != manifest

Runtime/Routing 不加载 `ReleaseCandidate`。

#### REL-002 manifest immutable

运行绑定 release_id 不原地改变。

#### REL-003 rollback

Canary hard stop 可按签名 Manifest rollback 并留证据。

### EVO-003 no_evolution_needed

## 14. Diagnosis / Repair — `REP-*`

### REP-001 symptom != repair target

### REP-002 smallest effective repair

证据支持 R1 时不扩大到不相关 R2/R3/R4。

### REP-003 escalation requires evidence

失败本身不自动扩大 scope。

### REP-004 R5

Governance 问题不产生自动 MutationProposal。

## 15. Mutation Surface — `MUT-*`

### MUT-001 undeclared field reject

未声明 path 拒绝。

### MUT-002 frozen reject

Governance/frozen path 拒绝。

### MUT-003 range reject

越界值拒绝。

### MUT-004 repair-level mismatch

R1 不允许 topology/code 修改。

### MUT-005 effective surface intersection

Profile 允许但 Authority/Run/Repair/Risk 不允许 -> reject。

### MUT-006 first sparse profile

默认：

```text

1 repair target
1 hypothesis
1 component
<=2 fields
```

### MUT-007 Genome materialization

Proposal 必须先生成 immutable GenomeManifest candidate，再进入 Candidate Build。

### OBJ-001 hard constraints first

硬约束先于加权目标。

### OBJ-002 guardrail

质量提升但成本/延迟超 guardrail，不得被选为改善。

### OBJ-003 evidence confidence

### OBJ-004 deterministic tie-break

### STR-001 bounded input

只读 Working Set/refs，不扫全历史。

### STR-002 zero candidate

0 Proposal 合法。

### STR-003 repeated failed proposal

### STR-004 no release authority

## 18. Evolution Threat — `ETH-*`

### ETH-001 delayed injection

Evidence 恶意指令按不可信数据，不能突破 Profile/Governance。

### ETH-002 trigger flooding

Dedup/cooldown/budget 防线性 EvolutionRun。

### ETH-003 R4 supply chain

R4 代码必须经过 static/secret/SBOM/sandbox/integration/security 检查。

### ETH-004 budget exhaustion

Budget 达上限后正常终止，不继续强制模型调用。

### P0-SCH-001 priority wave does not shrink mandatory list

### P0-SCH-002 prerequisite contracts

优先波次包含实际测试依赖的 `PromptCompileRequest`、`ModelStreamEvent`、`ValidationReport`、`QueryIntent`、`AuthorizationRequest`。

### P0-PORT-001 typed core SPI

最终 P0 Port 使用实施规范 02 的方法语义、typed request/result 和 `PortResult<T>/PortError`；`Any` 只允许 Phase 0 skeleton。

## 20. Vertical Slices

### 20.1 P0 read-only Eval slice

必须从冻结 Eval 控制面开始：

```text
EvalConfig / EvaluationBundle
→ Isolated Runner
→ Request / Runtime
→ Context / authorized RAG
→ Prompt / selected ModelRoute / ModelInvocation
→ deterministic fake model
→ StructuredDecision
→ grader
→ EvalResult
→ QualityGateDecision
```

普通生产 Request 不直接签发 EvalResult。

### 20.2 P0 action failure-injection slice

```text
StructuredDecision(tool_intents)
→ ToolIntent
→ stable action identity
→ ActionRecord(proposed)
→ AuthorizationRequest / PolicyDecision
→ reservation / execution
→ external write succeeds, response lost
→ ActionReceipt(unknown)
→ reconciliation
→ confirmation ActionReceipt(succeeded)
```

证明没有第二次业务写入。

### 20.3 Evolution vertical slice

继续使用受控 RAG drift fixture：

```text
Telemetry
→ Aggregate/Fingerprint
→ TriggerCandidate
→ Trigger Gate
→ EvolutionTrigger
→ EvolutionRun
→ Evidence Expansion
→ Diagnosis
→ R1 Context Policy MutationProposal
→ machine validation
→ GenomeManifest candidate
→ ReleaseCandidate
→ targeted Eval
→ Objective comparison
→ Reject or Canary
```

Reject 是合法结果。

## 22. Codex 规则

1. 先选择 Test IDs；
2. 先让测试失败，再最小实现；
3. 不删除/放宽测试解决冲突；
4. 规范矛盾时停止扩大代码并回文档；
5. mock 不得绕过关键事务、授权、副作用、恢复或发布边界；
6. 实施算法不得升级为新的 Canonical Object、公共 enum 或第二 Authority。
