## 4. Cross-contract Convergence

### CON-001 `ContractMeta`

所有跨模块持久化对象必须带完整 `meta: ContractMeta`；领域示例省略公共字段不能让机器 Schema 省略 meta。

额外断言：对象自身规范 ID 与 `meta.object_id` 一致；
`meta.contract_version` 必须与当前被校验机器 Schema 的
`x-ueaf-schema-version` 精确一致；任何 Schema 同时声明顶层 `tenant_id` 与
`meta` 时，顶层 `tenant_id` 必须等于 `meta.tenant_id`。

### CON-002 single `EventEnvelope`

公共 Event 只能使用核心完整 `EventEnvelope`；以下删减版字段集合必须被拒绝作为 public event contract：

```text
event_type + aggregate_ref + revision + correlation_refs
```

### CON-003 event naming

公共 event_name 必须匹配：

```text
ueaf.<domain>.<past_tense_fact>
```

PascalCase `TaskQueued/MutationProposed/...` 不能作为公共事件名。

### CON-004 event registry

实现不得发布未登记在核心事件目录的 public `ueaf.*` event。当前 Evolution lifecycle event 若未注册，只能留在模块 11 internal metadata/event。

Machine event catalog 的唯一 registration key 为 `(event_name, event_version)`，并且只能映射一个 `payload_schema_ref`。重复键、同键异 payload ref、不可解析 payload Schema，或 EventEnvelope 三元组与 catalog 不一致均必须失败；catalog 是核心事件目录的机器索引，不成为第二语义 Owner。

### CON-005 single error contract

跨进程/API 使用 `ProblemDetail`，Port 使用 `PortResult<T>/PortError`。

公共 `ErrorEnvelope` Schema、class、API payload 必须不存在。

### CON-006 RuntimeAdapter SPI

公共 `RuntimeAdapter` 必须至少且以核心方法为语义基线：

```text
DescribeRuntime
StartRun
AdvanceRun
SuspendRun
ResumeRun
CancelRun
InspectRun
```

`StreamEvents/Snapshot/ValidateRelease/Close` 等只能是 optional/private convenience，不得替代核心方法。

### CON-007 core capability Port names

RuntimeExecutionContext 只使用规范名：

```text
ContextBuildPort
ModelStepPort
ToolIntentPort
HandoffPort
TelemetryPort
```

不得新增 `ContextPort`、同名不同签名 `TelemetryPort.emit` 等公共接口。

### CON-008 canonical `PrincipalContext`

代码/Schema 中只有一套 `PrincipalContext` 字段：

```text
principal_id
principal_type
tenant_id
roles
scopes
delegation_chain
authentication_strength
credential_ref
data_regions
consent_refs
issued_at
expires_at
revocation_ref
meta
```

顶层 `tenant_id` MUST 存在并等于 `meta.tenant_id`。`subject_id/identity_provider/assurance_level/...` 不能成为第二套顶层 Canonical Schema。

### CON-009 risk type separation

`TaskEnvelope.risk_class` 使用：

```text
compute_only | read_only | reversible_write | high_risk_write
```

Evolution `RepairLevel` 的概念标签使用 `R0..R5`，wire/Schema/config enum 使用 `r0..r5`；`MutationProposal.repair_level` 只允许 `r1|r2|r3|r4`。大写概念标签不得作为 wire 值，Task risk 与 RepairLevel 不得混用。

### CON-010 ReleaseManifest version set

机器 Schema 使用 plural version-set 字段：

```text
agent_versions
prompt_versions
schema_versions
model_route_versions
capability_versions
adapter_versions
knowledge_index_versions
memory_policy_versions
policy_versions
```

不能另建单数线级字段版 ReleaseManifest。

### CON-011 Evolution build chain

必须存在：

```text
MutationProposal
-> GenomeManifest candidate
-> ReleaseCandidate
```

任何 `MutationProposal -> ReleaseCandidate` 直接路径必须失败 contract test。

### CON-012 implementation detail cannot become authority

07/08 中的 Tier、算法步骤、内部判断词和配置不得升级为：

```text
new Canonical Object
new public state/disposition/decision enum
second Semantic Owner / State Writer
second PDP / Release Authority
```

### CON-013 authoritative state/event atomicity

权威状态提交与规范事件记录必须使用 transactional outbox、同一事务日志或可证明等价机制。故障注入必须证明 Event Bus 不可用时权威事务不会丢失待发布事件，并能从持久 outbox 重发；普通 best-effort publish 不合格。

## 5. Runtime / State

### RUN-001 queued 不可跳过 admitting

新 Run 必须 `queued -> admitting`，只有有效 `RunAdmissionResult(admitted)` 才进入 running。

### RUN-002 phase/disposition 正交

非 terminal disposition 为空；terminal disposition 必填。

### RUN-003 stale fencing

旧 fencing token 写入被拒绝。

### RUN-004 crash recovery

Coordinator/Worker 强制终止后可恢复，不重复权威提交。

### RUN-005 edge reject no run

Edge pre-validation reject 不创建 RunRecord/RunAdmissionResult。

### RUN-006 task risk enum

新 API/Schema 不接受 `risk_class=R0|R1|R2|R3`；迁移 reader MAY 映射旧值，但 writer 只输出语义 enum。

### RUN-007 adapter binding frozen before admission

Runtime 必须在创建 `RunRecord` 前选择精确 Adapter/CapabilityBinding；`RunRecord(queued)` 与 `ueaf.run.created` 都引用同一冻结 `runtime_adapter_ref`。Admission 校验该引用，`RuntimeStartCommand`、恢复和重试不得重选或静默切换 Adapter。

### RUN-008 state-dependent record fields

`RunRecord.phase != waiting` 时 `wait_reason=null` 且 `wait_condition_refs=[]`；
`phase=terminal, completion_disposition=completed` 时不得残留 `pending_action_refs`，
必须有 `result_ref` 且 `error_ref=null`；任何 `phase=terminal` 的记录都必须
`lease=null`，不得让终态继续携带执行租约。`phase=admitting|running` 必须持有
Schema-valid 非空 `lease`；`phase=queued|waiting|paused|terminal` 必须
`lease=null`；`retrying` 可以处于等待新租约或已经取得下一尝试租约的窗口，允许
null 或非空 lease。非空 `RunLease` 只使用核心规范字段
`lease_id/holder_id/fencing_token/acquired_at/heartbeat_at/expires_at`，其中
`fencing_token` 为可单调比较的正整数，并满足
`acquired_at <= heartbeat_at < expires_at`。

静态单对象校验只证明上述内部时间顺序，不使用验证时的 wall clock 拒绝历史快照；
某个历史 lease 的 `expires_at` 早于当前验证时点，不代表快照自身无效。相对当前时间的
未过期性必须由 Run State Writer 在 acquire、heartbeat 和 phase write 的同一权威路径中
验证，并结合 CAS/revision 与 fencing token 拒绝迟到写入。

## 8. Tool / Action

### ACT-001 stable action identity before policy

服务端规范化后必须先稳定计算：

```text
action_fingerprint
action_key
ActionRecord(proposed)
```

再进入 validation/PDP。不能授权后首次生成或改写 action identity。

### ACT-002 action_key 幂等

并发提交同一逻辑动作只形成一个权威动作身份/记录。

### ACT-003 timeout unknown 不盲重试

写 API 实际可能成功但响应丢失：

```text
outcome_certainty = unknown
ActionRecord -> reconciling
no second write
```

### ACT-004 certain failure 才重试

权威确认失败且 retry policy/budget 允许，才有下一 Attempt。

### ACT-005 approval fail closed

高风险动作在审批/关键 Audit 不可用时 fail closed。

### ACT-006 permission denied 不自提权

PermissionDenied 可形成 Evidence，不能自动扩大权限。

`ACT-007..017` 在 08 中扩展 canonical arguments、规范 fingerprint 字段、既有 outcome vocabulary、fencing、unknown reconciliation、proof-based retry、有效已签 PolicyDecision 复用、大结果和 secret exclusion。

### ACT-018 terminal evidence chain

`ActionRecord` 以 `executed|failed|unresolved` 进入 terminal 时，必须保留非空
`policy_decision_ref`、`idempotency_reservation_ref`、`receipt_refs` 与
`latest_receipt_ref`，且 `latest_receipt_ref` 必须精确等于 `receipt_refs` 最后一项；
空 `receipt_refs` 当且仅当 `latest_receipt_ref=null`。未实际执行的
`denied|approval_rejected|invalid|cancelled` 不得被误要求 reservation；其中
`denied|approval_rejected` 不得残留 reservation 或 receipt 执行产物；`invalid`
不得残留 Policy、Approval、reservation 或 receipt；所有
`denied|approval_rejected|invalid|cancelled` 均不得残留 lease token 或
reconciliation state。`cancelled` 允许保留执行前已经提交的 reservation，以及路径上
已经产生的 Policy/Approval 引用作为审计事实。

上述断言只覆盖单个 `ActionRecord` 的契约形状。Policy、Approval、reservation、
Receipt 引用的真实存在、状态及同一 action 绑定必须由 Phase 3 行为门禁解析验证；
单对象 Schema 通过不得被当成副作用已经可以消费的证明。

## 11. Eval / Release

### EVAL-001 baseline pairing

Candidate/baseline 可比较；差异显式记录。

### EVAL-002 hard safety first

安全硬失败不能被平均分抵消。

### EVAL-003 inconclusive

缺证据 -> inconclusive/invalid，不 auto pass。

`EVAL-004..018` 在 08 中扩展冻结 EvalRun/Isolated Runner、Dataset provenance、baseline equivalence、hard grader、Judge freeze/calibration、样本和关键 slice、合法 reference access、污染 invalid、attempt history 与 Release Authority 分离。

### REL-001 candidate != manifest

Runtime/Routing 不加载 ReleaseCandidate。

### REL-002 manifest immutable

运行绑定 release_id 不原地改变。

### REL-003 rollback

Canary 硬停止可按已签清单 rollback 并留证据。

### REL-004 release activation chain fail closed

Release 激活必须逐对象验证 `ReleaseCandidate`、`QualityGateDecision`、
`SecurityGateDecision`、`OperationalReadinessDecision`、`ReleaseDecision` 与
`ReleaseManifest` 的 canonical Schema 和不变量，并满足以下闭链条件：

- 三类 Gate 均为 `active/pass`、未过期、未撤销，且 Quality/Security 不含
  `hard_failure_refs`；V1 初版拒绝 `conditional`；
- Candidate、tenant、environment、scope 精确一致；
- scope 显式 `tenant_id` 必须等于 canonical tenant；Candidate 的九类
  `component_ref@version` 必须与 Manifest 对应 plural version-set 精确相等，且
  每个 `(component_type, component_ref, version)` identity tuple 唯一、不得让同一
  identity 指向多个 digest；`contract_version_ranges`、`compatibility_matrix_ref`、
  `migration_refs` 精确绑定；
- `ReleaseDecision` 为 `active/approved`，其 Candidate 和三类 Gate 引用精确匹配，
  `issued_at < expires_at` 且当前未过期；
- `ReleaseManifest` 为 `active`，四类 Decision 引用精确匹配，创建时间不早于
  `ReleaseDecision.issued_at`；
- 三类 Gate 的 `issued_by` 必须两两不同；Builder 不得兼任任何 Gate/Release
  Authority，Release Authority 不得兼任 Gate Authority，Manifest producer 不得等于
  Candidate Builder；
- 激活 API 必须要求 Phase 4 提供可信 `ReleaseActivationVerifier`，逐对象验证完整性、
  Evidence 可访问性、authority role/trust、waiver 冲突和 scope coverage，并验证 rollback
  compatibility；每项必须返回字面值 `true`，缺少验证器或任一项未明确通过都 fail closed。
  Phase 0 只定义并调用该依赖边界，不声称已经实现生产级解析、签名或信任服务；真实
  verifier 必须从 immutable authority store 验证 Candidate digest/version graph 绑定及
  Gate Evidence 覆盖，allow-all fake 只能测试 boundary；
- 激活校验必须基于入口规范 JSON 的独立不可变快照，每次 verifier hook 只能收到新的
  disposable deep copy，并在返回前检测 caller input 是否变化。实际激活消费者必须使用
  content-addressed immutable store 或 CAS；返回后的任意可变原对象不是发布证明；
- 任一失败、过期、撤销、引用错配、范围错配、环境错配、租户错配或时间倒置均
  MUST fail closed，不得激活。

### REL-005 manifest lifecycle and delivery contract

`ReleaseManifest` 只接受规范 lifecycle vocabulary、plural version-set 字段、完整
contract compatibility、migration、rollout、rollback 与 observation-window 交付契约；
缺少任一 required delivery 字段、使用单数版本别名或不安全的空 rollout/observation
条件均必须拒绝。

### P0-SCH-003 registry implementation integrity

```text
-> Policy/Approval/Reservation
-> external write succeeds but response lost
-> ActionReceipt(unknown)
-> reconciliation
-> confirmation receipt
```

普通生产 Request 不直接签发 EvalResult；action failure-injection 必须证明没有第二次业务写入。

## 21. Evolution Vertical Slice

固定一个可控 RAG drift fixture，例如：

```text
baseline retrieval_empty ≈ 1%
inject query distribution drift
current retrieval_empty ≈ 8%
```

必须闭环：

```text
Telemetry
-> Aggregate/Fingerprint
-> TriggerCandidate
-> Trigger Gate
-> EvolutionTrigger
-> EvolutionRun
-> Evidence Expansion
-> Diagnosis
-> R1 Context Policy MutationProposal
-> machine validation
-> GenomeManifest candidate
-> ReleaseCandidate
-> targeted Eval
-> Objective comparison
-> Reject or Canary
```

Reject 是合法结果，不得为演示进化而放宽 Gate。

## 22. CI Gate

PR 至少：

```text
schema validation
CON-* relevant tests
unit
contract
migration
security invariants
adapter conformance relevant subset
```

涉及 P0 的 PR 还必须运行对应 `PRM/CTX/RAG/ACT/SEC/EVAL/P0-SCH/P0-PORT` 子集。Tool/Evolution/Release 核心变更运行对应 failure-injection/vertical slice。

## 23. Codex 规则

1. 先选 Test IDs；
2. 先让测试失败，再最小实现；
3. 不删除/放宽测试解决冲突；
4. 规范矛盾时停止扩大代码并回文档；
5. mock 不能替代关键事务/副作用/恢复测试；
6. 实施算法不得升级为新 Canonical Object、公共 enum 或第二 Authority。

## 24. 完成定义

实现任务应变成：

```text
choose Test IDs
-> implement canonical schema/port/storage
-> make tests green
-> preserve invariants
```

其中 `CON-*` 保证文档审计已经收敛的契约不会再次漂移。
