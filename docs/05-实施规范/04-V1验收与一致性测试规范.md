# UEAF V1 验收与一致性测试规范

版本：`0.2.0-draft`  
规范状态：Draft  
Architecture Generation: `V1`  
Maturity: `Required for Implementation`  
Implementation: `Current`

## 1. 目的

本文把 UEAF V1 架构不变量转换为 Codex/工程实现必须通过的可执行验收场景。规范正确性由测试和证据判断，不由“代码看起来合理”判断。


## 4. Cross-contract Convergence

### CON-001 `ContractMeta`

所有跨模块持久化对象必须带完整 `meta: ContractMeta`；领域示例省略公共字段不能让机器 Schema 省略 meta。

额外断言：对象自身规范 ID 与 `meta.object_id` 一致。

### CON-002 single `EventEnvelope`

公共 Event 只能使用核心完整 `EventEnvelope`；以下删减版字段集合必须被拒绝作为 public event contract：

```text
event_type + aggregate_ref + revision + correlation_refs
```

### CON-003 event naming

公共 event_name 必须匹配：

```text
ueaf.<domain>.<past_tense_fact>
```

PascalCase `TaskQueued/MutationProposed/...` 不能作为公共事件名。

### CON-004 event registry

实现不得发布未登记在核心事件目录的 public `ueaf.*` event。当前 Evolution lifecycle event 若未注册，只能留在模块 11 internal metadata/event。

### CON-005 single error contract

跨进程/API 使用 `ProblemDetail`，Port 使用 `PortResult<T>/PortError`。

公共 `ErrorEnvelope` Schema、class、API payload 必须不存在。

### CON-006 RuntimeAdapter SPI

公共 `RuntimeAdapter` 必须至少且以核心方法为语义基线：

```text
DescribeRuntime
StartRun
AdvanceRun
SuspendRun
ResumeRun
CancelRun
InspectRun
```

`StreamEvents/Snapshot/ValidateRelease/Close` 等只能是 optional/private convenience，不得替代核心方法。

### CON-007 core capability Port names

RuntimeExecutionContext 只使用规范名：

```text
ContextBuildPort
ModelStepPort
ToolIntentPort
HandoffPort
TelemetryPort
```

不得新增 `ContextPort`、同名不同签名 `TelemetryPort.emit` 等公共接口。

### CON-008 canonical `PrincipalContext`

代码/Schema 中只有一套 `PrincipalContext` 字段：

```text
principal_id
principal_type
roles
scopes
delegation_chain
authentication_strength
credential_ref
data_regions
consent_refs
issued_at
expires_at
revocation_ref
meta
```

`subject_id/identity_provider/assurance_level/...` 不能成为第二套顶层 Canonical Schema。

### CON-009 risk type separation

`TaskEnvelope.risk_class` 使用：

```text
compute_only | read_only | reversible_write | high_risk_write
```

Evolution `RepairLevel` 使用 `R0..R5`。两者类型和 enum 不得混用。

### CON-010 ReleaseManifest version set

机器 Schema 使用 plural version-set 字段：

```text
agent_versions
prompt_versions
schema_versions
model_route_versions
capability_versions
adapter_versions
knowledge_index_versions
memory_policy_versions
policy_versions
```

不能另建单数线级字段版 ReleaseManifest。

### CON-011 Evolution build chain

必须存在：

```text
MutationProposal
-> GenomeManifest candidate
-> ReleaseCandidate
```

任何 `MutationProposal -> ReleaseCandidate` 直接路径必须失败 contract test。

## 5. Runtime / State

### RUN-001 queued 不可跳过 admitting

新 Run 必须 `queued -> admitting`，只有有效 `RunAdmissionResult(admitted)` 才进入 running。

### RUN-002 phase/disposition 正交

非 terminal disposition 为空；terminal disposition 必填。

### RUN-003 stale fencing

旧 fencing token 写入被拒绝。

### RUN-004 crash recovery

Coordinator/Worker 强制终止后可恢复，不重复权威提交。

### RUN-005 edge reject no run

Edge pre-validation reject 不创建 RunRecord/RunAdmissionResult。

### RUN-006 task risk enum

新 API/Schema 不接受 `risk_class=R0|R1|R2|R3`；迁移 reader MAY 映射旧值，但 writer 只输出语义 enum。

## 6. Runtime Adapter

### ADP-001 Model Gateway 强制

Adapter model step 必须经 `ModelStepPort`。

### ADP-002 Tool Gateway 强制

function/tool candidate 只能变成 `ToolIntent`。

### ADP-003 unsupported capability

不支持必须显式 unsupported/rejected。

### ADP-004 第二 Adapter 等价

同一 read-only Agent Definition 在 LangGraph + Adapter #2 下 UEAF Task/Run/Context/Audit/Completion 语义等价。

### ADP-005 RuntimeEvent != EventEnvelope authority

Adapter 原生/归一 RuntimeEvent 不能直接伪造 `ueaf.action.*`、Policy、Audit、Release 等权威事件。

## 7. Tool / Action

### ACT-001 stable action identity before policy

服务端规范化后必须先稳定计算：

```text
action_fingerprint
action_key
ActionRecord(proposed)
```

再进入 validation/PDP。不能授权后首次生成或改写 action identity。

### ACT-002 action_key 幂等

并发提交同一逻辑动作只形成一个权威动作身份/记录。

### ACT-003 timeout unknown 不盲重试

写 API 实际可能成功但响应丢失：

```text
outcome_certainty = unknown
ActionRecord -> reconciling
no second write
```

### ACT-004 certain failure 才重试

权威确认失败且 retry policy/budget 允许，才有下一 Attempt。

### ACT-005 approval fail closed

高风险动作在审批/关键 Audit 不可用时 fail closed。

### ACT-006 permission denied 不自提权

PermissionDenied 可形成 Evidence，不能自动扩大权限。

## 8. Context / RAG

### RAG-001 ACL before relevance

未授权候选在排序前被过滤。

### RAG-002 single retrieval_empty != trigger

单次 retrieval_empty 不直接成为 Trigger/Mutation。

### RAG-003 context budget

Context Mutation 后仍满足模型/context/token/permission 约束。

### RAG-004 ContractMeta inheritance

`ContextManifest/EvidencePack/MemoryRecord` Schema 使用核心 ContractMeta，不采用模块内简写版第二公共 meta。

## 9. Security / Identity

### SEC-001 trusted principal mapping

外部 body 中 tenant/role/scope/principal 无法覆盖 canonical PrincipalContext。

### SEC-002 delegation narrows

Handoff/Resume/Retry 后 scopes 只能保持/收窄。

### SEC-003 credential non-leak

credential/secret 不进入 Prompt、Tool args、普通 Log/Trace/Event payload、Evolution Working Set。

### SEC-004 decisions orthogonal

`PolicyDecision`、`SecurityGateDecision`、`QualityGateDecision`、`OperationalReadinessDecision`、`ReleaseDecision` 不能互换。

### SEC-005 R5 no auto-elevation

Governance Root 无自动 Mutation path。

## 10. Eval / Release

### EVAL-001 baseline pairing

Candidate/baseline 可比较；差异显式记录。

### EVAL-002 hard safety first

安全硬失败不能被平均分抵消。

### EVAL-003 inconclusive

缺证据 -> inconclusive/invalid，不 auto pass。

### REL-001 candidate != manifest

Runtime/Routing 不加载 ReleaseCandidate。

### REL-002 manifest immutable

运行绑定 release_id 不原地改变。

### REL-003 rollback

Canary 硬停止可按已签清单 rollback 并留证据。

## 11. Evidence

### EVD-001 normal path 0 LLM token

Summary/aggregate/fingerprint/Trigger Candidate 默认无 LLM。

### EVD-002 metric cardinality

run/trace/user/document/prompt 不作为常规 Metric label。

### EVD-003 backpressure

优先保留 Audit/Security/ActionReceipt/P0-P1/Run Summary。

### EVD-004 evidence gap visible

缺采集必须显式 gap。

### EVD-005 TelemetryPort conformance

公共 `TelemetryPort` 只允许核心 `EmitTrace/EmitMetric/EmitLog/EmitAudit` 语义。

## 12. Evolution Trigger

### EVO-001 anomaly != trigger

普通异常/告警/单次失败不直接 Trigger。

### EVO-002 Trigger Gate

非 P0 至少检查 evidence/relevance/mutable/mitigation/novelty/value/cooldown。

### EVO-003 no_evolution_needed

合法 terminal disposition。

## 13. Diagnosis / Repair

### REP-001 symptom != repair target

支持跨层 root cause。

### REP-002 smallest effective repair

证据支持 R1 时不扩大到不相关 R2/R3/R4。

### REP-003 escalation requires evidence

失败本身不自动扩大 scope。

### REP-004 R5

Governance 问题不产生自动 MutationProposal。

## 14. Mutation Surface

### MUT-001 undeclared field reject

未声明 path 拒绝。

### MUT-002 frozen reject

Governance/frozen path 拒绝。

### MUT-003 range reject

越界值拒绝。

### MUT-004 repair-level mismatch

R1 不允许 topology/code 修改。

### MUT-005 effective surface intersection

Profile 允许但 Authority/Run/Repair/Risk 不允许 -> reject。

### MUT-006 first sparse profile

默认：

```text
1 candidate
1 repair target
1 hypothesis
1 component
<=2 fields
```

### MUT-007 Genome materialization

通过 Validator 的 Proposal 必须先生成新 immutable GenomeManifest candidate，再进入 Candidate Build。

## 15. Objective

### OBJ-001 hard constraints first

硬约束先于加权目标。

### OBJ-002 guardrail

质量提升但成本/延迟超 guardrail -> not improved。

### OBJ-003 evidence confidence

业务 KPI 证据不足 -> inconclusive。

### OBJ-004 deterministic tie-break

按 Profile 稳定 tie-break，不交自由 LLM。

## 16. Strategy

### STR-001 bounded input

只读 Working Set/refs，不扫全历史。

### STR-002 zero candidate

0 Proposal 合法。

### STR-003 repeated failed proposal

无新证据不重复已知失败 Proposal。

### STR-004 no release authority

Strategy 无 Eval/Release 签发权。

## 17. Evolution Threat

### ETH-001 delayed injection

Evidence 中恶意指令按不可信数据，不能突破 Profile/Governance。

### ETH-002 trigger flooding

Dedup/cooldown/budget 防线性 EvolutionRun。

### ETH-003 R4 supply chain

R4 代码必须 static/secret/SBOM/sandbox/integration/security 检查。

### ETH-004 budget exhaustion

Budget 达上限后正常终止，无继续强模型调用。

## 18. Evolution Vertical Slice

固定一个可控 RAG drift fixture，例如：

```text
baseline retrieval_empty ≈ 1%
inject query distribution drift
current retrieval_empty ≈ 8%
```

必须闭环：

```text
Telemetry
-> Aggregate/Fingerprint
-> TriggerCandidate
-> Trigger Gate
-> EvolutionTrigger
-> EvolutionRun
-> Evidence Expansion
-> Diagnosis
-> R1 Context Policy MutationProposal
-> machine validation
-> GenomeManifest candidate
-> ReleaseCandidate
-> targeted Eval
-> Objective comparison
-> Reject or Canary
```

Reject 是合法结果，不得为演示进化而放宽 Gate。

## 19. CI Gate

PR 至少：

```text
schema validation
CON-* relevant tests
unit
contract
migration
security invariants
adapter conformance relevant subset
```

Tool/Evolution/Release 核心变更运行对应 failure-injection/vertical slice。

## 20. Codex 规则

1. 先选 Test IDs；
2. 先让测试失败，再最小实现；
3. 不删除/放宽测试解决冲突；
4. 规范矛盾时停止扩大代码并回文档；
5. mock 不能替代关键事务/副作用/恢复测试。

## 21. 完成定义

实现任务应变成：

```text
choose Test IDs
-> implement canonical schema/port/storage
-> make tests green
-> preserve invariants
```

其中 `CON-*` 保证这次文档审计已经收敛的契约不会再次漂移。
