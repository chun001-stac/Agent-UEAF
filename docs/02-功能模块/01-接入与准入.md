# 接入与准入

## 1. 定位

接入与准入模块是 UEAF 的唯一外部请求入口，并同时承载两个不能混同的阶段：先把 HTTP、RPC、消息队列、事件总线和交互式通道中的不可信输入转换为通过边缘预校验的请求；再对 Runtime Domain 已创建的 `RunRecord(phase=admitting)` 生成确定性的 `RunAdmissionResult`。边缘 accepted 只允许创建候选 Task/Run，不代表 Agent 已获准执行；只有 `RunAdmissionResult.outcome=admitted` 才允许 Run 进入 `running`。

本模块位于协议边缘和运行时之间，固定主链如下：

```text
外部调用方
  -> 01 接入与准入
  -> 02 Agent Runtime
  -> 03 调用前：PromptContract -> ModelInvocation
  -> Model Provider
  -> 03 调用后：ModelRunResult -> StructuredDecision
  -> 02 Agent Runtime
```

`04 上下文、RAG 与记忆`只向 Runtime 提供 `ContextManifest`、`EvidencePack` 和 Memory 契约；`05 工具、MCP 与动作执行`唯一拥有 `ActionRecord`；`06 工作流与多 Agent`拥有 `WorkflowRun`、`NodeRun`，但不拥有根 `TaskState` 或根 `RunRecord`。LangGraph、Microsoft Agent Framework、OpenAI Agents SDK、Google ADK、CrewAI 等底层框架只能通过 `Runtime Adapter` 接入，不能成为接入层的协议或状态所有者。

## 2. 职责与非职责

### 2.1 职责

- 终止外部传输协议，限制报文大小、类型、速率和连接生命周期。
- 验证调用方凭证，解析用户、服务、工作负载和委托链。
- 由可信声明绑定 `tenant_id`、`principal_id`、数据区域和认证强度；请求正文不得覆盖这些字段。
- 校验输入 Schema、编码、附件引用、幂等语义和敏感数据处理目的。
- 将原始请求规范化为不可变 `RequestEnvelope`。
- 边缘预校验通过后创建或关联不可变 `TaskEnvelope`，明确目标、完成条件、风险和输入指纹。
- 分配 `BudgetEnvelope`，冻结总 deadline、步骤、Token、费用、工具和并发上限。
- 解析已批准的 `AgentDefinition`、`ReleaseManifest` 及兼容契约版本。
- 执行配额、并发、风险、区域、功能开关和发布门禁。
- 在 02 创建 `RunRecord(queued)` 后，对其产生可解释的 `RunAdmissionResult`；本次 Run 的版本校验单独记录为 `ReleaseValidationResult`，并引用治理面已签发的 `ReleaseManifest` 与 `ReleaseDecision`。
- 对同步、流式和异步接入返回稳定的接受、拒绝、限流和错误语义。
- 发布接入 Trace、Metric 和必要 AuditEvent；敏感正文只保存受控引用。

### 2.2 非职责

- 不调用模型，不编译 Prompt，不解释模型输出。
- 不构造 RAG 证据或长期记忆，不把请求正文自动写入 Memory。
- 不选择或执行工具，不创建 `ActionRecord`，不以接入幂等键代替业务动作 `action_key`。
- 不调度工作流节点或子 Agent。
- 不拥有业务系统事实，也不根据自然语言推断权限。
- 不把认证成功解释为具体业务动作已经授权。
- 不在运行过程中静默切换 Release、Prompt、策略、模型或工具版本。
- 不让底层 Agent SDK 的 request、thread、session 或 run 对象泄漏为 UEAF canonical 契约。

## 4. Canonical 契约

### 4.1 公共元数据 `ContractMeta`

本模块产生的 canonical 对象都必须携带 `ContractMeta`。字段语义不能由传输协议或 SDK 类名替代。

| 字段 | 必填 | 语义 |
| --- | --- | --- |
| `contract_name` / `contract_version` | 是 | canonical 契约名和语义版本 |
| `object_id` | 是 | 在 `tenant_id + contract_name` 范围内唯一 |
| `tenant_id` | 是 | 可信租户标识；边缘解析完成前使用隔离的 ingress 对象，不伪造 canonical tenant |
| `request_id` | 是 | 一次外部接入标识 |
| `task_id` / `run_id` / `turn_id` | 按生命周期 | 不得用一个 ID 代替全部生命周期 |
| `trace_id` / `release_id` | 按生命周期 | 仅在实际存在时关联，不得伪造 |
| `producer` / `producer_version` | 是 | 对象生产组件及其版本 |
| `created_at` | 是 | 首次提交时间，不可改写 |
| `expires_at` | 按对象 | 有效期对象必须提供；空值不表示无限保留 |
| `classification` | 是 | `public/internal/confidential/restricted` 或批准的兼容扩展 |
| `purpose` | 是 | 允许处理目的的字符串数组；空集合表示不可消费 |
| `provenance` | 是 | 原始来源或派生链 |
| `integrity_ref` | 按对象 | 审批、动作、治理决定和发布清单必须提供 |
| `extensions` | 否 | 仅反向域名前缀扩展；不得覆盖规范字段 |

### 4.2 输入：`IngressRequest`

`IngressRequest` 是边缘输入，不是可信 canonical 对象。

| 字段 | 说明 |
| --- | --- |
| `transport` | 协议、方法、模板化路由、媒体类型和协议版本 |
| `headers` | 经 allowlist 过滤的头字段，不包含日志可见凭证 |
| `credential_ref` | 凭证的安全句柄或传输层引用 |
| `payload` / `attachment_refs` | 原始请求或受控对象存储引用 |
| `client_request_key` | 客户端重试关联键；只用于同一接入语义的去重 |
| `requested_delivery` | sync、stream、async、callback 或 poll |
| `client_deadline` | 客户端期望的绝对 deadline，可被服务端进一步收紧 |
| `disconnect_signal` | 可传播的连接取消信号 |

### 4.3 `PrincipalContext`

| 字段 | 说明与不变量 |
| --- | --- |
| `meta` | 必须是完整 `ContractMeta` |
| `principal_id` | 经可信身份映射得到的主体标识 |
| `principal_type` | 仅允许 `end_user/calling_service/agent/workload/human_approver` |
| `tenant_id` | 必须与 `meta.tenant_id` 相同 |
| `roles` | 来自可信目录或策略映射的角色 |
| `scopes` | 所有委托跳的有效权限交集，不得取并集 |
| `delegation_chain` | 每一跳的 delegator、delegatee、scope、purpose、时效和证据 |
| `authentication_strength` | 认证强度和是否满足高风险重新认证要求 |
| `credential_ref` | 可选 opaque 引用；不得包含明文凭证 |
| `data_regions` | 数据驻留、模型区域和工具区域限制 |
| `consent_refs` | 涉及需同意数据时必填 |
| `issued_at` / `expires_at` | 可信签发和过期时间 |
| `revocation_ref` | 可选撤销状态引用；高风险动作前必须检查 |

渠道服务、允许 Agent 集合和可信策略属性如需传播，必须放入命名空间化 `meta.extensions`，不得另造可与 `principal_id`、`roles`、`scopes` 或 `data_regions` 冲突的身份字段。认证成功只证明“当前是谁”，不证明“允许做什么”。任何具体资源和动作仍由相应策略执行点重新授权。

### 4.4 `RequestEnvelope`

| 字段 | 说明 |
| --- | --- |
| `meta` | `ContractMeta` |
| `request_id` | 必须与 `meta.request_id` 相同 |
| `channel` / `protocol` | 来源渠道与线级协议 |
| `input_ref` 或受限 `input` | 原始载荷的受控引用，或通过大小/分类限制的内联输入 |
| `client_correlation_id` | 调用方关联标识；不得充当可信 trace_id |
| `received_at` / `deadline_at` | 可信接收时间和服务端接受的绝对 deadline |
| `principal_context_ref` | 指向已验证 `PrincipalContext` |
| `validation_status` | 边缘预校验状态及稳定原因引用 |
| `operation` | 稳定用例名 |
| `normalized_input` | 通过 Schema 校验的派生输入，不覆盖原始 input 证据 |
| `input_schema_ref` | 输入 Schema 名称、版本和兼容结果 |
| `attachment_refs` | 已扫描、分类且有访问范围的附件引用 |
| `input_fingerprint` | 对规范化输入、主体、租户、操作和契约版本计算 |
| `validation` | 字段级校验摘要、裁剪与拒绝原因，不保存敏感值 |
| `delivery` | 协商后的交付方式和回调/轮询契约 |

`RequestEnvelope` 一旦通过边缘预校验即不可原地修改。输入修订产生新的 request 或显式的任务目标变更事件；该状态不代表 Run 已 admitted。

| 字段 | 说明 |
| --- | --- |
| `meta` | 完整 `ContractMeta` |
| `task_id` | 可跨多次 Run 的业务任务标识；必须与 `meta.task_id` 一致 |
| `request_refs` | 触发或修订任务的请求引用 |
| `goal` | 规范化业务目标，不包含模型自由推断出的新目标 |
| `completion_criteria` | 可判定的完成条件和必要证据/副作用条件 |
| `constraints` | 时间、数据、地区、渠道、输出和禁止事项 |
| `risk_class` | `R0` 纯计算、`R1` 只读、`R2` 可逆写、`R3` 高风险写 |
| `owner_ref` | 任务语义所有者或责任主体引用 |
| `budget_ref` | 指向不可变 `BudgetEnvelope` |
| `revision` | 目标、约束或完成条件变更时单调增加 |
| `allowed_capability_scope` | 能力发现上限，执行仍需重新授权 |
| `initial_facts` | 仅包含经校验输入事实和权威引用 |
| `open_questions` | 进入运行前已知的缺失信息 |
| `expected_output_contract` | 最终结果契约及消费者兼容范围 |

### 4.6 `BudgetEnvelope`

| 字段 | 说明 |
| --- | --- |
| `absolute_deadline` | 所有子调用共享的硬截止时间 |
| `max_runtime_steps` | Runtime 最大确定性步数 |
| `max_model_calls` / `max_input_tokens` / `max_output_tokens` | 模型调用预算 |
| `max_tool_calls` / `max_write_actions` | 工具和副作用额度 |
| `max_workflow_nodes` / `max_depth` / `max_parallelism` | 编排预算 |
| `max_cost` | 归一费用上限及币种 |
| `risk_action_budget` | 各风险等级动作额度，不能被子任务重置 |
| `reserved_finalize_budget` | 保留给聚合、最终验证和结果交付的不可挪用预算 |
| `budget_policy_version` | 分配策略版本 |

时间、Token、费用、步骤、工具调用、并发和子任务等每一维必须有明确上限，或显式标记为 `unbounded_by_contract` / 组织默认策略引用；缺字段不得解释为无限。所有子预算预留之和不得静默超过父预算。

### 4.7 `ReleaseValidationResult`

`ReleaseValidationResult` 只回答“治理面已经批准的 Release，当前是否仍可绑定到本次请求和目标运行环境”。它是模块 01 的短期确定性校验结果，不得取代模块 08 签发的 `ReleaseDecision`。

| 字段 | 说明 |
| --- | --- |
| `outcome` | `valid`、`invalid` 或 `deferred` |
| `release_binding` | `ReleaseManifest` 及 Agent/Prompt/Schema/Policy/Tool/Model 兼容集合 |
| `release_decision_ref` | 签发该 Manifest 的最终 `ReleaseDecision` 引用 |
| `compatibility_report` | 请求、Agent、消费者和运行环境的版本交集 |
| `reason_codes` | 未发布、已撤销、区域不兼容、契约无交集等稳定原因 |
| `integrity_ref` | ReleaseManifest 与兼容集合的完整性证据 |
| `validated_at` / `expires_at` | 校验时间和有效期 |

### 4.8 Run 级输出：`RunAdmissionResult`

`RunAdmissionResult` 是 01 针对一个已存在 `run_id` 的确定性准入聚合结果。它不是边缘认证结果、不是发布 Gate，也不能由模型产生。边缘预校验通过使用 `ueaf.request.accepted` 和不可变 `TaskEnvelope` 表达；失败使用 `ueaf.request.rejected`，此时不得创建 Run。

| 字段 | 说明 |
| --- | --- |
| `run_admission_result_id` | 必填；本次 Run 准入结果的稳定对象标识 |
| `run_id` | 必填；仅绑定 02 已创建、处于 `phase=admitting` 且由调用方持有有效 admission lease 的 `RunRecord` |
| `outcome` | 仅允许 `admitted`、`rejected`、`deferred` |
| `reason_codes` | 稳定、可本地化且不泄露资源存在性的原因码 |
| `retry_after` | 仅 deferred 可选；建议调用方何时重新触发准入，不表示自动获准 |
| `validation_refs` | 输入、身份、版本、区域与完整性校验证据 |
| `policy_decision_refs` | 针对本次准入输入的 `PolicyDecision` 引用；缺失不得默认允许 |
| `budget_snapshot_ref` | 本次准入绑定的预算快照引用 |
| `release_manifest_ref` | 当前环境有效且完整性验证通过的 `ReleaseManifest` 引用 |
| `created_at` | 可信生成时间 |
| `quota_snapshot` | 准入时配额和并发水位摘要 |
| `risk_assessment_ref` | 风险分类证据 |
| `release_validation_ref` | 必须指向 `outcome=valid` 的 `ReleaseValidationResult` 才能得到 `admitted` |
| `obligations` | Runtime 必须执行的额外义务，如强审批、禁止流式或强制引用 |
| `expires_at` | 结果有效期；恢复时可能需要重新准入 |
| `audit_ref` | 高风险允许/拒绝的审计关联 |
| `principal_context_ref` | `admitted` 时必填；只传可信对象引用，不复制凭证或身份载荷 |
| `request_envelope_ref` | 规范化请求引用；拒绝时按数据最小化保留 |
| `task_envelope_ref` | 该 Run 绑定的不可变准入输入 |
| `budget_envelope_ref` | 可选便利引用；不得替代 `budget_snapshot_ref` |
| `release_binding` | 可选的冻结兼容版本投影；不得替代 `release_manifest_ref` |
| `delivery_contract` | admitted/deferred 的交付、轮询或重试契约 |

02 不得直接消费原始 HTTP body、JWT claims 或某个云网关的专有对象。边缘预校验失败不进入 02；Run 级 `rejected` 由 02 原子提交 `phase=terminal, completion_disposition=rejected`，`deferred` 提交 `phase=waiting` 并登记恢复条件，只有后续重新准入为 `admitted` 才能进入 `running`。

### 4.9 对外 `ResponseEnvelope` 与 `ErrorEnvelope`

所有响应至少带 `request_id`、状态、契约版本和轮询/结果引用。公开错误字段为 `code`、`category`、`message`、`retryable`、`retry_after`、`request_id`；内部根因、堆栈、策略正文、令牌、主机名和资源存在性不得回显。

稳定类别包括：`invalid_input`、`unauthenticated`、`forbidden`、`not_found_or_forbidden`、`rate_limited`、`admission_rejected`、`version_incompatible`、`budget_unavailable`、`dependency_unavailable`、`conflict`、`cancelled`、`internal`。

## 5. 主流程

1. Front Door 解析协议，校验允许的方法、媒体类型、消息大小和压缩比；失败提交 `ueaf.request.rejected`，不创建 Run。
2. 生成 `request_id`、`trace_id`，登记原始载荷引用和内容哈希。
3. Credential Verifier 验证签名、issuer、audience、时效、nonce 和认证强度。
4. Tenant Binder 从可信声明和目录绑定租户、主体、委托链、区域与用途；忽略正文中的身份字段。
5. Contract Validator 执行输入 Schema、长度、枚举、附件安全和数据分类校验。
6. Request Normalizer 形成不可变 `RequestEnvelope` 和输入指纹。
7. Task Builder 创建新任务或以期望 `revision` 关联已有任务，形成 `TaskEnvelope`。
8. Risk Classifier 依据目标、数据分类、允许能力和潜在副作用给出风险等级。
9. Budget Allocator 将客户端 deadline 与服务端 SLO 取更严格值，分配多维预算并保留收束预算。
10. 边缘预校验通过后提交 `ueaf.request.accepted`，形成不可变 `TaskEnvelope`，把规范化候选交给 02。
11. 02 创建或关联 `TaskState`，创建 `RunRecord(phase=queued)`；取得 admission lease 后提交 `queued -> admitting`。
12. Release Resolver 针对该 `run_id` 解析已批准的 `ReleaseManifest` 和 Agent/Prompt/Schema/Policy/Tool/Model 兼容交集。
13. Admission Controller 针对该 `run_id` 执行租户配额、并发、区域、策略、风险和运行条件检查，生成 `RunAdmissionResult`。
14. `admitted` 令 02 提交 `admitting -> running` 并启动 Runtime；`deferred` 提交 `admitting -> waiting`；`rejected` 提交 `terminal/rejected`。
15. Delivery Negotiator 返回同步、流式或异步交付引用；传输断开只取消交付，不自动证明已接受的异步 Run 已取消。

## 6. 状态与数据所有权

### 6.1 两级状态

```text
边缘预校验：received -> authenticated -> validated -> accepted
任一边缘非终态 -> rejected

Run 准入：queued -> admitting -> running       (admitted)
                     admitting -> waiting       (deferred)
                     admitting -> terminal/rejected
```

边缘状态与 `RunPhase` 是两套对象，不得合并为一个 `AdmissionDecision`。状态必须单调推进；accepted 后不得把同一 `request_id` 改写为另一个租户、主体或输入指纹。

### 6.2 唯一所有者

| 对象或状态 | 唯一写所有者 | 其他模块权限 |
| --- | --- | --- |
| 外部身份和角色事实 | 企业 IdP/目录 | 01 验证并形成快照，不修改来源 |
| `PrincipalContext` 准入快照 | Tenant Binder | 02/04/05/06 只读并在敏感操作前重新验证 |
| `RequestEnvelope` | Request Normalizer | 下游只读引用 |
| 原始 `TaskEnvelope` | Task Builder | 02 接收后创建或关联可变 `TaskState`；原始目标不原地覆盖 |
| `BudgetEnvelope` 根预算 | Budget Allocator/预算控制面 | 02/06 预留和结算，不能扩大硬上限 |
| `RunAdmissionResult` | Admission Controller | 02 执行 obligations，不自行放宽 |
| `ReleaseBinding` | Release Control | 运行期间只读；迁移必须显式发生 |
| Root `TaskState` / `RunRecord` | 02 Agent Runtime | 01 只针对已存在 run_id 产生准入证据，不写 Run 状态 |
| `ActionRecord` | 05 工具与动作执行 | 01 不创建、不更新 |
| `WorkflowRun` / `NodeRun` | 06 工作流编排 | 01 不创建、不更新 |

接入去重记录只证明同一外部请求是否已接受或已有结果引用，不能证明退款、发信、删除等副作用是否发生。

## 7. 权限与多租户

- `tenant_id` 必须来自受信任 issuer 与目录映射；请求参数、Prompt、附件和模型输出均不得指定租户。
- 每个租户独立执行配额、并发、Release allowlist、模型区域、工具范围和数据驻留策略。
- 缓存键必须包含租户、主体/权限摘要、operation、输入指纹、契约和 Release 版本。
- 外部错误可把“无权限”和“资源不存在”合并，内部 Audit 保留真实原因。
- 服务代理用户时必须保留完整委托链，scope 取每一跳交集，任何一跳过期即不再满足高风险准入。
- 管理员、审批人和工作负载身份不得混用；Break-glass 使用独立策略、短有效期和强审计。
- `PrincipalContext` 只保存凭证引用和可信属性，不保存可被模型读取的原始 access token。
- 同一客户端幂等键若出现不同 tenant、principal、operation 或输入指纹，返回 `conflict`，不得覆盖已有记录。

## 8. 故障与降级

| 故障 | 默认处理 | 允许降级 | 禁止行为 |
| --- | --- | --- | --- |
| IdP/JWKS 不可用 | 未验证新身份请求失败或延后 | 仅使用仍在有效期且策略允许的安全缓存 | 接受未验签令牌 |
| 租户目录不可用 | 失败关闭 | 无 | 从请求正文猜租户 |
| 输入 Schema 服务不可用 | 使用 Release 中冻结且已缓存的 Schema；无缓存则失败 | 只允许完全匹配的本地只读快照 | 跳过校验 |
| 策略服务不可用 | R2/R3 失败关闭；R0/R1 按预定义策略处理 | 仅预先批准的低风险只读路径 | 让模型决定是否放行 |
| 配额存储不可用 | 停止新高成本/写任务 | 可配置的极小低风险应急额度 | 无限放行 |
| Release 无兼容交集 | `version_incompatible` | 无 | 静默选择未评测版本 |
| Runtime 队列饱和 | `throttle` 或 `defer`，返回 retry-after/任务引用 | 异步接收需持久化成功后才确认 | 接收后丢弃 |
| 审计出口不可用 | R3 停止；其他风险按本地最小审计策略 | 加密本地缓冲 | 无审计继续敏感操作 |
| 客户端断开 | 停止流式传输并传播取消意图 | 已持久化异步任务可继续 | 把断开等同业务取消完成 |
| 重复请求 | 相同指纹返回既有接收/结果引用 | 无副作用的校验可重算 | 创建第二个根任务 |

## 9. 观测指标

### 9.1 指标

- `ingress_requests_total{operation,channel,outcome}`：按稳定低基数维度统计请求。
- `ingress_request_duration_seconds`：端到端准入 P50/P95/P99。
- `run_admission_results_total{outcome,reason_code,risk_class}`。
- `authentication_failures_total{reason}` 和认证缓存使用率。
- `tenant_binding_failures_total`，目标为零容忍告警。
- `contract_validation_failures_total{schema,error_class}`。
- `rate_limited_total{tenant_tier,operation}` 和并发饱和度。
- `admission_queue_wait_seconds`、`deferred_requests`、`expired_before_runtime_total`。
- `idempotency_replay_total`、`idempotency_conflict_total`。
- `release_resolution_failures_total`、版本兼容命中率。
- `admission_audit_publish_failures_total`。

指标标签禁止包含 `request_id`、用户输入、邮箱、原始路径、token 或高基数主体 ID。

### 9.2 Trace 与 Audit

Trace 至少包含协议解析、身份验证、租户绑定、Schema 校验、风险分类、预算、Release 解析、策略和队列提交 span。高风险 allow/deny、委托、Break-glass 和租户绑定产生 AuditEvent。Trace 可采样，安全拒绝和高风险准入审计不可因普通采样丢失。

## 10. 可替换端口

| 端口 | 稳定语义 | 可替换实现 |
| --- | --- | --- |
| `TransportPort` | 请求、流、断开、deadline 和响应映射 | HTTP、gRPC、消息队列、事件总线 |
| `IdentityVerificationPort` | 验签、issuer/audience、认证强度 | OIDC、SAML gateway、mTLS、云 IAM |
| `TenantDirectoryPort` | 主体到租户/组织/区域的可信映射 | 企业目录、IAM、主数据服务 |
| `ContractRegistryPort` | Schema 获取、版本兼容和完整性 | Git/OCI registry、Schema Registry、数据库 |
| `TaskLinkPort` | 创建或按版本关联任务 | 本地服务、领域任务系统 |
| `RiskPolicyPort` | 风险分类与 obligations | 规则引擎、集中策略服务 |
| `QuotaPort` | 租户额度、并发预留和结算 | Redis、数据库、云限流服务 |
| `ReleaseResolutionPort` | 兼容版本集合和回滚目标 | 自建控制面、制品平台 |
| `RuntimeSubmissionPort` | 向 02 提交边缘 accepted 候选，并对已创建 run_id 回送 `RunAdmissionResult` | 进程内调用、队列、工作流信号 |
| `AuditPort` | 不可抵赖事件提交 | 审计账本、SIEM、合规事件服务 |

端口适配器不得删除租户、主体、分类、purpose、deadline、版本、完整性和关联标识。

## 11. 配置项

| 配置键 | 含义 | 安全约束 |
| --- | --- | --- |
| `ingress.allowed_protocols` / `allowed_media_types` | 允许的协议与内容类型 | 默认拒绝未知类型 |
| `ingress.max_body_bytes` / `max_attachment_count` | 输入与附件上限 | 必须有硬上限 |
| `ingress.max_decompression_ratio` | 压缩炸弹保护 | 不可由租户普通开关关闭 |
| `auth.trusted_issuers` / `audiences` / `algorithms` | 身份验证信任根 | 禁止算法降级和通配 audience |
| `auth.clock_skew_seconds` / `jwks_cache_ttl` | 时钟与密钥缓存 | 缓存过期后不得无限接受 |
| `tenant.binding_policy_version` | 租户映射策略 | 运行可追溯 |
| `contracts.accepted_versions` | 输入/输出兼容范围 | 与 Release 一起冻结 |
| `admission.rate_limits` / `concurrency_limits` | 分租户、operation、风险限额 | 高风险限额不能无限 |
| `admission.risk_policy_version` | 风险分类策略 | 改动需评测和审计 |
| `budget.profiles` | 时间、Token、成本、工具和编排预算 | 子预算不得超过根预算 |
| `release.allowed_channels` | 各环境可用 Release | 生产只允许门禁通过版本 |
| `delivery.async_threshold_ms` | 同步转异步阈值 | 只有持久化成功才返回 accepted |
| `errors.public_catalog_version` | 公共错误码版本 | message 可变，code 语义稳定 |
| `audit.fail_closed_risk_level` | 审计故障失败关闭阈值 | R3 默认关闭 |

配置在请求准入时形成不可变快照；普通热更新只影响后续请求。紧急撤销通过独立安全下限使进行中 Run 暂停或重新授权，不以静默换版本实现。

## 12. 验收标准

- 所有支持的协议都只能产出同一版本语义的边缘 accepted 候选；Runtime 启动只认绑定既有 run_id 的 `RunAdmissionResult`。
- 请求正文中的 `tenant_id`、`principal_id`、role 或 region 不能覆盖可信身份映射。
- 非法类型、超限输入、错误 Schema 和无效附件在任何模型、检索或工具调用前被拒绝。
- 同一接入幂等键和同一输入指纹只创建一个根任务；同键异指纹稳定返回冲突。
- `PrincipalContext` 能重建用户、调用服务、委托链、认证强度、区域和有效期，不包含原始凭证。
- `TaskEnvelope` 有可判定完成条件，`BudgetEnvelope` 有绝对 deadline 和收束保留预算。
- 没有有效 `ReleaseManifest`、其 `ReleaseDecision` 不是已批准状态、无兼容版本集合或已撤销的 Agent 不能进入 Runtime。
- 策略、身份或租户绑定不可用时，高风险请求失败关闭。
- 调用方收到的错误不含堆栈、令牌、内部主机、策略正文和资源存在性泄漏。
- Trace 可关联 `request_id`、`task_id`、`trace_id` 和 `release_id`；高风险准入有独立 AuditEvent。
- 客户端断开、重试、队列饱和和 Runtime 提交超时均有确定终态且不会制造重复根任务。
- 下游 02 只消费 canonical 契约，不依赖 HTTP/JWT/云网关或底层 Agent SDK 对象。
