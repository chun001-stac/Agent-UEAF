# 01｜接入与准入

Architecture Generation: `V1`  
Implementation: `Current`

## 1. 定位

接入与准入是 UEAF 的唯一外部请求入口，并承载两个必须分离的阶段：

```text
Edge Pre-validation
  认证 / 租户绑定 / 协议与基础 Schema / 重放与速率 / 最低安全
  -> accepted | rejected

accepted
  -> RequestEnvelope + TaskEnvelope
  -> 02 创建 TaskState + RunRecord(queued)
  -> queued -> admitting
  -> Run Admission
       admitted | deferred | rejected
```

边缘 accepted 不表示 Agent 已获准执行；只有绑定同一 `run_id`、未过期且 `outcome=admitted` 的 `RunAdmissionResult` 才允许 02 进入 `running`。

本模块不调用模型、不构建 RAG、不执行工具、不写 `ActionRecord`、不推进 Workflow，也不拥有根 Run 状态。

## 2. Canonical 契约来源

本模块所有跨模块持久化对象继承核心 `ContractMeta`。Canonical Name 和字段以核心规范为唯一来源，模块只增加本域解释，不重定义同名对象。

特别是：

- `PrincipalContext` 使用核心规范的字段，不创建安全模块/接入模块私有变体；
- 跨进程错误使用 `ProblemDetail`；
- 不再使用 `ErrorEnvelope` 作为公共对象；
- Event 使用核心 `EventEnvelope`；
- 风险分类不得与 Evolution `RepairLevel=R0..R5` 复用同一符号。

## 3. 职责

- 终止 HTTP/RPC/WebSocket/Queue 等外部协议；
- 验证凭据、issuer/audience/时效、nonce、认证强度；
- 由可信目录绑定 `tenant_id`、主体、委托链、数据区域和用途；
- 对报文执行大小、媒体类型、编码、基础 Schema、附件、速率和重放检查；
- 生成不可变 `RequestEnvelope`；
- 生成或关联不可变 `TaskEnvelope`；
- 分配/引用 `BudgetEnvelope`；
- 解析目标 `AgentDefinition`、已批准 `ReleaseManifest` 和兼容范围；
- 在已有 `RunRecord(admitting)` 上形成 `RunAdmissionResult`；
- 返回同步/流式/异步的稳定接入语义；
- 发布 Trace/Metric/Audit，敏感 Payload 只保留受控引用。

## 4. 非职责

- 不从请求正文相信 tenant、role、scope、principal 或 credential；
- 不把认证成功等同于具体 Tool/资源授权；
- 不把边缘幂等键当作业务 `action_key`；
- 不在运行中切换 Release/Prompt/Model/Tool；
- 不把 SDK Session/Thread/Run 提升为 UEAF canonical 对象；
- 不签发 `PolicyDecision`、`ReleaseDecision` 或生产 `ReleaseManifest`。

## 5. 关键组件

| 组件 | 职责 | 输出 |
|---|---|---|
| Protocol Front Door | 协议终止、大小/速率/连接限制 | 非 canonical `TransportContext` |
| Credential Verifier | 可信凭据校验 | Verified claims / refs |
| Principal Mapper | 绑定租户、主体、委托、区域、用途 | canonical `PrincipalContext` |
| Request Normalizer | 规范化输入与指纹 | `RequestEnvelope` |
| Contract Validator | Schema/版本/字段边界 | Validation evidence |
| Task Builder | 固化目标、完成条件、风险、预算引用 | `TaskEnvelope` |
| Budget Allocator | 分配多维预算 | `BudgetEnvelope` |
| Release Resolver | 解析已批准版本集合 | release binding refs |
| Admission Controller | 对已有 Run 执行正式准入 | `RunAdmissionResult` |
| Error Mapper | 将内部失败映射为脱敏错误 | `ProblemDetail` |

## 6. `PrincipalContext`

本模块只能构造核心规范定义的 `PrincipalContext`：

```text
meta
principal_id
principal_type
roles
scopes
delegation_chain
authentication_strength
credential_ref
data_regions
consent_refs
issued_at
expires_at
revocation_ref
```

`tenant_id` 以 `meta.tenant_id` 为权威，任何便捷镜像字段都必须与其一致。

额外认证观察（如 IdP 名称、认证方法、原始 assurance claim、workload identity ref）不得重新定义 `PrincipalContext` 顶层 Canonical 字段；需要跨模块传播时放入已批准的 namespaced `meta.extensions` 或独立受控引用。

规则：

1. 只有 Trusted Admission Boundary MAY 构造；
2. 模型、Prompt、Tool 参数和下游 Agent 不得修改；
3. 委托 scopes 只能保持或收窄；
4. 高风险动作前由 07/PEP 重新验证有效期、撤销与资源属性。

## 7. `RequestEnvelope`

最小字段按核心对象规范，包括：

```text
meta
request_id
channel
protocol
input_ref or bounded input
client_correlation_id
received_at
deadline_at
principal_context_ref
validation_status
```

本模块 MAY 增加兼容的领域字段，如：

```text
operation
input_schema_ref
attachment_refs
input_fingerprint
delivery
validation summary
```

但不得覆盖核心字段语义。

`RequestEnvelope` 通过边缘预校验后不可原地改写；修订必须形成新请求或显式 Task revision。

## 8. `TaskEnvelope`

核心字段：

```text
meta
task_id
request_refs
goal
completion_criteria
constraints
risk_class
owner_ref
budget_ref
revision
```

### 8.1 任务风险分类

为避免与 Evolution Repair Ladder 的 `R0..R5` 混淆，V1 新实现的 `TaskEnvelope.risk_class` MUST 使用语义枚举：

```text
compute_only
read_only
reversible_write
high_risk_write
```

旧文档/实现若使用 `R0/R1/R2/R3` 表示上述任务风险，视为 deprecated alias，仅允许迁移读取，不得作为新 Schema enum、日志 label 或公共 API 输出。

映射仅用于迁移：

```text
R0 -> compute_only
R1 -> read_only
R2 -> reversible_write
R3 -> high_risk_write
```

Evolution 的 `RepairLevel=R0..R5` 保持不变，二者是不同类型。

## 9. `BudgetEnvelope`

必须显式覆盖或引用以下预算维度：

```text
absolute deadline
runtime steps
model calls / input tokens / output tokens
amount + currency
tool calls / write actions
workflow nodes / depth / parallelism
risk action budget
reserved finalize budget
```

缺字段不能隐式表示无限；使用组织默认或 `unbounded_by_contract` 必须显式。

## 10. Edge Pre-validation

推荐顺序：

```text
transport limits
-> credential verification
-> tenant/principal mapping
-> replay / idempotency checks
-> base schema/media validation
-> data classification / purpose / region precheck
-> release/request compatibility precheck
-> accepted | rejected
```

### 10.1 rejected

边缘 rejected：

- 不创建 `RunRecord`；
- 返回 `ProblemDetail`；
- 产生 `ueaf.request.rejected` 与必要 Audit；
- 不创建伪 `RunAdmissionResult`。

### 10.2 accepted

accepted：

- 固化 `PrincipalContext`、`RequestEnvelope`、`TaskEnvelope`；
- 交给 02 原子创建/关联 `TaskState` 与 `RunRecord(queued)`；
- 返回 task/run ref，不宣告 admitted。

## 11. Run Admission

只有在 02 已提交：

```text
RunRecord: queued -> admitting
```

后，本模块才对确定 `run_id` 评估：

```text
TaskEnvelope
PrincipalContext current validity
ReleaseManifest signature / lifecycle / environment / compatibility
entry PolicyDecision refs when required
Budget / quota / capacity / region
Runtime Adapter capability
risk / dependency health
```

输出核心 `RunAdmissionResult`：

```yaml
run_admission_result_id: string
run_id: string
outcome: admitted | rejected | deferred
validation_refs: [string]
policy_decision_refs: [string]
budget_snapshot_ref: string
release_manifest_ref: string
reason_codes: [string]
retry_after: timestamp | null
created_at: timestamp
expires_at: timestamp
```

结果：

```text
admitted -> 02 CAS admitting -> running
deferred -> 02 admitting -> waiting + durable condition
rejected -> 02 terminal/rejected
```

`RunAdmissionResult` 不替代 `PolicyDecision`，也不替代 Release Gate。

## 12. Idempotency

必须分离：

```text
request idempotency key
command idempotency key
event_id
action_key
```

同一请求幂等键 + 同一规范化指纹返回已有 task/run；同键不同指纹返回 conflict，不覆盖原对象。

## 13. 错误契约

外部/API 错误统一 `ProblemDetail`：

```text
code
category
message_safe
retryability
source
object_ref
field_paths
correlation_refs
cause_ref
observed_at
details_ref
```

具体 Port 失败仍使用核心 `PortResult<T>/PortError`，由 API 层映射；不得丢失 `Unknown` / `after_reconciliation` 语义。

## 14. Telemetry / Audit

接入模块：

- Trace/Metric/Log 使用核心 `TelemetryPort`；
- 身份、策略、安全拒绝等必要事实进入 `EmitAudit`/Audit owner；
- 原始 credential、secret、完整敏感 payload 不进入普通 Log/Metric；
- `request_id/user_id/raw query` 等高基数字段不作为常规 Metric label。

## 15. 验收条件

1. 未验证 tenant/principal 无法进入 canonical `PrincipalContext`；
2. 请求正文无法覆盖身份、scope、credential、region；
3. edge rejected 不创建 Run；
4. edge accepted 只创建 queued Run，不等同 admitted；
5. queued 无法直接进入 running；
6. `RunAdmissionResult` 必须绑定已存在 run_id 且校验 expires_at；
7. `deferred` 进入 durable waiting，不被当作失败重试；
8. 所有新错误输出使用 `ProblemDetail`，无公共 `ErrorEnvelope`；
9. 新任务风险 enum 不使用 `R0..R3`，避免与 RepairLevel 混淆；
10. 所有跨模块持久对象继承 `ContractMeta`；
11. 外部重放、过期 admission、tenant mismatch 和同键异 payload 均有自动测试。
