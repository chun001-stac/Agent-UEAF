# 07｜身份、权限与安全治理

Architecture Generation: `V1`  
Implementation: `Current`

## 1. 模块定位

本模块提供统一身份治理、在线授权、人工审批、最小权限凭据、安全执行边界和安全发布证据。

它回答：

> 哪个主体，在什么委托、用途、环境和风险条件下，能否对哪个资源执行什么动作？

本模块不执行企业工具，不拥有 `ActionRecord`，不签发质量/运行门禁，也不决定最终 `ReleaseDecision`。

## 2. Canonical 契约收敛

### 2.1 `PrincipalContext`

`PrincipalContext` 只有一套 Canonical Schema，字段以核心对象规范为准：

```text
meta
principal_id
principal_type
tenant_id
roles
scopes
delegation_chain
authentication_strength
credential_ref
data_regions
consent_refs
issued_at
expires_at
revocation_ref
```

顶层 `tenant_id` 是 MUST 字段，并且 MUST 与 `meta.tenant_id` 相同；二者共同表达同一可信租户绑定，顶层字段不是可选镜像。

本模块不得重新定义另一套 `PrincipalContext` 顶层字段，例如：

```text
subject_id
identity_provider
assurance_level
residency_scope
workload_identity_ref
```

这些若需要跨模块传播，应：

1. 映射到已有 Canonical 字段；或
2. 放入批准的 namespaced `meta.extensions`；或
3. 作为独立受控 identity evidence/workload identity ref 被引用。

不得用同名 Canonical Object 承载两套字段。

### 2.2 其他公共契约

- 在线授权结论：`PolicyDecision`；
- 人工审批：`ApprovalRequest`；
- 安全发布结论：`SecurityGateDecision`；
- 跨进程错误：`ProblemDetail`；
- Port 错误：`PortError`；
- 安全/Audit 事件遵守核心 `EventEnvelope` / Audit 语义。

## 3. 权威边界

- IdP 是原始认证事实来源；UEAF 验证并映射为 `PrincipalContext`；
- PDP 是在线授权结论的唯一 Semantic Owner；
- Approval Service 是人工审批事实的唯一 Semantic Owner；
- Credential Broker 是短时下游凭据的唯一签发入口；
- 模块 05 是 `ActionRecord/action_key/fencing/ActionReceipt` 的唯一动作域；
- 业务系统仍拥有业务事实；
- Security Evidence Service 只签发 `SecurityGateDecision`，不签发最终 Release。

## 4. 职责

1. 验证用户、服务、Agent workload 和审批者身份；
2. 构建/验证受限委托链，scope 只能保持或收窄；
3. 规范化主体、动作、资源、环境、用途和风险为 Policy 输入；
4. 在入口、RAG/Memory、Model、Tool、Handoff、管理和发布边界实施 PEP；
5. 对高风险动作编排审批；
6. 签发最小范围、短期、限定受众的 credential handle；
7. 对代码、文件、网络、MCP、远程 Agent 实施 Sandbox/DLP/结果最小化；
8. 生成不可被普通采样丢弃的 Audit/Security evidence；
9. 为候选版本形成独立 `SecurityGateDecision`。

## 5. 非职责

- 不把模型 Guardrail 当最终授权者；
- 不根据 capability discovery 推断执行权限；
- 不计算 `action_key`、不执行 Tool、不推进 `ActionRecord`；
- 不让审批替代 PDP；
- 不让 SecurityGate 替代运行时 `PolicyDecision`；
- 不把 Trace 当合规 Audit；
- 不让 Evolution 通过“修复”扩大 Governance 权限。

## 6. 身份与委托

核心不变量：

1. 用户主体、服务主体、Agent identity、workload identity、审批者身份保持逻辑分离；
2. `PrincipalContext` 表达当前调用可消费的规范身份快照，不保存长期 token；
3. delegation 每一跳必须有来源、scope、purpose、有效期；
4. 恢复、重试、Handoff、灾备切换时重验有效期与撤销；
5. Runtime/SDK 的 Session/Thread/Run ID 不是授权主体；
6. Prompt、模型、工具参数不能覆盖 tenant、roles、scopes、credential 或 delegation。

## 7. 逻辑组件

| 组件 | 主要职责 | 输出 |
|---|---|---|
| Identity Adapter | IdP token/cert 验证 | verified claims/evidence refs |
| Principal Mapper | claims -> canonical identity | `PrincipalContext` |
| Resource Resolver | 解析规范资源与关系快照 | resource refs |
| Capability Catalog | 能力风险/数据/授权属性 | capability policy metadata |
| Policy Administration | 管理签名 Policy bundle | policy refs |
| PDP | 对规范化授权输入求值 | `PolicyDecision` |
| PEP | 强制执行 PolicyDecision constraints | allow/deny/approval routing |
| Approval Service | 审批资格、动作摘要、时效 | `ApprovalRequest` state/evidence |
| Credential Broker | 短期最小权限 credential | opaque credential handle |
| Execution Sandbox | 代码/文件/网络/资源隔离 | sandbox evidence |
| DLP / Result Minimizer | 数据出站最小化 | safe result/evidence |
| Security Evidence Service | 安全测试/漏洞/威胁模型 | `SecurityGateDecision` |
| Audit Sink | 追加不可变安全事实 | Audit record/event |

## 8. `AuthorizationRequest`

它是 Policy 输入，不是新的授权决定。至少包括：

```yaml
authorization_request_id: string
tenant_id: string
principal_context_ref: string
workload_identity_ref: string | null
delegation_context_ref: string | null
action: string
resource: object
environment: object
purpose: string
risk_level: string
input_digest: string
policy_bundle_version: string
requested_at: timestamp
```

`risk_level` 属于安全/动作策略域，必须使用该 Policy Profile 的显式 enum，不得借用 Evolution `RepairLevel` 的概念标签 `R0..R5` 或 wire 值 `r0..r5`。

## 9. `PolicyDecision`

```yaml
policy_decision_id: string
authorization_request_id: string
tenant_id: string
principal_context_ref: string
action: string
resource: object
environment: object
outcome: allow | deny | require_approval
constraints: object
reason_codes: [string]
policy_versions: [string]
input_hash: string
evaluated_at: timestamp
expires_at: timestamp
```

PEP 应用前必须验证：

```text
issuer / signer
tenant
principal/action/resource/environment
input_hash
policy version
expires_at / revocation
constraints
```

缓存不得超过 Decision 有效期和撤销传播 SLO。

## 10. Tool 授权主链

```text
ToolIntent
  -> 05 server-side bind/canonicalize
  -> action_fingerprint + action_key
  -> ActionRecord(proposed)
  -> validate resource/schema/budget
  -> AuthorizationRequest
  -> PDP -> PolicyDecision
       deny -> 05 terminal/denied
       require_approval -> ApprovalRequest -> re-evaluate
       allow -> 05 reserve action_key
  -> Credential Broker
  -> Tool Adapter execution
  -> ActionReceipt
  -> reconciliation when unknown
```

关键规则：

- 07 不计算/修改 `action_key`；
- 审批必须绑定不可变 action fingerprint；
- 审批后参数、主体、资源、能力版本、用途变化必须重新授权/审批；
- Tool timeout 不意味着动作未发生。

## 11. `ApprovalRequest`

至少包含：

```text
approval_request_id
action_fingerprint
tool_intent_ref
principal_context_ref
policy_decision_ref
impact preview
risk reasons
approver policy
status
human decision
created_at / expires_at
revision
separation-of-duty rules
```

状态：

```text
pending | approved | rejected | expired | cancelled
```

只有当前版本 `approved` 且动作指纹仍匹配，才可进入重新 PDP 求值；审批从不证明动作成功。

## 12. Credential Broker

凭据必须：

- 短期；
- audience-bound；
- scope 最小化；
- 与 workload/action/resource/tenant 绑定；
- 只以 opaque handle 传给受控 Adapter；
- 不进入 Prompt、Tool arguments、Trace、Log、Checkpoint、Mutation/Evolution Working Set。

## 13. Security Gate

`SecurityGateDecision` 与 `PolicyDecision` 正交。

它回答“某 Candidate 在指定安全范围内是否可接受”，不能授权单次生产 Tool Action。

至少检查：

```text
identity / tenant isolation
permission & tool gateway enforcement
prompt injection / data exfiltration
secret leakage
sandbox & network egress
artifact/SBOM/provenance
R4 generated code
holdout/eval isolation
known vulnerability / exception expiry
```

任何 hard security failure 不能被质量、成本或业务收益加权抵消。

## 14. Evolution 安全边界

Governance Kernel 包括：

```text
Identity / Delegation root
PDP / PEP
Tool Gateway enforcement
Secret/Credential management
Audit root
Eval root / holdout / threshold root
Release Authority
Budget Enforcement
kill switch / legal hold / deletion root
```

V1 自动 Evolution：

- MAY observe 授权后的安全 evidence refs；
- MAY 诊断错误 Tool/Router/Prompt 导致的权限失败；
- MUST NOT 自动增加 scope/role/credential/ACL；
- MUST NOT 修改 PDP/PEP 或安全 hard gate；
- R5 一律路由独立治理。

## 15. 安全事件与 Telemetry

- 普通 Trace/Metric/Log 使用核心 `TelemetryPort`；
- 安全关键事实进入 Audit/Security evidence，不受普通采样削减；
- `user_id/request_id/trace_id/raw prompt` 不作为普通 Metrics label；
- 敏感 Payload 使用受控 ref；
- Evidence Expansion 读取的文本始终按不可信数据处理。

## 16. 故障语义

| 场景 | 默认行为 |
|---|---|
| identity/tenant 无法确认 | fail closed |
| Policy unavailable + high risk | fail closed |
| Policy expired/revoked | re-evaluate / deny |
| approval stale | invalidate and recreate |
| credential broker unavailable | do not execute side effect |
| sandbox/DLP hard failure | block candidate/action |
| security evidence missing for release | SecurityGate fail/inconclusive according to policy; never auto-pass |
| permission denied during Evolution | R5 or repair wrong routing; never self-elevate |

## 17. 验收条件

1. `PrincipalContext` 字段与核心对象模型完全一致；
2. 模块 07 不建立 `subject_id/identity_provider/...` 版第二 PrincipalContext；
3. 请求/模型/工具无法覆盖 tenant/roles/scopes/delegation；
4. `PolicyDecision` 与 Security/Quality/Operational/Release 决定不可互换；
5. 审批绑定 action fingerprint，变化后旧审批失效；
6. 07 不执行 Tool、不写 ActionRecord、不生成 action_key；
7. credentials 不进入模型/日志/事件正文；
8. Judge/Proposer/Builder 无生产 Tool 写权限；
9. R5 Governance 无法通过 Evolution 自动扩权；
10. Security hard failure 无法被其他评分抵消；
11. 多租户、委托收窄、撤销、过期、审批重验都有自动化测试。
