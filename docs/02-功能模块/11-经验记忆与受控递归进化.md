# 11｜经验记忆与受控递归进化

## 1. 模块定位

本模块负责把 UEAF 生产运行、评测、成本、工具、工作流和业务反馈中的结构化证据转化为**有限、可审计、可停止、可发布**的改进候选。它不是另一个 Agent Runtime，也不是默认常驻的“自我反思 Agent”。

模块目标是：

```text
Experience
  -> Pattern
  -> Hypothesis
  -> Mutation
  -> Candidate
  -> Evaluation
  -> Selection
  -> Release Governance
  -> Production Feedback
```

本模块强调 **Controlled Recursive Self-Improvement**：当前运行版本不可原地自改，所有改动形成新候选；候选不能控制自己的 Judge、门禁和发布权限；所有 EvolutionRun 都受预算、停止条件和不可变 Governance Kernel 约束。

## 2. 与现有模块的边界

| 相关模块 | 本模块如何协作 | 本模块不取得的语义 |
|---|---|---|
| 04 上下文/RAG/记忆 | MAY 引用经治理 Memory、Knowledge、Context 质量事实 | 不拥有业务 `MemoryRecord`，不把 EvolutionExperience 默认注入业务上下文 |
| 06 工作流/多 Agent | 可提出 Workflow/Topology Candidate | 不直接修改正在运行的 WorkflowRun/NodeRun |
| 07 身份/权限/安全 | 受 PDP、Secret、数据边界和 Security Gate 约束 | 不签发权限，不修改 Governance Kernel |
| 08 评测/发布治理 | 提交 Candidate 和 EvaluationSuiteRef，消费 Eval/Quality 证据 | 不拥有 `EvalResult`、`QualityGateDecision`、`ReleaseDecision`、`ReleaseManifest` |
| 09 生产运行/可观测 | 消费 Metric/Trace/成本/SLO/灰度反馈引用 | 不把普通遥测当权威演化结论 |
| 10 开发者平台/适配 | 使用 Bundle Builder、Sandbox、Adapter Test Kit 构建候选 | 不绕过 Developer/Release 流程直接修改生产 |

## 3. 逻辑组件

| 组件 | 职责 | 关键约束 |
|---|---|---|
| Evidence Aggregator | 汇总运行、评测、成本、反馈引用 | 只保存最小结构化事实和引用，不复制全部 Prompt/Trace |
| Pattern Miner | 去重、聚类、频率与显著性分析 | 优先规则/统计/embedding，不默认调用强模型 |
| Evolution Trigger Engine | 判断是否值得启动 EvolutionRun | 无 Trigger 时不进行持续 LLM 反思 |
| Experience Store | 保存 EvolutionExperience / Lesson / 搜索历史 | 与模块 04 Memory Store 分离语义 |
| Genome Registry | 管理不可变 AgentGenome 和 Lineage | 改 Gene 必须生成新 Genome |
| Evolution Strategy Engine | 选择 LLM-guided、GA、BO、RL 等策略 | 算法可替换；不能绕过评测 |
| Mutation Proposer | 基于 Trigger + Lesson 生成有限 Proposal | 默认 sparse mutation |
| Candidate Builder | 构建 ReleaseCandidate/AgentGenome 工件 | 运行在受限沙箱；无生产写权限 |
| Evolution Budget Controller | 管理 Token、费用、调用数、代数和时间预算 | 预算不可由 Candidate 自主提升 |
| Candidate Selector | 比较 Fitness 与基线 | 不用单一总分覆盖安全硬失败 |
| Lineage Service | 保存成功、失败、分支、归档和父子关系 | 失败实验也要可追溯，避免重复搜索 |
| Consolidation Engine | 将重复经验压缩为 Lesson/Skill/Policy/Tool | Active Working Set 有界 |

## 4. 为什么不采用“每次任务都反思”

错误模式：

```text
Every Task
  -> LLM summary
  -> LLM reflection
  -> LLM lesson extraction
  -> LLM candidate generation
  -> LLM judge
```

这会让 Token 成本随任务量近似线性增长，而且产生大量重复、低价值“经验”。

UEAF 推荐：

```text
100000 tasks
  -> structured telemetry/eval facts
  -> dedup / statistics / clustering
  -> 100 relevant patterns
  -> 20 meaningful anomalies
  -> 5 evolution cases
  -> limited candidate generation
```

因此稳定系统的演化成本应接近零，只有出现有效触发器才进入昂贵推理。

## 5. Experience Pipeline

### 5.1 Raw Evidence

Raw Evidence 仍属于其原始域，例如：

- `EvalResult`；
- Metric / Trace / Log 引用；
- `ActionReceipt`；
- SLO / cost ledger；
- Quality/Security/Operational Gate 结果；
- 明确业务反馈或人工复核。

本模块只保存 `source_refs`、统计量、窗口、分类和完整性信息。

### 5.2 Episode / Pattern

同类事件先经过：

```text
Exact dedup
  -> Semantic dedup
  -> Clustering
  -> Frequency / confidence
  -> significance / novelty
```

只有满足阈值的 Pattern 才升级为 `EvolutionExperience`。

### 5.3 Lesson Consolidation

多个 Experience 归纳成 Lesson：

```text
837 timeout events
  -> one validated pattern
  -> one EvolutionLesson
```

Lesson 必须包含支持与反例、作用范围、置信度和失效条件，禁止只保存自然语言“总结”。

### 5.4 Compile to Capability

成熟 Lesson SHOULD 尽量从文本记忆转化为低 Token 能力：

```text
Text Lesson
  -> Policy
  -> Router
  -> Workflow
  -> Tool
  -> Skill
```

一旦知识被稳定能力吸收，旧 Lesson 可从 Active Working Set 退出。目标是经验增加的同时，Prompt/Context 不随历史线性增长。

## 6. Active Working Set

Active Evolution Working Set 仅加载：

- 当前 `EvolutionTrigger` 相关的 Experience/Lesson；
- 当前 mutable gene scope；
- 当前 baseline Genome；
- 少量相似成功/失败实验；
- 必要 Governance/Eval 约束引用。

必须设置：

- 最大条目数；
- 最大 Token；
- 最大时间窗或相关性阈值；
- 去重和 superseded 排除；
- Archive/Cold Store 策略。

因此 Experience Store 总量可以增长，但单次 EvolutionRun 的上下文必须保持有界。

## 7. Evolution Trigger

推荐触发源：

1. 失败率/质量指标越过阈值；
2. 新的高频 Failure Cluster；
3. Token/费用/延迟显著恶化；
4. 新 Foundation Model 或 Provider Capability 可用；
5. 新 Tool/Adapter 可用；
6. 人工提出新业务目标；
7. 安全/质量回归；
8. 达到足够新证据数量；
9. 显式周期复核。

单个失败、普通低置信评论或无显著变化的日常任务不应默认触发演化。

## 8. Candidate Generation

### 8.1 Sparse Mutation

默认只修改被证据指向的少量 Gene，例如：

```text
Retrieval failure
  -> memory/context policy gene mutable
  -> prompt/model/tool/workflow genes frozen
```

这样将巨大搜索空间缩小为局部优化问题。

### 8.2 可变 Gene

典型 Gene 包括：

- Model Route；
- Prompt Bundle；
- Context Policy；
- Memory Policy；
- Tool Set；
- Workflow / Agent Topology；
- Routing Policy；
- Skill Bundle；
- Retry/Planning Strategy；
- Evolution Strategy 本身（仅更高层受控 Run）。

Identity、Permission、Audit、Release Authority、Evaluator Root、Budget Enforcement 等不属于默认 mutable genes。

## 9. Evolution Strategy Registry

本模块不把“自我进化”绑定为遗传算法。策略接口至少允许：

- `llm_guided_sparse_mutation`；
- `genetic_search`；
- `evolutionary_population_search`；
- `bayesian_optimization`；
- `reinforcement_learning`；
- `self_reflection`；
- `workflow_topology_search`；
- `tool_creation_search`；
- `human_guided`。

遗传算法适合有明确 Genome 编码、可自动评价、候选成本可控的搜索空间；LLM-guided mutation 适合需要理解失败原因和结构语义的场景。两者可组合，但不是互相替代的规范概念。

## 10. Evaluator 选择

### 10.1 默认优先级

```text
Deterministic
  -> Statistical
  -> Cheap/Small Model
  -> Strong Model
  -> Human
```

### 10.2 示例

Coding Agent：

- tests；
- lint/type check；
- benchmark；
- security scan；
- regression suite。

Quant Agent：

- OOS；
- leakage check；
- Sharpe / drawdown / turnover；
- stability；
- statistical significance。

Customer Service Agent：

- resolution rate；
- reopen rate；
- SLA；
- escalation；
- CSAT；
- cost per resolution。

模型 Judge 只处理开放语义、难以确定性评分的维度，并继续遵守模块 08 的身份隔离和校准要求。

## 11. Fitness 与 Evolution ROI

禁止以单一 `accuracy` 作为晋升条件。Fitness 至少观察：

- Capability/quality gain；
- Safety；
- Robustness；
- Input/Output Token；
- Dollar/compute cost；
- P50/P95 latency；
- Runtime complexity；
- Tool/Agent fan-out；
- Regression risk。

示例：

```text
Candidate A
accuracy +2%
token +80%
latency +45%
=> MAY reject

Candidate B
accuracy +1.5%
token -35%
latency -20%
=> MAY promote
```

实现 SHOULD 提供：

```text
EvolutionROI = delta business utility / delta total operating cost
```

以及可选的 Intelligence Efficiency 指标，但不得用加权平均掩盖安全硬失败。

## 12. EvolutionBudget

每个 EvolutionRun 必须绑定预算，例如：

```yaml
max_model_calls: 100
max_input_tokens: 2000000
max_output_tokens: 500000
max_amount_usd: 20
max_candidates: 5
max_generations: 3
max_strong_model_calls: 10
max_wall_time_ms: 7200000
```

预算可以由租户/环境/风险 Profile 调整，但 Candidate 与 Evolution Strategy 无权自行扩大。

## 13. EvolutionRun 主流程

```text
Trigger
  -> queued
  -> collecting
  -> analyzing
  -> generating
  -> evaluating
  -> selecting
  -> terminal
```

可在 `waiting` 等待人工、外部评测或配额。

主流程：

1. Trigger Engine 固化证据窗口与阈值版本。
2. Aggregator 只获取必要证据引用。
3. Pattern Miner 去重、聚类和显著性筛选。
4. Experience/Lesson 检索过滤掉已知无效重复方向。
5. Strategy Engine 选择局部搜索策略。
6. Mutation Proposer 产生有限数量 Proposal。
7. Candidate Builder 在沙箱生成 CandidateRelease。
8. Module 08 运行 Eval；优先确定性和统计评价。
9. Candidate Selector 形成 FitnessRecord 并比较 baseline。
10. 无有效候选则终止；有候选则提交现有发布治理。
11. 模块 08/07/09 完成质量、安全、生产门禁和灰度。
12. 线上结果回流为新 Evidence，而不是直接改写 Lesson。

## 14. 停止条件

每轮必须有显式停止条件：

- 达到 Fitness target；
- 连续 N 代/候选提升低于阈值；
- Budget exhausted；
- Max generations；
- No valid candidate；
- Regression guard；
- Safety blocked；
- Novelty exhausted；
- Manual stop。

这意味着“工作持续、进化间歇”。生产 Agent 可以长期运行，但 EvolutionRun 不应永不结束。

## 15. Lineage 与物种/分支

UEAF MAY 保留多个分支而非永远只保留一个 Winner。例如：

```text
Root Genome
  -> Coding Species
  -> Finance Species
  -> Sales Species
```

不同业务域可以拥有不同 Fitness Profile。综合最优 Candidate 不必淘汰在某一专门切片上更强的候选；其 Lineage 可进入冷存档或保留为可复用分支。

历史 Candidate 不默认进入生产和模型上下文，但必须能通过 LineageGraph 追溯。

## 16. 受控递归

允许：

```text
L0 Business Agent
  <- optimized by L1 Evolution Agent
L1 Evolution Strategy
  <- MAY be optimized by L2 Meta-Evolution
```

禁止自动跨越：

```text
--------- Governance Kernel ---------
Identity
Permission
Tool Gateway enforcement
Audit root
Evaluator root / holdout answers
Release Authority
Budget enforcement
Secrets
Data deletion / legal hold
Kill switch
-------------------------------------
```

修改 Governance Kernel 需要独立治理变更，不属于同一自动递归链。

## 17. 故障与安全

| 风险 | 响应 |
|---|---|
| Reward hacking | 多维 Eval、独立 hard gate、真实业务事实交叉验证 |
| 修改测试让自己通过 | Candidate 无 Eval 资产写权限，保留集隔离 |
| 无限 Token 消耗 | EvolutionBudget + event-driven trigger + hard stop |
| Memory 无限增长 | consolidation、archive、bounded active set |
| 重复探索 | Lineage + failed experiment memory + novelty check |
| Candidate 自提权 | Governance Kernel 不可变，工具仍走 Tool Gateway |
| Judge 与 Subject 串通 | 服务身份、上下文、权限和证据存储隔离 |
| 能力提升但成本爆炸 | cost/latency/complexity 纳入 Fitness |

## 18. 验收条件

实现本模块至少应证明：

1. 没有 `EvolutionTrigger` 时不会因为“持续学习”对每个生产任务追加 LLM 调用。
2. 生产 Agent 无法修改自身当前 `ReleaseManifest`。
3. Candidate 无法读取保留集答案或修改自身 Eval 结果。
4. EvolutionRun 在预算耗尽、平台期或无有效候选时可确定终止。
5. 一百万条原始经验可通过结构化聚合只产生有限数量 Active Lesson，而不是全部进入上下文。
6. 一个已验证 Lesson 可以被编译为 Tool/Policy/Workflow 后退出 Active Working Set。
7. Fitness 报告能同时展示质量、Token、费用、延迟、复杂度和安全差异。
8. GA、LLM-guided mutation 两种不同策略可以通过相同规范端口生成 Candidate。
9. Candidate 晋升仍必须经过现有模块 08/07/09 的独立门禁。
10. 当前生产 Release 可以完整追溯到 Genome、Mutation、Eval 和 Lineage。
