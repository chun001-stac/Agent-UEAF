# UEAF 部署拓扑与多租户

## 1. 部署目标

UEAF 的物理架构采用“全局控制面 + 区域运行单元 + 租户隔离数据单元”。控制面负责版本、策略、Schema、Adapter、评测和发布；区域运行单元承载低延迟请求、Run 调度、模型/上下文/工具访问；数据单元按租户等级选择共享、独立 Schema、独立数据库或独立集群。

部署设计必须满足：

- 任一请求进入 Runtime Plane 前已确定 tenant_id、region、environment 和 release_id；
- Runtime Adapter 只能访问本次 `RuntimeStartRequest` 授予的端口和引用；应用层 `RuntimeStartCommand` 仅由模块 02 在校验已绑定的 `RunAdmissionResult(outcome=admitted)` 后映射为该 SPI 请求；
- TaskState、RunRecord 与 ActionRecord 的权威写路径分别唯一；
- 高风险副作用与审计故障采用 fail closed；
- 扩容、升级和故障转移不得改变规范对象语义；
- 同一租户的受管数据不因模型、向量库或框架默认配置跨越驻留边界。

## 3. 部署单元

| 单元 | 建议运行形态 | 扩缩容维度 | 有状态性 |
|---|---|---|---|
| Agent Gateway | 无状态 Deployment / App Service | RPS、连接数、流式会话 | 仅短时连接状态 |
| Runtime Ingress / Task-Run State Service | 模块 02 API 与唯一 State Writer | 创建/查询 QPS、状态提交、事务冲突 | 权威状态写入外置事务库；Gateway 不直写 |
| Admission Coordinator | 无状态服务 | 准入 QPS、策略延迟 | 不持久化权威状态 |
| Run Coordinator | Worker 池 | runnable Run、租约数、队列滞后 | 权威状态外置 |
| Runtime Adapter Pool | 按框架/版本隔离 Worker | framework、release、CPU/内存 | 只保留可丢弃本地状态 |
| Context Builder | 独立服务或 Worker | 检索 QPS、token 预算 | ContextManifest 外置 |
| Model Gateway | 无状态代理 + 速率控制 | provider、模型、区域、token/s | 用量账本持久化 |
| Tool Gateway | 强隔离服务 | 风险级、连接器、动作吞吐 | ActionRecord 外置 |
| Reconciler | 独立 Worker | unknown/reconciling 数量 | 基于 Action Store |
| State/Event Store | 托管关系库 + outbox | tenant shard、IOPS、连接 | 权威 |
| Evidence/Object Store | 加密对象存储 | 容量、保留期限 | 权威证据 |
| Search/Vector | 区域化索引 | tenant、语料、查询负载 | 可重建投影或受管记录 |

Runtime Adapter 应按 adapter_id、adapter_version、framework_version 和 trust_profile 分池。不同安全等级、不同第三方依赖或带自定义代码的 Adapter 不共用进程；它们使用独立工作负载身份、网络策略、临时目录和资源上限。

## 4. 租户隔离模型

### 4.1 隔离等级

| 等级 | 计算 | 事务数据 | 对象/向量 | 适用场景 |
|---|---|---|---|---|
| T1 逻辑隔离 | 共享 Cell 与 Worker 池 | 共享库、每表 tenant_id + RLS | 共享服务、租户命名空间与独立密钥 | 一般内部团队、低敏只读 |
| T2 强逻辑隔离 | 共享 Cell、租户专属队列/限额 | 独立 Schema 或数据库 | 独立 bucket/index | 生产业务和中等敏感数据 |
| T3 物理隔离 | 租户专属 Worker/Adapter 池 | 独立数据库实例 | 独立账户/集群和密钥 | 高敏、受监管、强噪声隔离 |
| T4 专属区域 | 专属 Cell 或账户/订阅 | 区域内独立数据栈 | 禁止跨区域复制 | 主权数据、关键行业 |

隔离等级由 TenantProfile 声明并进入 ReleaseManifest 的环境约束。运行时不能自动降级隔离等级；容量不足时返回 deferred 或切换到同等级已批准 Cell。

### 4.2 强制租户上下文

tenant_id 来源只能是已验证的 PrincipalContext 或受信任路由，不接受业务载荷自报值。tenant_id 必须传播至：

- RequestEnvelope、TaskState、RunRecord、ActionRecord 和 EventEnvelope；
- 数据库连接会话、RLS 条件、对象键前缀、向量 namespace；
- 队列 topic/subscription、缓存键、限流键、幂等键；
- KMS key、凭据授权、模型供应商项目/账户；
- Trace、Metric、Log、Audit 和 Eval，但日志正文必须按分类脱敏。

任何缺少 tenant_id、tenant_id 不一致或跨租户引用的写操作必须在存储前失败。后台 Worker 读取消息后重新建立租户上下文，不能继承上一个任务的线程本地变量。

### 4.3 数据访问防线

1. API 层校验主体与租户关系；
2. 服务间 token 包含 audience、tenant、purpose、delegation 和短有效期；
3. Repository 强制接收 TenantScope，不提供无租户查询接口；
4. 数据库启用 RLS 或独立连接池；
5. 对象存储使用租户前缀、条件策略和每租户密钥；
6. 搜索/向量查询同时过滤 tenant_id、classification、purpose 和 ACL；
7. 导出、调试快照和 Eval 数据集走独立审批与脱敏；
8. 自动隔离测试验证缓存、批处理、错误栈、遥测和备份恢复路径。

## 5. 网络与身份拓扑

运行平面至少划分六个网络区：

| 网络区 | 允许入口 | 允许出口 |
|---|---|---|
| Edge Zone | 企业/公网受控入口 | Agent Gateway |
| Runtime Zone | Gateway、队列 | Control read API、Gateway、State Store |
| Adapter Sandbox | Runtime Shell | 仅 UEAF 端口，不直连企业写 API |
| Data Zone | 受信服务身份 | 指定存储复制/备份端点 |
| Tool Egress Zone | Tool Gateway | allowlist 企业 API、MCP Server |
| Model Egress Zone | Model Gateway | 批准的模型供应商私网/固定域名 |

人类身份由企业 IdP 签发，服务身份由工作负载身份系统签发；长期静态密钥禁止注入 Adapter。Credential Broker 为一次 ToolIntent 签发最小权限、短时、受 audience 限制的句柄，并记录签发与使用审计。模型与工具出口分离，防止模型插件或 Hosted Tool 绕过 Tool Gateway。

## 6. 环境与发布拓扑

开发、集成、预生产和生产使用不同账户/订阅、身份、密钥和数据。工件通过内容摘要晋级，不重新构建；ReleaseManifest 绑定：

- agent、prompt、schema、adapter 和 policy bundle 的精确版本；
- 目标 environment、region、tenant segment 与 isolation tier；
- model/tool/data provider allowlist；
- QualityGateDecision、SecurityGateDecision、OperationalReadinessDecision 和 ReleaseDecision 引用；
- 灰度比例、熔断阈值、回滚版本和状态迁移约束。

生产路由只加载已签名且 lifecycle_status=active 的 ReleaseManifest。长运行恢复继续使用原 release_id；发布控制器不得把已有 RunRecord 原地切换到新版本。

## 7. 高可用、容灾与故障域

### 7.1 单区域高可用

- Gateway、Coordinator、Adapter、Context/Model/Tool Gateway 至少跨三个可用区部署；
- 队列、事务库和对象存储使用区域多可用区能力；
- Coordinator 通过租约和 fencing 接管，不依赖进程粘性；
- Adapter 崩溃从 CheckpointProjection/provider_state_ref 恢复；
- Tool Reconciler 独立于主执行 Worker，主集群故障后仍能处理 unknown 动作；
- 审计通道与普通 Trace 分离，审计积压触发风险级策略。

### 7.2 跨区域策略

| 数据/能力 | 默认策略 | RPO | RTO |
|---|---|---:|---:|
| Registry、Schema、发布元数据 | 跨区域复制，只读缓存 | 15 分钟 | 1 小时 |
| TaskState、RunRecord | 同驻留边界复制；T4 不跨区 | 5 分钟 | 30 分钟 |
| ActionRecord 与业务收据 | 同驻留边界强保护 | 0–5 分钟 | 30 分钟 |
| AuditEvent | WORM/不可变复制 | 5 分钟 | 4 小时查询可用 |
| Trace/Metric/Search 投影 | 可重建 | 1 小时 | 8 小时 |
| Vector 索引 | 从权威语料重建或受控复制 | 24 小时 | 24 小时 |

区域故障转移只有在目标区域满足 TenantProfile、数据驻留、ReleaseManifest、Adapter 能力和依赖条件时才能执行。无法满足时暂停新准入，保留恢复信息，不把请求导向未批准区域。

## 8. 容量与伸缩

容量规划以四类独立资源核算：

1. 入口：requests/s、并发流式连接、请求体大小；
2. 推理：模型调用/s、input/output token/s、供应商配额；
3. 编排：活跃 Run、等待 Run、事件/s、Checkpoint 大小；
4. 动作：ToolIntent/s、待审批数、unknown/reconciling 积压。

自动扩缩容指标优先使用队列滞后、最老消息年龄、活跃租约、token/s 和工具积压，不能只看 CPU。租户公平调度至少包含每租户并发上限、加权队列、突发额度和全局保护阈值。降载顺序为：拒绝非关键批处理、延迟低优先级 Run、降低允许的并发、切换 ReleaseManifest 明示的模型路由，最后暂停新准入；不得跳过策略检查或关闭审计换取吞吐。

## 9. MVP 与目标态部署差异

| 能力 | 90 天 MVP | 目标态 |
|---|---|---|
| Runtime Cell | 单区域、多可用区、一个生产 Cell | 多区域、多 Cell、自动合规路由 |
| 服务拆分 | 模块化单体控制 API + 独立 Worker/Gateway | 按负载与故障证据拆分服务 |
| 数据 | PostgreSQL、对象存储、Redis、单一消息系统 | 分片/多区域数据单元 |
| 租户等级 | T1/T2，预留 T3 接口 | T1–T4 |
| Adapter | LangGraph + 第二个只读 Adapter | 五类框架适配及版本矩阵 |
| HA/DR | 区域 HA、备份恢复演练 | 跨区域编排和分级 RPO/RTO |

MVP 仍必须保留端口、独立所有权、tenant_id 强制传播、ActionRecord 账本和审计边界，不能用“以后拆服务”为由合并语义。

## 10. 部署验收

1. 两个测试租户在数据库、对象、向量、缓存、队列、Adapter 临时目录和遥测中均无法互访。
2. 任一 Coordinator 或 Adapter 实例强制终止后，Run 可由新实例恢复，过期 fencing_token 写入失败。
3. Tool Gateway 断连后 ActionRecord 保持 unknown/reconciling，并在恢复后通过对账收敛。
4. 生产 Adapter 无法直连企业写 API、Secret Manager 原始密钥或控制面写接口。
5. ReleaseManifest 失效或撤销后不再接受新 Run，既有 Run 按明确策略继续、暂停或迁移。
6. 单可用区故障不影响已承诺 SLO；备份恢复演练满足所选隔离等级的 RPO/RTO。
7. 不合规的跨区域路由、隔离等级降级和缺少 tenant_id 的后台消息均被自动拒绝并产生安全审计。
