## 3. V1 Evidence 责任边界

```text
02..08
  在事实产生位置形成结构化 observation

09
  通过核心 TelemetryPort / module-local non-blocking buffer
  完成 sampling / aggregation / retention / Evidence Projection

11
  读取 Projection / refs
  完成 Trigger Candidate / Trigger Gate / Evidence Expansion
```

这里的 `TelemetryPort` 只指核心端口规范中的：

```text
EmitTrace
EmitMetric
EmitLog
EmitAudit
```

模块内部 MAY 使用私有轻量 buffer，但不得再定义公共 `TelemetryPort.emit(TelemetryEvent)` 同义接口。

## 4. V1 Evolution 复用边界

模块 11 只新增五个 Canonical Object：

```text
EvolutionTrigger
EvolutionRun
GenomeManifest
MutationProposal
EvolutionAuthorityPolicy
```

以下必须复用：

| 需要 | 复用 |
|---|---|
| 即时止血 | 05/07/08/09 的 rollback / fallback / isolate / degrade / kill 等既有能力 |
| Evidence collection | 模块 09 Telemetry / Sampling / Aggregation / Retention |
| 原始领域 Evidence | 02–08 各自权威对象和 refs |
| Genome candidate materialization | 模块 11 `GenomeManifest` owner 的应用操作 |
| 候选构建 | 模块 10 `ReleaseCandidate` |
| 评测 | 模块 08 `EvalConfig` / `EvalRun` / `EvalResult` |
| 安全门禁 | 模块 07 |
| 生产就绪门禁 | 模块 09 |
| 预算 | 既有 Budget Domain |
| 发布 | 模块 08 `ReleaseDecision` / `ReleaseManifest` |
| 工件 | Artifact / Registry |

因此演化构建链固定为：

```text
MutationProposal
  -> machine validation
  -> GenomeManifest candidate
  -> Module 10 ReleaseCandidate
  -> Eval / Gates / Release
```

不得为工程便利跳过 Genome candidate。

## 5. 两条反馈链

```text
Observed signal / opportunity
  ├─ P0/P1 urgent -> existing Operational Response
  │                  rollback / fallback / isolate / degrade / kill
  │
  └─ Trigger Gate -> EvolutionTrigger -> EvolutionRun
```

- Operational Response：解决“现在怎么办”；
- Evolution Response：解决“以后是否值得改变自己”。

异常、告警、Incident、Metric 超阈和单次失败都不是 `EvolutionTrigger` 的同义词。

## 6. Trigger Gate

除 P0 快速路径外：

```text
evidence_sufficient
  -> still_relevant
  -> mutable_surface_match
  -> existing_mitigation_insufficient
  -> novelty_sufficient
  -> expected_value_positive
  -> cooldown_satisfied
  -> EvolutionTrigger
```

Trigger Gate 优先规则/统计/Projection/索引；模型只处理无法可靠判断的根因、novelty 或 expected value。

## 7. 关键同步契约

公共接口名称以核心端口规范为准：

| 调用方 | 规范接口 | 服务方 | 响应 |
|---|---|---|---|
| Runtime Adapter | `ContextBuildPort` | Context Builder | `ContextManifest` |
| Runtime Adapter | `ModelStepPort` | Model/Prompt Facade | model step result / `StructuredDecision` |
| Runtime Adapter | `ToolIntentPort` | Tool Gateway | `ActionRecordRef` / controlled interruption |
| Runtime Adapter | `HandoffPort` | Workflow/Handoff | controlled handoff result |
| Runtime/Modules | core `TelemetryPort` | Module 09 / Audit path | TelemetryAck / AuditCommitReceipt |
| Tool Gateway | Policy interface | PDP | `PolicyDecision` |
| Module 11 | Strategy input | Evolution Strategy | Proposal Draft[] |
| Module 11 | Genome materialization | Genome owner | `GenomeManifest` candidate |
| Module 11 | `CandidateBuildPort` | Module 10 | `ReleaseCandidate` |
| Module 11/10 | Eval interface | Module 08 | `EvalRun` / `EvalResult` refs |

模块内部 convenience method 不成为新的跨模块规范 Port。

## 8. 事件边界

跨模块权威事件只使用核心规范已经登记的 `EventEnvelope` 与事件名：

```text
ueaf.<domain>.<past_tense_fact>
```

当前核心事件目录尚未把 Evolution lifecycle event 注册成跨模块 public event。因此 V1 模块化单体中的 Trigger/Run/Mutation/Genome 生命周期 MAY 使用模块 11 内部 event/attempt metadata；它们不是新的公共契约。

如果未来需要跨进程公开：

```text
ueaf.evolution.*
```

必须先更新核心事件规范/ADR，再实现。本文不预注册 `ueaf.evolution.triggered` 等 public event。

## 9. 模块边界规则

### 9.1 Canonical Object

- 所有跨模块持久化对象继承核心 `ContractMeta`；
- 下层文档列领域字段时只是增量字段；
- 同一 Canonical Name 不得在模块内重新定义一套冲突字段。

### 9.2 Context

- 模块 04 是 `ContextManifest` 的唯一写者；
- Evolution Working Set 不成为业务 `MemoryRecord`；
- RAG 大 Payload 通过 refs 按需读取。

### 9.3 Action

- 模块 05 唯一拥有 `ActionRecord/action_key`；
- Tool timeout/unknown 必须 reconciliation；
- 新 Tool 进入生产后仍必须经过 Tool Gateway。

### 9.4 Eval / Release

- 模块 08 拥有 Eval/Release 语义；
- `ReleaseManifest` 使用核心“兼容版本集合”字段；
- Module 11 只消费 Eval、提交 Candidate，不签发生产 Release。

### 9.5 Budget

- Evolution budget 是既有 Budget Domain 切片；
- Candidate/Strategy 不得提高自身预算。

### 9.6 Genome

V1 统一：

```text
GenomeManifest<agent>
GenomeManifest<skill>
GenomeManifest<tool>
GenomeManifest<workflow>
GenomeManifest<strategy>
```

不同 Subject 由 `profile_ref` 定义操作面，不建立多套 Genome 生命周期。

### 9.7 Lineage / Fitness / Experience

- Lineage：refs/events -> Projection；
- Fitness：Eval/Cost/SLO -> comparison view；
- Experience/Lesson：内部记录；
- RunSummary/ErrorFingerprint/AggregateWindow/TriggerCandidate：Projection/内部分析；
- Gene Pool / Species：V1 不是当前 Domain。

## 10. Minimum Semantic Surface

新增跨模块对象前必须证明：

1. 独立生命周期；
2. 独立 Semantic Owner；
3. 独立状态迁移/并发控制；
4. 跨模块稳定契约需求；
5. 现有对象 + ref / Projection / Registry metadata / Eval dimension 无法表达。

否则不得新增 Canonical Object。

## 11. V2/V3 边界

V2 Planned：Species、Population、Elite、Gene Pool、Capability Transfer、Local/Ecosystem Fitness、Diversity。

V3 Research：Meta Evolution、Dynamic Niche/Species、Ecosystem Topology、Pareto、Evolution Debt/Systemic Risk、ModelEvolutionPort。

V2/V3 不属于 V1 Current 实现或验收要求。
