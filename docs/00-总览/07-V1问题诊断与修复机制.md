# UEAF V1 问题诊断与修复机制

Architecture Generation: `V1`  
Implementation: `Current`

## 1. 定位

V1 在完成 Evidence 自动采集和 Trigger Gate 后，需要回答最后一个关键问题：

> 发现问题以后，到底修什么、修到哪一层、由谁修？

UEAF 的回答是：

```text
基层模块
  -> 发现事实
  -> 必要时止血

Evolution Kernel
  -> 诊断
  -> 选择最小长期修复
  -> MutationProposal

Build / Eval / Release
  -> 证明修复是否有效
  -> 决定是否进入生产
```

- `../01-核心规范/08-V1问题诊断与最小修复规范.md`
- `../03-参考架构/08-V1问题诊断与修复路由.md`

## 2. 核心原则

### 2.1 基层不长期自改

RAG、Tool、Model、Workflow、Memory、Runtime 可以检测异常并执行当前版本已允许的 fallback/retry/reconcile/degrade/rollback 等即时动作，但不能原地修改长期配置、代码或当前 `ReleaseManifest`。

### 2.2 问题发生层不等于修复层

```text
Tool error
  MAY repair Prompt/Model

RAG empty
  MAY repair Query/Route
  MAY be source/security issue

Workflow slow
  MAY repair Tool/Model
```

所以必须先 Diagnosis，再选 Repair Target。

### 2.3 最小有效修复

```text
R0 Operational Mitigation
R1 Parameter / Config
R2 Component / Routing
R3 Workflow / Composition
R4 Artifact / Code
R5 Governance Boundary
```

优先选择最小可行层级，只有新证据支持时才扩大修改范围。

## 3. Repair Router

Repair Router 是模块 11 内部逻辑，不是新服务或 Canonical Object。

输入：

```text
EvolutionTrigger
A/B/C Evidence
baseline GenomeManifest
EvolutionAuthorityPolicy
mitigation refs
previous attempts
```

输出：

```text
NO_EVOLUTION
OPERATIONAL_ONLY R0
MUTATION R1..R4
ROUTE_GOVERNANCE R5
```

四类输出互斥；`ROUTE_GOVERNANCE` 不生成 `MutationProposal`。大写 `R0`–`R5` 是概念标签，wire/Schema/config 使用小写 `r0`–`r5`，MutationProposal 只允许 `r1`–`r4`。

## 4. 首批 V1 修复能力

为控制实现复杂度，第一阶段建议只支持：

### RAG

```text
retrieval_empty / recall / context token
  -> R1 Context/Retrieval Policy
```

必要时再进入 R2 Retriever/Embedding/Route。

### Model

```text
schema invalid / token / provider route
  -> R1 Prompt/Config
  -> R2 Model Route
```

### Tool

```text
timeout / rate limit / schema mismatch
  -> R0 reconcile/fallback/backoff
  -> R1 timeout/backoff
  -> R2 Tool/Provider route
```

Tool timeout + `outcome_certainty=unknown` 必须先 reconciliation，禁止机械增加 retry。

## 5. 延后能力

在 V1 基础闭环稳定前，不要求自动启用：

- R3 Workflow topology repair；
- R4 Tool/Adapter/Skill code generation and repair；
- 大范围 Agent composition 修改。

这些设计已经保留，但需要更强 Eval/Canary 后再开启。

## 6. Governance Boundary

R5 包括：

```text
Identity
Permission
PDP / PEP
ACL / classification root
Secrets
Tool Gateway enforcement
Audit root
Eval root
Release Authority
Budget Enforcement
Kill switch
Deletion / Legal Hold
```

AI 可以发现“权限导致任务无法完成”，但不能把“增加自身权限”当作自动修复。

## 7. V1 修复主链

```text
Problem / Opportunity
  -> Operational Response if needed
  -> Trigger Gate
  -> EvolutionTrigger
  -> bounded Evidence Expansion
  -> Diagnosis
  -> Repair Router
      -> no evolution
      -> R5 governance
      -> R1..R4 MutationProposal
  -> GenomeManifest Candidate
  -> ReleaseCandidate
  -> targeted/full Eval by repair level
  -> Release Governance
  -> Production Feedback
```

这样 V1 既具备真正的自我修复能力，又不会让每个基层模块变成独立自治自修改系统。
