# UEAF 总体设计

Architecture Generation: `V1`  
Implementation: `Current`

## 1. 文档目的

本文定义 UEAF V1 的系统边界、能力域、模块职责、唯一所有权、运行主链和受控演化主链。字段级对象、状态、事件和端口分别以核心规范 01–09 为准；本文不得另建同义 Schema、Port 或状态机。

V2/V3 仅保留 Future/Research 方向，不覆盖本文 V1 Current 范围。

## 2. 架构驱动因素

| 优先级 | 驱动因素 | V1 设计响应 |
|---:|---|---|
| 1 | 身份、租户和权限正确 | `PrincipalContext` 由可信边界建立；PDP/PEP 独立授权 |
| 2 | 副作用不可重复、可追责 | `ActionRecord`、`action_key`、审批、收据、fencing、对账 |
| 3 | 任务可暂停、恢复、取消 | 正交状态、Checkpoint、租约、CAS、版本重验 |
| 4 | 结果有证据 | `ContextManifest`、Evidence、Trace/Audit/Eval 分离 |
| 5 | Runtime 可替换 | 核心 `RuntimeAdapter` SPI + Conformance |
| 6 | 多租户隔离 | tenant propagation、ACL、RLS/Cell、用途和驻留控制 |
| 7 | 变化可控制 | `ReleaseManifest`、门禁、灰度、回滚 |
| 8 | 运营可量化 | SLO、成本、容量、Evidence gap |
| 9 | Agent 可持续改进 | 事件驱动 Trigger、受控 `EvolutionRun`、Sparse Mutation、独立 Eval/Release |
| 10 | 演化成本与风险有界 | L0/L1/L2 Evidence、Budget、Working Set、Governance Kernel 边界 |

## 3. 系统边界与五个平面

```text
Developer Plane
  定义 / 构建 / Sandbox / Adapter / ReleaseCandidate

Control Plane
  Registry / Policy / Budget / Eval / Release / Route / Kill Switch

Runtime Plane
  Admission / Run Coordinator / Runtime Adapter / Context / Model / Tool / Workflow

Data Plane
  Task / Run / Action / Checkpoint / Artifact / Memory 的物理承载

Evidence & Governance Plane
  Trace / Metric / Log / Audit / Eval / SLO / Evolution Evidence Projection
```

语义所有权与物理部署必须分开。模块可共进程实现，但不得通过共享数据库、共享 ORM 或框架原生状态建立第二真相源。

## 4. V1 功能模块

| 编号 | 模块 | 唯一主责 | 关键输出 |
|---:|---|---|---|
| 01 | 接入与准入 | 边缘预校验、可信身份映射、不可变任务输入、已有 Run 的准入 | `PrincipalContext`、`RequestEnvelope`、`TaskEnvelope`、`RunAdmissionResult` |
| 02 | Agent 运行时与状态 | Task/Run 状态、Agent Loop、Checkpoint、终态 | `TaskState`、`RunRecord`、`TurnRecord` |
| 03 | 模型、Prompt 与结构化输出 | Prompt/Schema 契约、模型调用、候选结果校验 | `PromptContract`、`ModelInvocation`、`ModelRunResult`、`StructuredDecision` |
| 04 | 上下文、RAG 与记忆 | 权限检索、证据、上下文装配、受治理记忆 | `ContextManifest`、`EvidencePack`、`MemoryRecord` |
| 05 | 工具、MCP 与动作执行 | Tool Gateway、动作授权执行、幂等、收据、对账 | `ToolIntent`、`ActionRecord`、`ActionReceipt`、`ToolResult` |
| 06 | 工作流与多 Agent | Workflow/Node 状态、路由、并发、Handoff | `WorkflowRun`、`NodeRun`、`HandoffEnvelope` |
| 07 | 身份、权限与安全治理 | PDP/PEP、审批、短期凭据、安全治理 | `PolicyDecision`、`SecurityGateDecision`、安全/Audit 事实 |
| 08 | 评测与发布治理 | Eval、质量门、门禁聚合、发布裁决 | `EvalResult`、`QualityGateDecision`、`ReleaseDecision`、`ReleaseManifest` |
| 09 | 生产运行与可观测性 | 队列/租约承载、Telemetry、SLO、部署恢复、运行就绪 | `OperationalReadinessDecision`、Run/Evidence Projection、运营事实 |
| 10 | 开发者平台与框架适配 | SDK/CLI、Artifact、Sandbox、Adapter、Candidate Build | `ReleaseCandidate`、Adapter/Artifact、Conformance evidence |
| 11 | V1 经验记忆与受控递归进化 | Trigger、EvolutionRun、Genome、Mutation、演化权限 | 五个 V1 Evolution Canonical Object |

V1 Module 11 是当前参考实现和 V1 验收的一部分；企业部署可以通过 `EvolutionAuthorityPolicy` 收紧或关闭自动 Experiment/Promote，但不能因此把 V1 文档解释成需要另建 V2 生态服务。

## 5. 核心对象与唯一所有权

所有跨模块持久化对象继承 `ContractMeta`。同一 Canonical Name 只能有一套字段语义。

| 事实 | Semantic Owner | State Writer |
|---|---|---|
| `PrincipalContext` | Identity & Delegation | Trusted Admission Boundary / Principal Mapper |
| `TaskState` | Task Domain | Task State Service |
| `RunRecord` | Runtime Domain | Run Coordinator / State Service |
| `RunAdmissionResult` | Admission Domain | Admission Coordinator |
| `ContextManifest` | Context Domain | Context Builder |
| `MemoryRecord` | Memory Domain | Memory Service |
| `ActionRecord` / `ActionReceipt` | Action Domain | Tool Gateway / Action Coordinator |
| `PolicyDecision` | Policy Domain | PDP |
| `WorkflowRun` / `NodeRun` | Workflow Domain | Workflow Coordinator |
| `EvalResult` | Eval Domain | Eval infrastructure |
| `ReleaseManifest` | Release Control | Manifest Signer / Release Controller |
| V1 五个 Evolution 对象 | Evolution Domain / Module 11 | Evolution Coordinator/Genome Registry/Authority owner as defined by core specs |

Projection、缓存、搜索/向量索引和物理 Store 不取得 Semantic Owner 权限。

## 6. 核心运行主链

```text
RequestEnvelope + PrincipalContext
  -> Edge Pre-validation + TaskEnvelope
  -> TaskState + RunRecord(queued)
  -> queued -> admitting
  -> RunAdmissionResult
       admitted -> running
       deferred -> waiting
       rejected -> terminal/rejected
  -> ContextBuildPort -> ContextManifest
  -> ModelStepPort -> ModelInvocation / ModelRunResult / StructuredDecision
  -> ToolIntentPort when side effect is proposed
  -> PolicyDecision / ApprovalRequest
  -> ActionRecord / ActionReceipt / reconciliation
  -> Workflow/Handoff when required
  -> Run terminal + CompletionDisposition
  -> Trace / Metric / Log / Audit / Eval / Production Evidence
```

Run 使用核心正交状态：`RunPhase`、`WaitReason`、`CompletionDisposition`。外部 Tool timeout/断连且结果可能已发生时，必须保持 unknown 并先 reconciliation。

## 7. Runtime Adapter 边界

公共最小 SPI 只由核心端口规范定义：

```text
DescribeRuntime
StartRun
AdvanceRun
SuspendRun
ResumeRun
CancelRun
InspectRun
```

Adapter：

- 只转换框架原生生命周期和事件；
- 通过 `ContextBuildPort`、`ModelStepPort`、`ToolIntentPort`、`HandoffPort`、`TelemetryPort` 使用 UEAF 能力；
- 不能持有企业写工具旁路、模型长期凭据或权威 State Store 句柄；
- 原生 Runtime event 先映射为 `RuntimeEvent`/observation；只有权威 State Writer 提交的事实才形成跨模块 `EventEnvelope`；
- 不支持的能力必须显式拒绝。

## 8. Event、Command 与错误契约

跨模块权威事件只使用核心 `EventEnvelope`，事件名为：

```text
ueaf.<domain>.<past_tense_fact>
```

实施/功能模块不得定义第二套 Event Envelope 或 PascalCase public event。

跨进程/API 错误使用 `ProblemDetail`；Port 使用 `PortResult<T>` + `PortError`。早期 `ErrorEnvelope` 不再是新实现的公共对象。

## 9. Tool / Action 边界

所有企业副作用：

```text
ToolIntent
  -> server-side bind/canonicalize
  -> action_fingerprint + action_key
  -> ActionRecord(proposed)
  -> validation
  -> PolicyDecision
  -> Approval if required
  -> idempotency reservation
  -> scoped credential + execution
  -> ActionReceipt(succeeded | failed | unknown)
  -> reconciliation when unknown
```

工具“可发现”不等于“可执行”；Policy/Eval/Release 也不能替代一次运行时动作授权。

## 10. V1 Evidence 主链

```text
Modules 02..08 domain facts
  -> core TelemetryPort / module-local non-blocking buffer
  -> Module 09 sampling / aggregation / retention
  -> Run Summary / rolling windows / Error Fingerprint
  -> Trigger Candidate
  -> Trigger Gate
       enough -> decide
       unclear -> bounded Evidence Expansion
  -> EvolutionTrigger or no_trigger
```

L0 全量小指标、L1 条件采样、L2 按需扩展。正常 Collection/Aggregation/Fingerprint/Trigger Candidate 路径目标为 `0 LLM Token`。

## 11. V1 Evolution 主链

```text
Production Evidence / Opportunity
  -> Operational Response first if urgent
  -> Trigger Gate
  -> EvolutionTrigger
  -> bounded EvolutionRun
  -> Diagnosis / Repair Router
  -> Effective Mutation Surface
  -> bounded EvolutionStrategy
  -> machine-valid MutationProposal when justified
  -> GenomeManifest candidate
  -> Module 10 ReleaseCandidate
  -> Module 08 Eval + 07/09 hard gates
  -> Objective comparison against baseline
  -> ReleaseDecision / ReleaseManifest
  -> Production Feedback
```

V1 只新增：

```text
EvolutionTrigger
EvolutionRun
GenomeManifest
MutationProposal
EvolutionAuthorityPolicy
```

Candidate/Eval/Budget/Release/Artifact 均复用既有语义。

## 12. Repair 与 Governance 边界

```text
R0 Operational Mitigation
R1 Parameter / Config
R2 Component / Routing
R3 Workflow / Composition
R4 Artifact / Code
R5 Governance Boundary
```

R1–R4 只能产生 Candidate；R5 退出同一自动递归链。问题发生层不等于 root cause/repair target，默认遵守 Smallest Effective Repair。

Task/业务风险分级不得复用 `R0..R5` RepairLevel 符号；不同风险体系必须使用语义明确的枚举或独立类型名，防止日志/Schema 混淆。

## 13. V1 可变操作面

有效修改面为：

```text
Subject Profile
∩ EvolutionAuthorityPolicy
∩ EvolutionRun.mutable_scope
∩ Repair Target
∩ Risk Profile
```

`change_summary` 仅用于解释；机器执行依赖 `changes[]`。Prompt/ContextPolicy/ModelRoute/MemoryPolicy 默认是版本化 Profile/Artifact，不新增独立 Evolution Canonical Object。

## 14. 生产与发布

- 每个 Run 冻结一个不可变 `ReleaseManifest`；
- `ReleaseManifest` 表达兼容版本集合；
- Quality/Security/Operational 三类门禁独立产生，`ReleaseDecision` 只聚合有效结论；
- 当前 Production Agent 无权原地修改自身 Release；
- Candidate 不能改自身 Eval root、Release Authority 或 Budget Enforcement。

## 15. 实现拓扑

首个 V1 继续遵守 ADR-004：模块化单体优先，配合少量独立基础设施。Reference Profile 的技术默认见 `docs/05-实施规范/05-V1参考实现与Codex开发规范.md`。

拆服务只有在独立扩缩、信任域、合规、故障域、驻留或团队所有权有证据时进行。

## 16. V1 完成标准

V1 Reference Implementation 至少证明：

1. 两个 Runtime Adapter 的只读 Conformance；
2. Run 状态、CAS、恢复和终态不变量；
3. 企业副作用全部经过 Tool Gateway 且 unknown 可对账；
4. 多租户、身份、Policy、Audit、Eval/Release 边界有效；
5. L0/L1/L2 Evidence 成本有界；
6. 至少一个 `Trigger -> EvolutionRun -> Diagnosis -> Mutation -> Genome -> ReleaseCandidate -> Eval -> Accept/Reject` 闭环；
7. Mutation 可被 Subject Profile/Authority 机器拒绝越权字段；
8. Governance Kernel 不进入同一递归链；
9. V1 未预建 Species/GenePool/Ecosystem Fitness/Meta Evolution 服务。
