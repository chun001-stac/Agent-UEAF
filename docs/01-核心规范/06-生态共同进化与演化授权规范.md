# UEAF 生态共同进化与演化授权规范

版本：`0.2.0-draft`  
规范状态：Draft  
Architecture Generation: `V2`  
Maturity: `Planned`  
Implementation: `Future`

> 本文是 V2 计划架构，不属于 V1 当前实现与验收范围。V1 只需要保证版本化引用、provenance、compatibility metadata 和 `GenomeManifest` 不堵死本设计。

## 1. 范围

V2 将 V1 的“单 Agent / 局部能力受控进化”扩展为“整个 Agent 生态共同进化”。核心目标不是构造一个不断膨胀的超级 Agent，而是让 Agent、Skill、Tool、Workflow、Routing 与 Strategy 可以作为可复用能力单元演化、竞争和迁移。

V2 继续复用 V1 的：

- `EvolutionTrigger`；
- `EvolutionRun`；
- `GenomeManifest`；
- `MutationProposal`；
- `EvolutionAuthorityPolicy`；
- 既有 `ReleaseCandidate` / Eval / Release Governance。

V2 不创建第二套 Runtime、Identity、Tool、Eval 或 Release 语义。

## 2. V2 计划能力

V2 计划引入或正式化：

- Species / Population / Elite；
- Gene Pool；
- Capability Transfer；
- Local Fitness + Ecosystem Fitness；
- Diversity / Monoculture Risk；
- Specialist / Niche-aware routing 的基础能力；
- Funnel Evaluation 后的生态级评测；
- 共享 Agent、Tool、Model、Skill 的资源归因与外部性分析。

这些能力进入 Current 前，必须通过 ADR 证明实际规模和独立生命周期，不能仅因为本设计存在就预建服务或数据库。

## 3. 生态版本

V2 MAY 引入 `EcosystemGenome` 作为环境级不可变组合清单：

```yaml
ecosystem_genome_id: string
environment: string
agent_refs: [string]
shared_capability_refs: [string]
routing_ref: string
gene_pool_view_ref: string | null
diversity_policy_ref: string | null
evolution_authority_policy_ref: string
parent_refs: [string]
integrity_ref: string
```

`EcosystemGenome` 主要引用 V1 `GenomeManifest` 与已注册能力工件，不复制其内容。

在 V2 正式实施前，V1 不需要创建该对象。

## 4. Species

Species 表达一组共享目的、接口与适用范围的可替代实现。

V2 MAY 把 V1 的 `species_tag` / Registry metadata 升级为 `SpeciesDefinition`：

```yaml
species_id: string
subject_type: agent | skill | tool | workflow | strategy
purpose: [string]
interface_contract_ref: string
compatibility_profile_ref: string
member_genome_refs: [string]
elite_refs: [string]
status: active | experimental | deprecated | archived
```

V2 仍 SHOULD 复用通用 `GenomeManifest`，而不是默认建立 AgentGenome/SkillGenome/ToolGenome/WorkflowGenome 五套基础生命周期。

只有某一 subject type 证明拥有真正不同的状态机和 Semantic Owner 时，才允许单独升级。

## 5. Gene Pool

Gene Pool 的 V2 目标是复用已经验证的能力。

优先实现方式：

```text
Artifact / Registry
  -> reusable_for_evolution metadata
  -> provenance / compatibility / eval refs
  -> Gene Pool Projection / View
```

只有当规模和查询/治理需求证明必要时，Gene Pool 才升级为独立 Domain。

V2 Gene Pool MAY 包含：

- Prompt Bundle；
- Model/Router Policy；
- Context / Memory Policy；
- Skill；
- Tool；
- Workflow；
- Agent topology；
- Evolution Strategy；
- 已验证并编译的 Rule / Policy。

默认 tenant scoped。跨租户复用必须显式发布、重新分类并在目标侧重新评测。

## 6. Capability Transfer

V2 的横向能力迁移默认复用 V1 `MutationProposal.mutation_type=transfer`。

只有当迁移本身出现独立长生命周期、审批、状态机或跨团队流程时，才升级为独立 `CapabilityTransferProposal`。

基本流程：

```text
validated source capability
  -> transfer MutationProposal
  -> target compatibility check
  -> target sandbox eval
  -> local fitness
  -> ecosystem checks
  -> existing release gates
```

源场景 Fitness 不得直接继承到目标场景。

## 7. Local Fitness 与 Ecosystem Fitness

### 7.1 Local Fitness

评价 Candidate 自身：

- task success / quality；
- safety / robustness；
- token / cost；
- latency；
- regression。

V2 SHOULD 继续从模块 08 EvalResult、模块 09 Cost/SLO 等事实派生，不建立第二套评测真相源。

### 7.2 Ecosystem Fitness

评价 Candidate 对整体系统的外部性，例如：

- overall business utility；
- total token / compute / dollar cost；
- end-to-end P95/P99 latency；
- Tool/Model/Agent contention；
- correlated failure risk；
- dependency concentration；
- operational complexity；
- cross-agent regression；
- resource fairness；
- monoculture risk。

Local 提升但 Ecosystem 明显退化时，不得自动 Promote。

## 8. Funnel Evaluation

V2 不允许每个 Mutation 默认执行全生态评测。

推荐：

```text
Candidate
  -> cheap local deterministic eval
  -> local regression
  -> shortlist
  -> ecosystem externality eval
  -> diversity/concentration check
  -> final release gates
```

全生态评测只针对少量 Finalist，防止 Eval 组合爆炸。

## 9. Diversity

Diversity 在 V2 首先可以作为 Eval/Policy Profile，而不是独立服务。

可能的维度：

```yaml
min_alternative_species: integer
min_model_provider_diversity: integer
max_shared_gene_ratio: number
max_dependency_concentration: number
preserve_elite_variants: integer
```

目标是避免所有 Agent 收敛到同一个隐藏故障路径，而不是为了多样性牺牲质量。

## 10. Evolution Authority

V2 继续复用 V1 `EvolutionAuthorityPolicy`：

```text
Observe     default allow
Propose     default allow
Experiment  default allow
Promote     risk-based
```

V2 扩展 target scope，例如：

- ecosystem topology；
- species membership；
- capability transfer；
- population strategy。

Governance Kernel 仍为 `never`。

## 11. V2 实施前置条件

至少满足以下条件中的多数后，才建议从 V1 升级到 V2：

1. 多个 Agent/Skill/Tool 出现重复能力和重复评测成本；
2. 真实生产中存在明显跨 Agent 资源外部性；
3. Capability reuse 的收益已超过 Registry metadata 管理成本；
4. 需要同时保留多个 Specialist / Elite；
5. Local-only Eval 已无法解释系统级退化；
6. V1 的标签/Projection 无法满足查询、权限或生命周期要求。

## 12. V2 非目标

V2 仍不要求：

- Meta Evolution；
- Dynamic Niche Discovery；
- Dynamic Species Creation；
- Ecosystem Topology 自主递归改写；
- Pareto Frontier 作为权威状态；
- Evolution Debt 独立领域；
- ModelEvolutionPort。

这些属于 V3 Research。

## 13. V2 兼容原则

1. 不推翻 V1 Runtime/Tool/Eval/Release 语义；
2. 尽量继续复用 `GenomeManifest`；
3. Species/GenePool/Transfer/Fitness 只有在独立生命周期被证明后才升级为 Canonical Object；
4. Gene Pool 优先作为 Registry Projection；
5. Lineage 优先由 refs/events 生成 Projection；
6. Ecosystem Fitness 不建立第二套 Eval 真相源；
7. V2 仍受 Budget、停止条件、Release Governance 和 Governance Kernel 约束。

详细代际关系见 `docs/00-总览/06-UEAF架构代际与实施范围.md`。
