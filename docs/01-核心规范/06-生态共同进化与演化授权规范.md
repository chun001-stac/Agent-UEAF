# UEAF 生态共同进化与演化授权规范

版本：`0.1.0-draft`  
规范状态：Draft

## 1. 范围

本文扩展《受控演化与递归自改规范》，定义 UEAF 在“整个 Agent 生态共同进化”场景下的规范对象、授权边界、共享基因池、能力迁移、双层 Fitness 与多样性要求。

本规范不新增第二套 Runtime、Eval、Release、Identity 或 Tool 语义。所有候选仍必须遵守现有 `Runtime Adapter`、`Tool Gateway`、`Evaluation`、`ReleaseManifest` 与 Governance Kernel 边界。

核心目标不是让单个超级 Agent 无限膨胀，而是允许 Agent、Skill、Tool、Workflow、Routing 与 Evolution Strategy 作为可独立演化、可组合、可复用的能力单元共同进化。

## 2. 核心原则

1. **生态共同进化优先于单体无限膨胀。** Agent SHOULD 通过引用可复用 Skill、Tool、Workflow、Routing 与 Strategy 工件组合能力。
2. **最小有效变异单元优先。** 若失败可定位到单个 Skill、Tool、Workflow Gene 或 Routing Gene，MUST NOT 默认重写完整 AgentGenome。
3. **实验自治与生产晋升分离。** `Observe`、`Propose`、`Experiment` 与 `Promote` 是四种独立权限。
4. **默认开放演化，治理边界例外。** 对允许演化的目标，默认开启 Observe、Propose 与 Experiment；Promote 按风险分层。Governance Kernel 不属于可演化目标。
5. **能力可横向迁移。** 一个 Agent/Species 中验证有效的 Skill、Tool 或 Strategy MAY 经兼容性评测迁移到其他 Agent/Species。
6. **局部提升不得伤害整体生态。** Candidate 同时接受 Local Fitness 与 Ecosystem Fitness 约束。
7. **避免单一物种垄断。** 生态必须保留替代 Species、候选和能力实现，降低 Monoculture Risk。
8. **跨租户能力迁移默认禁止。** Gene Pool 默认 tenant scoped；跨租户共享只能通过显式发布、分类审查、来源证明与授权策略。

## 3. 规范对象

### 3.1 `EcosystemGenome`

`EcosystemGenome` 描述一个环境中可被组合和演化的 Agent 生态版本，不等于所有运行实例的内存快照。

```yaml
ecosystem_genome_id: string
environment: string
agent_species_refs: [string]
skill_species_refs: [string]
tool_species_refs: [string]
workflow_genome_refs: [string]
routing_genome_ref: string
memory_policy_genome_refs: [string]
evolution_policy_genome_ref: string
gene_pool_ref: string
diversity_policy_ref: string
evolution_authority_policy_ref: string
parent_ecosystem_refs: [string]
integrity_ref: string
```

任何组成引用发生变化都必须生成新的 `EcosystemGenome`，不得原地覆盖。

### 3.2 `SpeciesDefinition`

Species 是一组共享目标、接口和适用范围的可替代 Genome 集合。

```yaml
species_id: string
species_type: agent | skill | tool | workflow | strategy
purpose: [string]
interface_contract_ref: string
compatibility_profile_ref: string
population_refs: [string]
elite_refs: [string]
diversity_constraints_ref: string
status: active | experimental | deprecated | archived
```

Species 不等于具体实现。多个 Genome MAY 同时属于同一 Species，并在不同任务切片上表现更优。

### 3.3 `GenePool`

`GenePool` 是版本化、来源可追溯的可复用能力工件集合。

Gene Pool MAY 包含：

- Prompt Bundle；
- Model/Router Policy；
- Context Policy；
- Memory Policy；
- Skill Genome；
- Tool Genome；
- Workflow Genome；
- Agent Topology；
- Evolution Strategy；
- 经过验证的可编译 Policy/Rule。

Gene Pool MUST 保存：来源、tenant、classification、purpose、兼容版本、Fitness 证据、安全状态、父子 Lineage 和撤销状态。

### 3.4 `CapabilityTransferProposal`

用于描述能力从一个 Species/Agent 迁移到另一个 Species/Agent。

```yaml
capability_transfer_id: string
source_gene_ref: string
source_species_ref: string
target_species_ref: string
compatibility_evidence_refs: [string]
required_eval_suite_ref: string
risk_profile_ref: string
expected_gain: object
expected_cost: object
status: proposed | evaluating | accepted | rejected | archived
```

迁移成功不代表源能力在目标环境中自动继承原 Fitness；目标侧 MUST 重新评测。

### 3.5 `EvolutionAuthorityPolicy`

`EvolutionAuthorityPolicy` 定义 AI 对不同演化目标能做什么。它与 Genome 内容分离，不允许 Candidate 通过修改 Genome 获得更高演化权限。

```yaml
evolution_authority_policy_id: string
defaults:
  observe: allow
  propose: allow
  experiment: allow
  promote: risk_based
targets:
  prompt: object
  model_strategy: object
  context_policy: object
  memory_policy: object
  routing: object
  workflow: object
  skill: object
  tool: object
  agent_topology: object
  ecosystem_topology: object
  evolution_strategy: object
  meta_evolution: object
policy_version: string
issued_by: string
integrity_ref: string
```

每个 target 的权限必须分别表达：

```text
Observe    读取证据、现状与可见 Lineage
Propose    提出 Mutation / Transfer / Replacement
Experiment 在隔离环境构建并评测 Candidate
Promote    将通过门禁的候选推进到 Canary / Production
```

不得用单一 `can_modify=true` 代替四级权限。

## 4. 默认演化权限

UEAF 的默认思想是“允许能力演化，禁止治理边界演化”。

对 mutable targets，默认：

| Target | Observe | Propose | Experiment | Promote 默认 |
|---|---|---|---|---|
| Prompt | allow | allow | allow | automatic_after_gates |
| Model Strategy / Routing | allow | allow | allow | automatic_after_gates |
| Context Policy | allow | allow | allow | automatic_after_gates |
| Memory Policy | allow | allow | allow | automatic_after_gates |
| Workflow | allow | allow | allow | canary |
| Skill | allow | allow | allow | canary |
| Agent Topology | allow | allow | allow | canary |
| Ecosystem Topology | allow | allow | allow | gated |
| Tool | allow | allow | allow | gated |
| Evolution Strategy | allow | allow | allow | gated |
| Meta Evolution | allow | allow | allow | gated |
| Governance Kernel | observe_by_policy | deny | deny | never |

企业 MAY 收紧任意 mutable target，但不得通过普通配置把 Governance Kernel 改成可自主 Promote。

## 5. Genome 分层

### 5.1 AgentGenome

`AgentGenome` SHOULD 主要引用可复用能力，而不是复制全部实现：

```yaml
agent_genome_id: string
species_ref: string
model_strategy_ref: string
prompt_bundle_ref: string
context_policy_ref: string
memory_policy_ref: string
skill_refs: [string]
tool_refs: [string]
workflow_ref: string
routing_policy_ref: string
runtime_compatibility_ref: string
parent_genome_refs: [string]
integrity_ref: string
```

### 5.2 SkillGenome

Skill 是可复用的能力单元，MAY 自己拥有 Prompt、Tool、Workflow、Evaluator 与兼容约束。

### 5.3 ToolGenome

ToolGenome 只能描述受控工具工件及其 Schema、Adapter、策略、测试和安全元数据。任何有企业副作用的 Tool 进入生产后仍必须经过统一 Tool Gateway。

### 5.4 WorkflowGenome

WorkflowGenome 描述可版本化拓扑与节点组合。拓扑变异必须产生新版本，不得修改运行中的 `WorkflowRun`。

### 5.5 EvolutionPolicyGenome

Evolution Strategy 与搜索参数 MAY 被 Meta Evolution 产生候选，但其 Promote 受独立 `EvolutionAuthorityPolicy` 与 Governance Kernel 约束。

## 6. Gene Provenance 与 Genome Diff

每个可演化 Gene MUST 可追溯：

```yaml
gene_provenance:
  gene_ref: string
  source_genome_ref: string
  mutation_ref: string
  evolution_run_ref: string
  fitness_refs: [string]
  created_at: timestamp
```

发布审查 SHOULD 能生成 `GenomeDiff`，至少显示：

- 哪些 Gene 发生变化；
- 变化原因和 MutationProposal；
- Local/Ecosystem Fitness 差异；
- Token、费用、延迟与复杂度变化；
- 新增/删除的依赖；
- 兼容性与回滚目标。

## 7. Local Fitness 与 Ecosystem Fitness

### 7.1 Local Fitness

衡量 Candidate 对自身任务/Species 的效果，例如：成功率、准确率、成本、延迟、安全、鲁棒性和回归。

### 7.2 Ecosystem Fitness

衡量 Candidate 对整体生态的外部性，至少可包含：

- Overall Business Utility；
- 总 Token / Compute / Dollar Cost；
- 全链路 P95/P99 Latency；
- Tool/Model/Agent Contention；
- Correlated Failure Risk；
- Dependency Concentration；
- Operational Complexity；
- Cross-Agent Regression；
- Resource Fairness；
- Diversity / Monoculture Risk。

Local Fitness 改善而 Ecosystem Fitness 发生重大退化时，Candidate MUST NOT 自动 Promote。

## 8. `DiversityPolicy`

```yaml
diversity_policy_id: string
min_alternative_species: integer
min_model_provider_diversity: integer
max_shared_gene_ratio: number
max_dependency_concentration: number
preserve_elite_variants: integer
preserve_distinct_failure_modes: boolean
archive_policy_ref: string
```

DiversityPolicy 的目的不是为了多样性而牺牲质量，而是防止所有 Agent 共享同一隐藏缺陷、模型故障、Tool 实现或 Workflow 假设。

即使某 Genome 当前全局最优，系统 MAY 保留次优但差异显著的 Elite Variant 作为回滚、灾备或不同任务切片的替代 Species。

## 9. Capability Transfer

能力迁移流程：

```text
Source Species validated Gene
  -> Transfer Proposal
  -> Target Compatibility Check
  -> Target-specific Sandbox Eval
  -> Local Fitness
  -> Ecosystem Fitness
  -> Security / Operational Gates
  -> Target Candidate
  -> Canary / Release
```

禁止仅因“在 Agent A 上有效”就直接写入 Agent B。

## 10. 生态级不变量

1. `EcosystemGenome`、`AgentGenome`、`SkillGenome`、`ToolGenome` 与 `WorkflowGenome` 都是不可变版本化对象。
2. `EvolutionAuthorityPolicy` 不属于 Candidate 可提升自身权限的 Genome Gene。
3. Observe、Propose、Experiment、Promote 必须独立授权。
4. mutable targets 默认开放 Observe/Propose/Experiment；Promote 按风险分层。
5. Governance Kernel 永不作为普通 Species 或 Gene 进入 Gene Pool。
6. Capability Transfer 必须在目标环境重新评测。
7. Gene Pool 默认 tenant scoped；跨租户转移必须显式授权并重新执行分类、安全与兼容评测。
8. Candidate 必须同时产生 Local 与 Ecosystem Fitness 证据。
9. 局部 Agent/Skill 的提升不得通过无限调用其他 Agent、Tool 或强模型把成本转嫁给生态。
10. DiversityPolicy 不得被 Candidate 为通过自身评测而修改。
11. 生态允许多个 Species 并存，不要求收敛到单一全局 Agent。
12. 生态进化仍受 `EvolutionBudget`、停止条件、Release Governance 与 Governance Kernel 约束。
