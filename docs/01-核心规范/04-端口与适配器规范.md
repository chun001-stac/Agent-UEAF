# UEAF 端口与适配器规范

版本：`0.1.0-draft`<br>
规范状态：Draft

## 1. 目的与适用范围

本文定义 UEAF 采用六边形架构时的端口、适配器、能力协商、失败语义和一致性测试。目标是让 LangGraph、Microsoft Agent Framework、OpenAI Agents SDK、Google ADK、模型供应商、MCP Server、企业 IAM、存储与遥测产品可以替换，而不改变 UEAF 的任务、运行、动作和治理语义。

本文中的 MUST、SHOULD、MAY 具有规范等级。公共对象名称、状态和事件以[统一术语与对象模型](01-统一术语与对象模型.md)、[状态机与终态规范](02-状态机与终态规范.md)和[跨模块契约与事件规范](03-跨模块契约与事件规范.md)为准。

## 2. 六边形边界

UEAF 核心域 MUST 只依赖端口，不得依赖供应商 SDK、传输协议或基础设施对象。适配器负责把外部语义归一为 UEAF 契约，或把 UEAF 请求转换为外部协议。

```text
                 Inbound Adapters
 API / Event / CLI / Scheduler / Webhook / Agent SDK
                         |
                         v
              +-----------------------+
              |  UEAF Application     |
              |  Task / Run / Action  |
              |  Policy / Release     |
              +-----------------------+
                ^    ^    ^    ^    ^
                |    |    |    |    |
        Runtime Model Tool Identity Storage/Telemetry
                 Outbound Ports
                         |
                         v
   Frameworks / Providers / MCP / IAM / Databases / OTel
```

### 2.1 依赖规则

- 核心域 MUST NOT 导入供应商 SDK 类型。
- 端口方法 MUST 使用 UEAF 规范对象、稳定值对象或显式版本化 DTO。
- 供应商原生对象 MAY 保存在受控诊断工件中，但 MUST NOT 穿透为跨模块契约。
- 适配器 MUST 显式声明支持的契约版本、能力和限制。
- Runtime Domain MUST 在创建 `RunRecord` 前选择精确的 Adapter/CapabilityBinding，并在创建时冻结唯一 `runtime_adapter_ref`；Run admission 校验该冻结引用，admitted 后启动、恢复和重试均不得重新选择或静默切换适配器。
- MCP 只是 `ToolAdapter` 的协议实现，MUST NOT 绕过 Tool Gateway、Policy、审批、幂等或审计边界。

## 3. 公共端口约定

每个端口调用 MUST 携带或可可靠关联以下公共上下文：

| 字段 | 规则 |
| --- | --- |
| `tenant_id` | MUST；服务端从可信上下文绑定，不信任模型或工具参数 |
| `principal_context_ref` | 涉及主体、数据或动作时 MUST |
| `correlation_id` / `trace_id` | MUST；只用于关联，不替代审计 ID |
| `deadline_at` | MUST；适配器不得自行延长 |
| `release_id` | Run 内调用 MUST；绑定冻结配置 |
| `contract_version` | MUST；用于确定 Schema 与兼容范围 |
| `idempotency_key` | 可能产生副作用的调用 MUST |
| `classification` / `purpose` | 数据出域、存储或遥测时 MUST |

所有端口响应 MUST 使用下列归一结果之一：

```text
PortResult<T> = Success<T> | Rejected<PortError> | Unknown<PortError>
```

- `Success` 表示已获得满足契约的确定结果。
- `Rejected` 表示请求确定未执行或确定失败，可按策略修正或重试。
- `Unknown` 表示无法证明副作用是否发生；调用方 MUST NOT 当作失败重放。

`PortError` MUST 至少包含 `code`、`category`、`retryability`、`certainty`、`message_ref`、`provider_error_ref`、`observed_at` 和 `details_schema_ref`。错误正文不得包含凭证、未最小化敏感数据或完整 Prompt。

## 4. `RuntimeAdapter`

### 4.1 职责

`RuntimeAdapter` 把外部 Agent 运行时归一为 UEAF 的 Run、Turn、Checkpoint、Handoff 和流式事件语义。它不拥有 `RunRecord`；Runtime Domain 是唯一 State Writer。

### 4.2 最小端口

```text
DescribeRuntime() -> RuntimeCapabilities
StartRun(RuntimeStartRequest) -> RuntimeSession
AdvanceRun(RuntimeAdvanceRequest) -> RuntimeEventStream
SuspendRun(RuntimeSuspendRequest) -> RuntimeCheckpointRef
ResumeRun(RuntimeResumeRequest) -> RuntimeSession
CancelRun(RuntimeCancelRequest) -> RuntimeCancellationObservation
InspectRun(RuntimeInspectRequest) -> RuntimeObservation
```

`RuntimeStartCommand` 是模块 02 应用层的唯一启动命令，只能由 Run Coordinator 消费。Run Coordinator MUST 先验证命令绑定同一 `run_id` 的有效 `RunAdmissionResult.outcome=admitted`、当前 revision、租约、预算和冻结版本，再将它映射为适配器层 `RuntimeStartRequest`；应用命令不得直接传给 Adapter。

`RuntimeStartRequest` MUST 引用 `TaskEnvelope`、`RunRecord`、`ReleaseManifest`、`PrincipalContext` 和预算快照，并包含受限的 `RuntimeExecutionContext`。后者是仅在本次适配器会话中有效的能力上下文，至少绑定 tenant/run/release/trace、当前 revision、fencing token、deadline、取消句柄，以及 `ContextBuildPort`、`ModelStepPort`、`ToolIntentPort`、`HandoffPort` 和 `TelemetryPort` 五个句柄。适配器 MUST NOT 修改 `TaskEnvelope`；进度更新必须通过应用层写入 `TaskState`。

Runtime Domain MUST 只通过上述 `RuntimeExecutionContext` 向适配器授予能力。外部 Runtime 不得直接持有模型长期凭据、读取 UEAF Store 或连接企业工具；其模型步骤必须经模块 03，工具候选必须经 Tool Gateway。

### 4.3 归一规则

- 供应商线程、图实例或会话 ID MUST 作为外部引用保存，不得替代 `run_id`。
- 原生 interrupt、pause、waiting 和 checkpoint MUST 映射为 UEAF 明确状态；无法无损映射时 MUST 报告能力限制。
- 运行时输出只能形成模型/流程候选或规范 `RuntimeEvent`；只有模块 03 可在校验后签发 `StructuredDecision`。适配器不能直接提交 Run 终态或执行副作用。
- 原生工具调用 MUST 转换为 `ToolIntent` 并经过 Tool Gateway。
- 多 Agent 委派 MUST 转换为 `HandoffEnvelope`，不得共享隐式内存或扩大权限。
- 恢复 MUST 校验运行时版本、Checkpoint 完整性、`release_id` 和 fencing token。

### 4.4 必需能力声明

`RuntimeCapabilities` MUST 声明：流式、暂停/恢复、持久化检查点、人工中断、并行分支、确定性重放、原生工具调用、结构化输出、Handoff、取消确认、最大上下文/步骤和支持的 UEAF 契约版本。

## 5. `ModelProviderAdapter`

### 5.1 最小端口

```text
DescribeModels() -> ModelCapabilities[]
Invoke(ModelInvocation) -> ModelRunResult
InvokeStream(ModelInvocation) -> ModelStreamEvent[]
CancelModelInvocation(model_invocation_id, deadline_at) -> CancellationObservation
Estimate(ModelEstimateRequest) -> ModelEstimate
```

### 5.2 约束

- 适配器 MUST 只接收已完成 `PromptContract` 渲染、`ContextManifest` 装配和 `ModelRoute` 选择的 `ModelInvocation`。
- 供应商角色、工具调用、停止原因、用量、拒绝和错误 MUST 归一化。
- 流式与非流式路径 MUST 产生等价的最终 `ModelRunResult` 语义。
- 断流且无供应商终态时 MUST 返回 `unknown` 或明确失败，不得伪造 `final`。
- 结构化输出必须经过 UEAF Output Validator；供应商宣称 Schema 成功不是最终校验。
- 数据区域、保留、训练使用、日志策略和内容过滤能力 MUST 可发现并可被路由策略约束。

## 6. `ToolAdapter` 与 `MCPAdapter`

### 6.1 `ToolAdapter` 最小端口

```text
DescribeCapabilities() -> CapabilityDescriptor[]
Prepare(ToolExecutionRequest) -> PreparedAction
Execute(PreparedAction) -> ActionReceipt
QueryAction(ActionQuery) -> ActionReceipt
Compensate(CompensationRequest) -> ActionReceipt
Health(HealthRequest) -> AdapterHealth
```

`ToolExecutionRequest` MUST 引用 `ActionRecord`、`ToolIntent`、有效 `PolicyDecision`、必要的 `ApprovalRequest`、主体上下文、deadline 和幂等键。适配器 MUST 重算或验证动作指纹，不能信任模型提供的主体、租户、授权或凭证。

### 6.2 副作用规则

- 有副作用的能力 MUST 声明 `side_effect_class` 和幂等支持级别。
- `Prepare` MUST NOT 产生未声明的业务副作用。
- `Execute` 超时或连接丢失且动作可能发生时 MUST 返回未知观察，并触发对账。
- 自动重试只允许用于可证明未执行或由业务幂等键保护的调用。
- 补偿不是事务回滚；Action Coordinator MUST 先为补偿 `ToolIntent` 创建独立 `ActionRecord`，再调用 `Compensate`。ToolAdapter 只执行已授权的补偿请求并返回 `ActionReceipt`，不得创建权威动作记录。
- 结果 MUST 最小化为 `ToolResult`；完整业务事实仍由权威系统持有。

### 6.3 `MCPAdapter`

`MCPAdapter` 是 `ToolAdapter` 的受限实现，负责 MCP transport、能力发现和 Schema 转换。它 MUST：

- 固定 Server 身份、信任记录和允许版本；
- 将 tools/resources/prompts 分别映射为明确能力类别；
- 在能力发现结果进入 Registry 前完成 Schema、风险、权限、数据处理和供应链校验；
- 防止 Server 返回内容修改 `PrincipalContext`、Policy、Release 或系统指令；
- 对动态能力变化触发重新准入，不得在现有 Run 中静默扩权；
- 将 MCP 错误与断连归一为本规范错误类别；
- 禁止直接把 MCP Server 暴露给模型以绕过 Tool Gateway。

## 7. `IdentityAdapter`

### 7.1 最小端口

```text
Authenticate(CredentialPresentation) -> AuthenticatedSubject
ResolvePrincipal(PrincipalResolutionRequest) -> PrincipalContext
ExchangeDelegation(DelegationRequest) -> DelegationRef
CheckRevocation(RevocationQuery) -> RevocationStatus
ResolveAttributes(AttributeQuery) -> VerifiedAttributes
```

### 7.2 信任规则

- 只有 Trusted Admission Boundary MAY 调用身份适配器构造 `PrincipalContext`。
- 凭证 MUST 使用安全句柄或工作负载身份传递，不得进入 Prompt、事件或普通日志。
- 委托 MUST 缩小或保持权限、用途、资源范围和有效期，不得扩大。
- 缓存身份属性时 MUST 记录来源、获取时间、TTL 和撤销策略。
- 身份认证结果不得替代具体动作的 `PolicyDecision`。
- 租户、主体或委托不一致 MUST fail closed。

## 8. `StoragePort`

### 8.1 逻辑端口

```text
Load(type, id, tenant_id) -> VersionedObject
CompareAndSet(object, expected_revision) -> VersionedObject
AppendEvents(events, expected_sequence) -> CommitReceipt
SaveCheckpoint(checkpoint, fencing_token) -> CheckpointRef
PutArtifact(content_ref, policy) -> ArtifactRef
EnqueueOutbox(event_ref, transaction_ref) -> OutboxRef
AcquireLease(resource_ref, ttl) -> Lease
RenewLease(lease, fencing_token) -> Lease
```

### 8.2 一致性规则

- `TaskState`、`RunRecord` 和 `ActionRecord` 写入 MUST 使用 revision/sequence 并发控制。
- 权威状态与 outbox 事件 MUST 原子提交，或使用可证明等价机制。
- 跨租户键空间 MUST 物理或密码学隔离；所有查询 MUST 强制 tenant predicate。
- Checkpoint MUST 包含完整性证明和 fencing token，过期 lease 不得继续提交。
- 工件引用 MUST 绑定内容摘要、分类、保留、区域和加密策略。
- 存储端口不得把“写入副本成功”宣称为跨系统业务事务成功。

## 9. `TelemetryPort`

### 9.1 最小端口

```text
EmitTrace(TraceRecord) -> TelemetryAck
EmitMetric(MetricPoint[]) -> TelemetryAck
EmitLog(LogRecord[]) -> TelemetryAck
EmitAudit(AuditRecord) -> AuditCommitReceipt
```

### 9.2 规则

- Trace、Metric 和普通 Log 是可观测数据，不是权威领域事件。
- Audit 必须独立定义完整性、保留和访问控制；普通 Telemetry 丢失不得伪装为 Audit 已提交。
- 遥测失败 SHOULD 不阻断低风险业务，但高风险审计提交失败 MUST 按策略 fail closed 或进入明确等待态。
- 属性 MUST 包含 tenant、release、run、adapter 和结果分类，但不得包含明文凭证、完整 Prompt 或未最小化业务数据。
- 高基数字段 SHOULD 使用引用或受控标签，避免把正文作为 label。

## 10. 能力协商

每个适配器 MUST 暴露不可变、可签名的 `AdapterDescriptor`：

```text
adapter_id, adapter_version, adapter_kind,
contract_version_ranges, capabilities, limitations,
data_handling, regions, trust_record_ref,
configuration_schema_ref, health_profile,
deprecation, integrity_ref
```

协商流程：

1. Control Plane 验证适配器身份、完整性、信任记录和配置 Schema。
2. 对 `ReleaseManifest` 的必需能力与适配器声明取交集。
3. 对缺失能力执行显式替代、降级或拒绝；不得按方法存在推断语义等价。
4. 生成 `CapabilityBinding`，绑定适配器、能力版本、限制、环境和有效期。
5. 将绑定写入发布清单；Run 启动后冻结。

安全关键能力、状态终态、幂等等级、取消确认和数据处理不允许自动降级。协商失败 MUST 返回 `capability_mismatch`，并列出缺失或冲突项。

## 11. 超时、取消与重试

- deadline 从调用方单调递减传播；适配器 MAY 使用更短内部超时，不得延长外部 deadline。
- timeout 表示观察期限结束，不表示工作必然停止。
- cancel 是请求；只有收到可验证确认或查询到确定状态后，调用方才能认定取消生效。
- 重试预算 MUST 计入 Run 和子预算，并有指数退避、抖动和上限。
- 模型只读调用 MAY 按路由策略重试；副作用动作必须同时满足确定未执行或业务幂等保护。
- 重试尝试 MUST 保留同一业务幂等键，并使用不同 attempt/调用 ID。
- 熔断器打开时 MUST 返回 `temporarily_unavailable`，不得回退到不满足数据或安全要求的适配器。

## 12. 幂等与对账

幂等键作用域 MUST 至少包含 tenant、能力、规范化动作指纹和业务目标。相同键、不同规范化请求 MUST 返回 `idempotency_conflict`。

`ActionRecord` 出现未知观察时：

1. Tool Gateway 停止盲目重放；
2. 调用 `QueryAction` 或权威业务查询；
3. 记录新的 `ActionReceipt`；
4. 只有证据足够时才提交 succeeded/failed；
5. 对账耗尽仍未知时提交 unresolved，并阻止所属 Run 宣称 completed。

## 13. 版本与兼容性

- 端口与 DTO 使用语义化版本。
- 适配器 MUST 声明生产版本和接受范围；主版本不兼容必须拒绝或执行显式迁移。
- 新增可选字段 MAY 为次版本；改变字段含义、所有权、终态或默认值 MUST 增加主版本。
- 适配器升级必须形成新 `adapter_version`；运行中的 Run 继续使用冻结版本。
- 紧急撤销适配器时，受影响 Run MUST 安全暂停、迁移或终止，不能静默切换。
- 转换器 MUST 记录 source/target 版本、规则版本、有损字段和完整性引用。

## 14. 标准错误分类

| category | certainty | 默认处理 |
| --- | --- | --- |
| `invalid_request` | not_executed | 修正请求，不重试原请求 |
| `unauthenticated` / `unauthorized` | not_executed | fail closed；重新认证或重新授权 |
| `capability_mismatch` | not_executed | 重新路由或拒绝发布/运行 |
| `contract_incompatible` | not_executed | 显式迁移或拒绝 |
| `rate_limited` | not_executed/unknown | 遵守 retry-after；副作用需先确认 certainty |
| `temporarily_unavailable` | not_executed/unknown | 受预算重试或降级 |
| `deadline_exceeded` | unknown | 查询状态；禁止假定失败 |
| `provider_rejected` | not_executed | 按原因修正或停止 |
| `integrity_failed` | not_executed | fail closed；安全告警 |
| `idempotency_conflict` | not_executed | 人工/程序修复键冲突 |
| `data_policy_violation` | not_executed | fail closed；不得不合规回退 |
| `internal_error` | not_executed/unknown | 记录关联引用；按副作用等级处理 |

错误映射 MUST 保留供应商原始错误引用，但不能把供应商 HTTP 状态码直接当作 UEAF 业务终态。

## 15. 安全基线

所有适配器 MUST：

- 使用工作负载身份、短期凭证和最小权限；
- 验证出站目标、TLS、证书/服务身份和允许区域；
- 对输入输出执行 Schema、大小、内容类型和数据分类校验；
- 防止 SSRF、路径穿越、命令注入、Prompt 注入导致的权限提升和跨租户引用；
- 对插件、MCP Server、SDK 和镜像记录供应链来源、签名、SBOM 与漏洞状态；
- 在日志、Trace、错误和工件中执行脱敏与用途限制；
- 支持凭证轮换、适配器撤销、版本封禁和紧急熔断；
- 为高风险动作生成可验证审计引用。

任何来自模型、RAG、工具或下游 Agent 的身份、策略、租户和 Release 字段都视为不可信数据。

## 16. Conformance Test Kit

每种适配器 MUST 通过公共测试和类型专项测试。测试结果形成版本化 `AdapterConformanceReport`，并作为 `SecurityGateDecision` 与 `OperationalReadinessDecision` 的证据输入。

### 16.1 公共测试

- 契约版本协商、未知字段和主版本拒绝；
- tenant/principal/release 绑定与跨租户负例；
- deadline 传播、超时、取消竞态和熔断；
- 相同幂等键重放及冲突检测；
- 确定失败与 unknown 的区分；
- 敏感数据脱敏、出域和审计完整性；
- Trace 关联不影响权威状态；
- 适配器重启、重复交付和网络分区。

### 16.2 专项测试

| 适配器 | 必测场景 |
| --- | --- |
| Runtime | Checkpoint 恢复、原生工具拦截、Handoff 权限收缩、取消确认、流式归一 |
| Model Provider | Schema 拒绝、断流、用量缺失、内容拒绝、路由回退、数据区域 |
| Tool | 副作用超时、幂等重放、未知对账、补偿、结果最小化 |
| MCP | 动态能力漂移、恶意 Schema/内容、Server 身份变化、断连和越权尝试 |
| Identity | 撤销、委托缩权、时钟偏差、属性过期、租户错配 |
| Storage | CAS 冲突、outbox 原子性、lease fencing、恢复完整性、租户隔离 |
| Telemetry | 背压、采样、审计独立性、敏感属性、Collector 不可用 |

测试桩 MUST 支持故障注入；仅以 happy path 通过不得获得生产合规状态。

## 17. 适配器上线门槛

适配器进入生产前 MUST 满足：

1. `AdapterDescriptor`、配置 Schema、支持矩阵和限制已发布；
2. Conformance Test Kit 全部必需用例通过；
3. 威胁建模、供应链扫描和数据处理评审通过；
4. 超时、重试、熔断、限流和预算策略完成压测；
5. unknown、对账、取消竞态和恢复演练有证据；
6. 遥测、审计、告警、SLO 和 Runbook 可用；
7. 灰度、回滚、版本撤销和兼容迁移已演练；
8. `SecurityGateDecision`、`OperationalReadinessDecision` 和最终 `ReleaseDecision` 对指定版本有效。

## 18. 验收标准

- 核心域代码不依赖任何供应商 SDK 类型。
- 替换同类适配器不改变 `TaskEnvelope`、`TaskState`、`RunRecord`、`ActionRecord` 或治理决定语义。
- 所有 Run 可追溯到冻结的 adapter、contract、release 和 capability binding 版本。
- 所有副作用都经过 Policy、必要审批、幂等和收据/对账流程。
- timeout、断连和取消不会被错误归类为确定失败。
- MCP、模型或运行时原生工具不能绕过 Tool Gateway。
- 跨租户、版本不兼容、动态扩权、完整性失败和敏感数据泄漏均有自动化失败用例。
- 每个生产适配器均有可重复生成的 `AdapterConformanceReport` 和有效发布决定。
