# UEAF 统一术语与对象模型规范

版本：`0.1.0-draft`<br>
规范状态：Draft<br>
适用范围：UEAF 控制面、运行面、数据面、证据面及其所有适配器

## 1. 范围

本文规定统一企业 Agent 框架（UEAF）的规范用语、对象名称、标识关系、对象最小字段、所有权模型和跨信任边界的不变量。实现可以扩展对象字段，但不得改变本文规定的语义。

本文不规定数据库、消息中间件、Agent SDK、模型供应商、云平台或编程语言。

规范词含义如下：

- **MUST / MUST NOT**：实现必须满足，否则不具备 UEAF 核心兼容性。
- **SHOULD / SHOULD NOT**：默认必须满足；偏离时必须记录理由、风险、补偿控制和到期条件。
- **MAY**：可选能力，不影响核心兼容性。

## 2. 规范命名规则

### 2.1 Canonical Name

跨模块对象 MUST 使用本文给出的英文 PascalCase 名称作为 Canonical Name。中文名称只用于解释，不参与协议判定。供应商 SDK 类型、数据库表名和 UI 名称 MAY 不同，但适配器 MUST 显式映射到 Canonical Name。

以下名称是唯一规范名称：

| 语义 | Canonical Name | 禁止作为同义跨模块契约 |
| --- | --- | --- |
| 可信主体上下文 | `PrincipalContext` | UserContext、AuthContext |
| 准入不可变任务输入 | `TaskEnvelope` | TaskRequest、TaskRecord |
| 公开任务状态 | `TaskState` | TaskRecord、TaskAggregate |
| Run 准入聚合结果 | `RunAdmissionResult` | AdmissionDecision、AdmissionResult |
| 运行时授权决定 | `PolicyDecision` | GateDecision、AuthResult |
| 具体动作审批请求 | `ApprovalRequest` | Approval、ApprovalTicket |
| 动作权威记录 | `ActionRecord` | ActionAggregate、ActionState |
| 外部动作收据 | `ActionReceipt` | SideEffectReceipt、ActionLedger |
| 质量发布门判断 | `QualityGateDecision` | GateDecision |
| 安全发布门判断 | `SecurityGateDecision` | GateDecision |
| 运行就绪发布门判断 | `OperationalReadinessDecision` | GateDecision、SLODecision |
| 最终发布裁决 | `ReleaseDecision` | GateDecision、PublishDecision |
| 兼容发布版本集合 | `ReleaseManifest` | DeploymentBundle、VersionSet |

`GateDecision` MUST NOT 出现在新契约、事件、API 或持久化模型中。迁移适配器遇到旧 `GateDecision` 时，MUST 根据生产者域映射为上述四种对象之一；无法确定语义时 MUST 拒绝转换，不能按字段相似度猜测。

### 2.2 字段命名与枚举

- 线级字段名 MUST 使用 `snake_case`。
- 对象名 MUST 使用 PascalCase。
- 枚举线值 MUST 使用小写 `snake_case`。
- 时间 MUST 使用带时区的 RFC 3339 UTC 字符串。
- 持续时间 SHOULD 使用整数毫秒并以 `_ms` 结尾。
- 数量与金额 MUST 带单位或币种，不得使用无单位的 `cost`、`timeout`。
- 布尔值 SHOULD 使用肯定式名称，例如 `is_terminal`，不得用三态布尔值表达业务状态。

## 3. 核心概念边界

### 3.1 生命周期对象

| 概念 | 回答的问题 | 边界 |
| --- | --- | --- |
| Conversation | 哪组消息形成用户可理解的对话连续性 | 不等于任务、运行或长期记忆 |
| Session | 哪个短期交互窗口保持连接和临时状态 | 可跨多个 Run，也可在一个 Task 内重建 |
| Task | 哪个业务目标需要跨一次或多次 Run 完成 | 由确定性完成条件定义 |
| Run | 哪次有边界的 Agent 执行正在推进 Task | 必须绑定一个执行引擎和一个发布清单 |
| Turn | 哪次模型观察、决定和结果交换发生了什么 | 不等于用户对话轮次或工具调用 |
| Checkpoint | 从哪个运行位置可以安全恢复 | 不证明外部副作用未发生 |
| Working Context | 当前一次模型调用实际可见的临时视图 | 不是真相源，也不永久累加 |
| Memory | 哪些经治理的信息可以跨会话复用 | 不得覆盖业务事实或企业知识 |
| Business Fact | 权威业务系统当前确认的事实是什么 | 模型、摘要和记忆只能引用，不能直接覆盖 |
| Workspace | 文件、工件和执行环境的可恢复状态是什么 | 不等于消息历史、TaskState 或 Checkpoint |

### 3.2 证据、观测与审计

| 概念 | 目的 | 不得替代 |
| --- | --- | --- |
| Evidence | 支撑模型输入、结果或治理判断的带来源材料 | 业务事实写入 |
| Trace | 重建一次执行的因果与性能路径 | 合规审计账本 |
| Log | 诊断组件局部事件 | 权威状态记录 |
| Metric | 聚合观察趋势、容量和 SLO | 单次动作证据 |
| Audit | 证明谁在何时依据什么执行了什么 | 调试全文日志 |
| Eval | 对版本化结果、轨迹、安全和性能作出评价 | 运行时授权 |

## 4. 所有权模型

每个规范对象 MUST 明确以下四种角色；四者不得用“服务拥有数据”一句话混为一谈。

| 角色 | 定义 | 规范要求 |
| --- | --- | --- |
| Semantic Owner | 定义对象含义、不变量、允许状态和演进策略的唯一责任域 | 每个 Canonical Name MUST 恰有一个 Semantic Owner |
| State Writer | 接受命令、校验并提交该对象权威状态变化的逻辑写入者 | 每个聚合实例在任一时刻 MUST 只有一个有效写入权；多副本必须使用租约、CAS 或 fencing token |
| Physical Store | 保存权威记录、事件或快照的物理技术 | MAY 更换或多副本部署；不得借存储位置取得语义所有权 |
| Projection | 从权威事件或对象派生的查询视图、索引、缓存或分析副本 | MUST 标记来源位置和新鲜度；MUST NOT 接受权威状态命令或判定终态 |

示例：Run 域是 `RunRecord` 的 Semantic Owner；Run Coordinator 是 State Writer；PostgreSQL MAY 是 Physical Store；运营控制台中的 Run 列表是 Projection。更换 PostgreSQL 不改变语义所有权，控制台显示 `completed` 也不能替代 Run Coordinator 提交终态。

### 4.1 所有权总表

| 对象 | Semantic Owner | State Writer | 典型 Physical Store | 典型 Projection |
| --- | --- | --- | --- | --- |
| `PrincipalContext` | Identity & Delegation | Trusted Admission Boundary | 短期安全上下文存储 | 审计身份视图 |
| `TaskState` | Task Domain | Task State Service | 事务数据库/事件存储 | 任务列表、搜索索引 |
| `RunRecord` | Runtime Domain | Run Coordinator | 事务数据库/事件存储 | 运行控制台、指标维度 |
| `Checkpoint` | Recovery Domain | Recovery Manager | Checkpoint Store | 可恢复点目录 |
| `ContextManifest` | Context Domain | Context Builder | Artifact/Metadata Store | 上下文诊断视图 |
| `EvidencePack` | Evidence Domain | Evidence Service | Evidence Store | 引用索引 |
| `MemoryRecord` | Memory Domain | Memory Service | Governed Memory Store | 向量/关键词索引 |
| `PolicyDecision` | Policy Domain | Policy Decision Point | 决策日志存储 | 安全分析视图 |
| `ApprovalRequest` | Approval Domain | Approval Service | 审批事务存储 | 审批工作台 |
| `ActionRecord` | Action Domain | Tool Gateway/Action Coordinator | 事务数据库/事件存储 | 动作清单、对账视图 |
| `ActionReceipt` | Action Domain | Tool Gateway/Action Executor | Action Ledger | 对账和运营视图 |
| 四类发布决定 | 对应治理域 | 对应 Gate Service | Evidence Store | 发布看板 |
| `ReleaseManifest` | Release Control | Release Controller | 配置/制品注册表 | 部署状态视图 |

## 5. 公共元数据

所有跨模块持久化对象 MUST 包含 `meta`，其规范类型为 `ContractMeta`。

| 字段 | 类型 | 必需 | 规则 |
| --- | --- | ---: | --- |
| `contract_name` | string | 是 | 等于对象 Canonical Name |
| `contract_version` | semver string | 是 | 线级 Schema 版本，不是实现版本 |
| `object_id` | string | 是 | 在 `tenant_id + contract_name` 范围内唯一 |
| `tenant_id` | string | 是 | 来自可信边界；跨租户共享对象须使用专用系统租户和显式策略 |
| `created_at` | timestamp | 是 | 首次提交时间，不可改写 |
| `producer` | string | 是 | 逻辑生产者标识 |
| `producer_version` | string | 是 | 可复现生产逻辑的版本 |
| `classification` | enum | 是 | `public/internal/confidential/restricted` 或组织批准的兼容扩展 |
| `purpose` | string[] | 是 | 允许处理目的；空集合表示不可消费 |
| `provenance` | `ProvenanceRef[]` | 是 | 原始来源或派生链；原生对象也必须说明来源边界 |
| `integrity_ref` | string | 条件 | 审批、动作、治理决定和发布清单 MUST 提供 |
| `expires_at` | timestamp/null | 条件 | 有效期对象 MUST 提供；`null` 不代表无限保留 |
| `extensions` | object | 否 | 扩展键 MUST 使用反向域名前缀；不得覆盖规范字段 |

`ContractMeta` SHOULD 包含 `request_id`、`task_id`、`run_id`、`turn_id`、`trace_id`、`release_id` 等实际存在的关联引用。实现 MUST NOT 伪造不存在的关联，也不得用一个 ID 填充所有字段。

## 6. 标识关系

| 标识 | 基数和作用域 | 生成者 | 不得替代 |
| --- | --- | --- | --- |
| `tenant_id` | 所有受租户约束对象 | Trusted Admission Boundary | `principal_id` |
| `principal_id` | 一个经认证的用户、服务或工作负载 | Identity Provider/Mapper | `agent_id` |
| `request_id` | 一次外部接入 | Agent Gateway | `task_id` |
| `conversation_id` | 一段对话连续性 | Conversation Service | `task_id`、`memory_id` |
| `session_id` | 一个活动交互窗口 | Session Manager | `run_id` |
| `task_id` | 一个业务目标 | Task Service | `run_id` |
| `run_id` | 一次执行 | Run Coordinator | `thread_id`、`turn_id` |
| `turn_id` | 一次模型交换 | Agent Loop | `tool_call_id` |
| `checkpoint_id` | 一个可恢复快照 | Recovery Manager | `run_id` |
| `evidence_pack_id` | 一组授权证据 | Evidence Service | 文档 ID |
| `action_key` | 一个逻辑副作用的幂等身份 | Tool Gateway | `tool_call_id` |
| `trace_id` | 一条观测因果链 | Telemetry Boundary | 审计事件 ID |
| `release_id` | 一个获准的版本集合 | Release Controller | `agent_version` |

标识 MUST 由确定性系统生成并通过可信字段传播。模型输出 MAY 引用标识，但 MUST NOT 创建或重绑定 `tenant_id`、`principal_id`、`action_key`、`release_id`。

## 7. 身份与接入对象

### 7.1 `PrincipalContext`

表示一次请求或动作的可信组合安全上下文。

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `meta` | `ContractMeta` | MUST |
| `principal_id` | string | MUST |
| `principal_type` | enum | `end_user/calling_service/agent/workload/human_approver` |
| `tenant_id` | string | MUST 与 `meta.tenant_id` 相同 |
| `roles` | string[] | MUST 来自可信目录或策略映射 |
| `scopes` | string[] | MUST 为有效委托交集，不得取参与方权限并集 |
| `delegation_chain` | `DelegationRef[]` | MUST；无委托时为空数组 |
| `authentication_strength` | string | MUST |
| `credential_ref` | opaque ref/null | MAY；不得包含明文凭证 |
| `data_regions` | string[] | SHOULD |
| `consent_refs` | string[] | 条件必需 |
| `issued_at` / `expires_at` | timestamp | MUST |
| `revocation_ref` | string/null | SHOULD |

不变量：

- 只有 Trusted Admission Boundary MAY 构造 `PrincipalContext`。
- 模型、Prompt、RAG 内容、工具参数和下游 Agent MUST NOT 修改它。
- 每次高风险动作执行前 MUST 验证有效期、撤销状态、委托范围和当前资源属性。
- 身份认证成功不等于动作授权成功；后者只能由 `PolicyDecision` 表达。

### 7.2 `RequestEnvelope`

最小字段：`meta`、`request_id`、`channel`、`protocol`、`input_ref` 或受限 `input`、`client_correlation_id`、`received_at`、`deadline_at`、`principal_context_ref`、`validation_status`。原始请求 MUST 可追溯；规范化不得覆盖原始证据。

### 7.3 `TaskEnvelope` 与 `BudgetEnvelope`

`TaskEnvelope` 是准入边界产生的不可变任务输入，MUST 包含 `task_id`、`request_refs`、`goal`、`completion_criteria`、`constraints`、`risk_class`、`owner_ref`、`budget_ref` 和 `revision`。任何已发布实例 MUST NOT 原地修改；目标或完成条件改变 MUST 形成新的 `TaskEnvelope` revision，并记录可追溯事件。运行期间的公开任务进度只能写入 `TaskState`，不得回写 `TaskEnvelope`。

`BudgetEnvelope` MUST 分别声明时间、模型 Token、费用、步骤、工具调用、并发和子任务预算；未设置的维度 MUST 明确为 `unbounded_by_contract` 或组织默认值，不能以缺字段表示无限。所有子预算之和 MUST NOT 静默超出父预算。

`RunAdmissionResult` 是已存在 `RunRecord` 的 Run 级准入聚合结果，MUST 绑定 `run_id`。它不用于边缘请求的认证、协议和基础 Schema 预校验；规范字段、结果和转换见[状态机与终态规范](02-状态机与终态规范.md)。`AdmissionDecision` MUST NOT 作为新契约名。

## 8. 定义、配置与发布对象

### 8.1 `AgentDefinition`

最小字段：`agent_id`、`agent_version`、`owner`、`purpose`、`input_contract`、`output_contract`、`completion_contract`、`runtime_profile`、`capability_refs`、`prompt_contract_ref`、`policy_refs`、`risk_class`、`budget_defaults`、`compatibility`、`deprecation`。

版本 MUST 不可变；修改任何可观察行为 SHOULD 产生新版本。

### 8.2 `CapabilityDescriptor`

最小字段：`capability_id`、`capability_version`、`kind`、`input_schema_ref`、`output_schema_ref`、`risk_class`、`side_effect_class`、`trust_record_ref`、`auth_requirements`、`idempotency_support`、`timeout_profile`、`data_handling`、`lifecycle_status`。

能力可被发现不等于主体获准执行；`CapabilityDescriptor` MUST NOT 携带某次调用的授权结果。

### 8.3 `PromptContract`、`ModelRoute`、`ReleaseManifest`

`PromptContract` MUST 绑定指令版本、变量 Schema、输出 Schema、证据规则、拒绝规则和信任分区规则。Prompt 文本与 Schema MUST 能共同复现。

`ModelRoute` MUST 表达能力要求、允许供应商与模型版本、回退序列、数据区域、成本/延迟预算和风险限制。供应商原生响应对象不得作为 UEAF 跨模块契约。

`ReleaseManifest` MUST 至少包含：

- `release_id`、环境与生命周期状态；
- `agent_versions`、`prompt_versions`、`schema_versions`；
- `model_route_versions`、`capability_versions`、`adapter_versions`；
- `knowledge_index_versions`、`memory_policy_versions`、`policy_versions`；
- UEAF 契约版本范围和迁移引用；
- `quality_gate_decision_ref`、`security_gate_decision_ref`、`operational_readiness_decision_ref`、`release_decision_ref`；
- 灰度、回滚、观察窗口和完整性证明。

运行 MUST 冻结一个 `release_id`。恢复长运行任务时，原清单不可用则 MUST 显式迁移或安全终止，不得静默加载“最新版本”。

## 9. 运行、上下文与状态对象

### 9.1 `RunRecord`

最小字段：`run_id`、`task_id`、`agent_ref`、`runtime_adapter_ref`、`release_id`、`phase`、`completion_disposition`、`wait_reason`、`attempt`、`budget_snapshot`、`checkpoint_ref`、`pending_action_refs`、`result_ref`、`error_ref`、`revision`、`created_at`、`updated_at`。

`phase` 使用 `RunPhase`；`completion_disposition` 使用 `CompletionDisposition`。两者 MUST 正交，详细状态规范见[状态机与终态规范](02-状态机与终态规范.md)。

### 9.2 `TurnRecord`、`TaskState` 与 `Checkpoint`

`TurnRecord` MUST 记录 `turn_id`、输入 `context_manifest_ref`、Prompt/Schema/Model 版本、归一化模型事件、工具意图引用、用量、停止原因和终态。流式与非流式路径 MUST 归一为相同终态语义。

`TaskState` 是任务域对其他模块公开的可变状态对象，MUST 只保存确定性任务进度、已确认事实、未决条件、完成条件状态和 revision。模型摘要只能作为带来源的派生字段，MUST NOT 覆盖确认事实。`TaskState` MUST NOT 被命名为 `TaskRecord` 或 `TaskAggregate`；后者仅可作为实现模式描述。

`Checkpoint` MUST 包含运行位置、状态引用、待处理条件、运行时原生检查点引用、冻结版本、并发 token、在途动作引用和完整性证明。Checkpoint 可恢复性不代表外部动作可重复。

### 9.3 `ContextManifest`

最小字段：`context_manifest_id`、`run_id`、`turn_id`、`sections`、`source_refs`、`policy_snapshot_ref`、`budget_before`、`budget_after`、`selection_decisions`、`omissions`、`compression_records`、`trust_labels`、`integrity_ref`。

每个上下文片段 MUST 可追溯到来源、版本、主体/作用域、用途、信任级别和选择或排除原因。`ContextManifest` 是本次调用的清单，不是正文副本或长期状态。

### 9.4 `WorkspaceSnapshot`

最小字段：`workspace_snapshot_id`、`workspace_id`、`base_snapshot_ref`、`artifact_refs`、`environment_descriptor`、`change_set_ref`、`integrity_ref`、`retention_policy_ref`。它 MUST NOT 被当作 Conversation、TaskState、MemoryRecord 或 Run Checkpoint。

## 10. 知识与记忆对象

### 10.1 `EvidencePack`

最小字段：`evidence_pack_id`、`query_intent_ref`、`principal_context_ref`、`items`、`authorization_proof_refs`、`source_versions`、`coverage`、`conflicts`、`freshness`、`expires_at`、`selection_policy_ref`。

每个 `items[]` MUST 包含来源、版本、位置、内容引用或最小片段、权限范围、信任标签和引用句柄。权限过滤 MUST 先于相关性排序。EvidencePack 只证明哪些材料获准进入当前任务，不证明模型正确使用材料。

### 10.2 `MemoryCandidate` 与 `MemoryRecord`

`MemoryCandidate` 是待验证候选，MUST 包含主体、来源、用途、敏感度、候选内容、置信度和所需同意。它不得被直接召回为长期记忆。

`MemoryRecord` MUST 包含 `subject_ref`、`scope`、`source_refs`、`statement` 或内容引用、`confidence`、`consent_ref`、`valid_from`、`expires_at`、`status`、`supersedes_ref`、`deletion_state` 和 `use_audit_policy_ref`。Memory Service 只能从通过治理的候选或权威同步生成它。

### 10.3 `BusinessFactRef`

必须包含 `system_of_record`、`resource_type`、`resource_id`、`fact_version`、`observed_at`、`authorization_scope` 和可选 `snapshot_ref`。模型输出、ContextManifest、EvidencePack 和 MemoryRecord 均不得覆盖 `BusinessFactRef` 指向的权威事实。

## 11. 动作与运行时治理对象

### 11.1 `ToolIntent`

最小字段：`tool_intent_id`、`run_id`、`turn_id`、`capability_ref`、`arguments`、`argument_provenance`、`purpose`、`target_resource_hints`、`risk_hint`、`requested_by`、`proposal_hash`。

它只是候选动作。`arguments` 中出现的租户、主体、授权或凭证字段 MUST 被忽略或拒绝；服务端使用 `PrincipalContext` 重新绑定。

### 11.2 `PolicyDecision`

`PolicyDecision` 只表示运行时主体—动作—资源—环境授权，MUST NOT 表示质量、安全发布门或最终发布。

最小字段：`policy_decision_id`、`principal_context_ref`、`action`、`resource`、`environment`、`outcome`、`constraints`、`reason_codes`、`policy_versions`、`evaluated_at`、`expires_at`、`input_hash`。`outcome` 只能为 `allow/deny/require_approval`。

### 11.3 `ApprovalRequest`

最小字段：`approval_request_id`、`action_fingerprint`、`tool_intent_ref`、`principal_context_ref`、`policy_decision_ref`、`approver_policy`、`status`、`decision`、`decision_reason`、`decided_by`、`created_at`、`expires_at`、`revision`。

审批 MUST 绑定主体、租户、能力版本、目标资源和规范化参数的动作指纹。任何绑定字段变化都使旧审批失效。

### 11.4 `ActionRecord`

`ActionRecord` 是动作域的线级、事件级与持久化权威对象，MUST 包含 `action_id`、`action_key`、`action_fingerprint`、`tool_intent_ref`、`run_id`、`capability_ref`、`phase`、`disposition`、`policy_decision_ref`、`approval_request_ref`、`latest_receipt_ref`、`attempt`、`reconciliation_state`、`revision`、`created_at` 和 `updated_at`。`ActionAggregate` 只可表示模块内部的聚合实现模式，MUST NOT 出现在跨模块 API、事件 Schema 或持久化公共模型中。

### 11.5 `ActionReceipt`

最小字段：`action_receipt_id`、`action_key`、`action_fingerprint`、`tool_intent_ref`、`policy_decision_ref`、`approval_request_ref`、`capability_ref`、`executor_ref`、`status`、`attempt`、`started_at`、`finished_at`、`external_reference`、`result_digest`、`error`、`reconciliation`、`integrity_ref`。

`status` MUST 区分 `succeeded/failed/unknown`；处于执行协调阶段的内部状态详见状态规范。超时、连接断开和响应丢失 MUST NOT 自动映射为 `failed`。当外部副作用可能已发生时 MUST 记录 `unknown` 并进入对账。

## 12. 评测与发布治理对象

### 12.1 `EvalResult`

必须绑定候选版本集合、基线版本集合、数据集与切片版本、运行环境、评分器及校准版本、结果指标、轨迹指标、样本证据、不确定性、污染检测和仪器健康状态。仪器失败 MUST 与候选质量失败分开表达。

### 12.2 四类决定

| 对象 | 唯一语义 | 必需输入 | 合法 outcome |
| --- | --- | --- | --- |
| `QualityGateDecision` | 候选在质量和任务效果上是否满足发布门 | `EvalResult`、质量策略、基线比较 | `pass/conditional/fail` |
| `SecurityGateDecision` | 候选在安全、权限、隐私和供应链上是否满足发布门 | 安全回归、威胁评估、例外 | `pass/conditional/fail` |
| `OperationalReadinessDecision` | 容量、SLO、成本、恢复、灰度、回滚和运维能力是否就绪 | 负载/演练/SLO 证据 | `pass/conditional/fail` |
| `ReleaseDecision` | 在前三类独立决定基础上是否批准指定清单进入指定环境 | 三类决定、职责分离、变更窗口 | `approved/conditional/rejected` |

上述对象 MUST 包含候选版本集合、适用环境/范围、证据引用、策略版本、决定者、决定时间、有效期、条件/例外、撤销状态和完整性证明。前三类决定 MUST 由各自语义所有者独立生成；`ReleaseDecision` 不得把缺失的决定默认为通过。

## 13. 版本与兼容性

1. 契约版本 MUST 使用语义化版本；主版本变化表示消费者必须显式迁移。
2. 新增可选字段、枚举开放扩展点或更严格的非破坏性校验 MAY 增加次版本。
3. 删除字段、改变字段含义、改变默认值、收窄合法枚举、改变终态或所有权 MUST 增加主版本。
4. 生产者 MUST 声明生成版本；消费者 MUST 声明可接受版本范围。
5. `extensions` 中未知字段 SHOULD 保留转发；规范对象顶层未知字段 MUST 按契约策略处理，不得静默解释。
6. 安全关键字段、租户字段、动作指纹、有效期、来源和完整性引用不得在降级转换中丢弃。
7. 适配器转换 MUST 记录源类型、源版本、目标版本、转换规则版本和有损字段。
8. 长运行 Run MUST 冻结契约和 ReleaseManifest；跨主版本恢复必须执行可审计迁移。

## 14. 失败语义

所有对象校验失败 MUST 返回结构化 `ProblemDetail`，至少包含 `code`、`category`、`message_safe`、`retryability`、`object_ref`、`field_paths`、`correlation_refs` 和 `cause_ref`。

| 类别 | 示例 | 默认处理 |
| --- | --- | --- |
| `contract_invalid` | 必需字段缺失、Schema 不匹配 | 拒绝接纳；不得写入权威状态 |
| `identity_untrusted` | Principal 来源不可信或已撤销 | 失败关闭；记录安全审计 |
| `tenant_mismatch` | 关联对象跨租户 | 失败关闭；不得返回另一租户存在性信息 |
| `version_incompatible` | 无契约兼容交集 | 不调度；要求升级或显式迁移 |
| `integrity_failed` | 指纹、签名或哈希不一致 | 隔离对象；禁止高风险动作和发布 |
| `stale_projection` | 查询投影不满足新鲜度 | 回读权威存储或明确返回陈旧；不得提交终态 |
| `ownership_violation` | 非 State Writer 试图修改权威记录 | 拒绝写入并审计 |
| `semantic_ambiguous` | 旧 GateDecision 无法确定语义 | 拒绝转换；人工迁移 |

错误文本 MUST NOT 泄漏凭证、跨租户资源存在性、内部策略全文或受限内容。可重试性 MUST 由错误代码与操作幂等属性共同决定，不能仅由 HTTP 状态码决定。

## 15. 验收条件

实现通过本规范验收必须满足：

- 所有跨模块对象均使用 Canonical Name 和 `ContractMeta`。
- 代码、Schema、事件和持久化模型中不存在新建的 `GateDecision` 泛型契约。
- `PolicyDecision` 只用于运行时授权，四类发布决定分别建模。
- `ApprovalRequest`、`ActionReceipt`、`ReleaseManifest` 各只有一个规范名称。
- `RunRecord.phase` 与 `completion_disposition` 为两个独立字段；非终态不得填写 disposition。
- 每个权威对象均能指出唯一 Semantic Owner、有效 State Writer、Physical Store 和 Projection。
- Projection 无法直接提交权威状态或终态。
- Principal、租户、动作指纹、版本、来源和完整性字段不能被模型或适配器覆盖。
- 同一输入对象在支持的序列化格式间往返后，规范字段语义保持一致。
- 不兼容版本、跨租户引用、完整性失败和旧 GateDecision 歧义均有自动化失败用例。
