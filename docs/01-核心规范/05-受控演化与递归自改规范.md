# UEAF 受控演化与递归自改规范

版本：`0.2.0-draft`  
规范状态：Draft  
Architecture Generation: `V1`  
Maturity: `Required`  
Implementation: `Current`

## 1. 范围

本文定义 UEAF V1 的 **Controlled Evolution Kernel**。目标是让真实生产证据可以触发一次有预算、可停止、可审计的改进循环，同时避免把 V2/V3 的生态、Population、Meta Evolution 复杂度带入当前实现。

V1 必须满足：

```text
Production Evidence
  -> EvolutionTrigger
  -> EvolutionRun
  -> sparse MutationProposal
  -> GenomeManifest candidate
  -> existing ReleaseCandidate
  -> existing Eval / Security / Operational Gates
  -> ReleaseDecision / ReleaseManifest
```

本文是既有核心规范的扩展。身份、任务、运行、预算、事件、Eval、发布、审计和 Tool Gateway 仍由既有语义所有者负责。

## 2. V1 核心原则

1. **进化只产生候选，不修改当前运行体。** 当前 `ReleaseManifest` 不得原地自改。
2. **最小语义表面积。** V1 不为未来可能需要的概念提前建设独立 Canonical Object。
3. **事件驱动。** 没有有效 `EvolutionTrigger` 时，不为每个生产任务追加演化模型调用。
4. **Sparse Mutation 优先。** 只修改证据指向的最小有效范围。
5. **Evaluator 优先确定性。** 能由程序或统计验证的维度不默认交给强模型 Judge。
6. **能力与成本共同评估。** Token、费用、延迟、复杂度、回归和安全都必须进入现有 Eval/Gate 证据。
7. **经验上下文有界。** 历史可增长，但单次 EvolutionRun 的 Active Working Set 必须有上限。
8. **实验自治与生产晋升分离。** Observe、Propose、Experiment、Promote 是独立权限。
9. **递归存在硬边界。** Governance Kernel 不属于 V1 mutable surface。
10. **搜索算法可替换。** Genetic Algorithm 只是可选 Strategy，不定义 UEAF Evolution。

## 3. V1 Canonical Object

V1 Evolution Kernel 只新增五个一等规范对象。

### 3.1 `EvolutionTrigger`

回答“为什么现在值得启动一次演化”。它是触发事实，不是改动结论。

```yaml
evolution_trigger_id: string
subject_ref: string
trigger_type: anomaly | failure_cluster | cost_drift | quality_drift | new_model | new_tool | business_change | scheduled_review | human_request
window_ref: string
evidence_refs: [string]
threshold_profile_ref: string
severity: low | medium | high | critical
observed_at: timestamp
expires_at: timestamp
```

低置信单次异常 SHOULD 聚合后再触发。普通 Trace、Metric 或 Log 不能自行成为 Trigger；必须由 Trigger Owner 按版本化阈值形成权威对象。

### 3.2 `EvolutionRun`

表示一次有限的演化生命周期。

最小字段：

```yaml
evolution_run_id: string
subject_ref: string
baseline_genome_ref: string
trigger_ref: string
phase: string
disposition: string | null
budget_ref: string
mutable_scope: [string]
strategy_ref: string
active_working_set_ref: string
revision: integer
created_at: timestamp
updated_at: timestamp
```

`budget_ref` MUST 指向现有 Budget Domain 中专用于本次演化的预算切片；V1 不建立第二套独立预算真相源。

### 3.3 `GenomeManifest`

`GenomeManifest` 是 V1 唯一的 Genome 生命周期对象。Agent、Skill、Tool、Workflow 或 Strategy 不分别拥有新的基础 Genome 状态机。

```yaml
genome_id: string
subject_type: agent | skill | tool | workflow | strategy
subject_ref: string
profile_ref: string
component_refs: [string]
parent_refs: [string]
provenance_refs: [string]
created_from_mutation_ref: string | null
integrity_ref: string
```

规则：

- Genome 是不可变、内容可验证的候选能力描述；
- 不同 `subject_type` 通过 `profile_ref` 定义必需组件和兼容规则；
- 改变任一组成引用必须产生新的 `genome_id`；
- Genome 只引用已注册工件，不复制完整 Prompt、Tool Code、Workflow 或 Memory 内容；
- Governance Kernel 不得进入 Genome 作为普通 Gene。

### 3.4 `MutationProposal`

记录“改什么、为什么改、允许改到哪里”。

```yaml
mutation_proposal_id: string
subject_ref: string
baseline_genome_ref: string
trigger_ref: string
evidence_refs: [string]
strategy_ref: string
mutation_type: modify | add | remove | replace | transfer
mutable_scope: [string]
change_summary: object
hypothesis: string
expected_gain: object
expected_cost: object
risk_refs: [string]
created_by: string
created_at: timestamp
```

`transfer` 在 V1 只表示“复用一个已注册能力工件”的 Mutation 类型；它不要求建设 V2 Gene Pool 或独立 CapabilityTransfer 生命周期。

### 3.5 `EvolutionAuthorityPolicy`

定义 AI 对各类 mutable target 能执行哪一种演化行为。

```yaml
evolution_authority_policy_id: string
defaults:
  observe: allow
  propose: allow
  experiment: allow
  promote: risk_based
targets: object
policy_version: string
issued_by: string
integrity_ref: string
```

必须分别表达：

```text
Observe     读取被授权证据与版本信息
Propose     创建 MutationProposal
Experiment  在隔离环境构建和评测候选
Promote     将已通过独立门禁的候选推进到 Canary / Production
```

不得使用单一 `can_modify=true` 代替四级权限。

## 4. V1 必须复用的既有对象

为了防止语义膨胀，以下能力不得在 V1 新建第二套权威对象。

| 演化需要 | V1 复用 |
|---|---|
| Candidate | 模块 10 `ReleaseCandidate` |
| Eval 配置 | 模块 08 `EvalConfig` |
| Eval 执行 | 模块 08 `EvalRun` |
| Eval 事实 | 模块 08 `EvalResult` / `EvalEvidenceGraph` |
| Quality / Security / Operational Gate | 模块 08 / 07 / 09 既有门禁 |
| Budget | 现有 BudgetEnvelope / Budget Ledger / budget slice |
| 发布 | `ReleaseDecision` / `ReleaseManifest` |
| 工件 | Artifact / Registry |
| 运行证据 | Trace / Metric / Log / Audit / Action / SLO 原始域 |

因此 V1 不再定义 `CandidateRelease`、`EvaluationSuite`、`EvolutionBudget` 作为独立 Canonical Object。

## 5. V1 非 Canonical 概念

以下概念可以实现，但默认是内部记录、Projection、Registry metadata 或 Eval dimension：

### 5.1 Experience / Lesson

- 原始 Trace/Metric/Log/Eval/Action 不复制进 Evolution Store；
- 实现 MAY 保存结构化 Pattern、Experience、Lesson 记录；
- 它们不是 V1 跨模块公共契约；
- 已被 Tool/Policy/Workflow/Skill 吸收的 Lesson SHOULD 退出 Active Working Set。

### 5.2 Fitness

V1 不创建独立 `FitnessRecord` 真相源。

Candidate Selection 通过读取 `EvalResult`、成本、延迟、安全和回归证据形成比较视图；该视图 MAY 被物化为 Projection，但不得覆盖原始 Eval 事实。

### 5.3 Lineage

V1 不维护独立 `LineageGraph` 权威状态。

Lineage 由以下引用构建：

```text
GenomeManifest.parent_refs
MutationProposal
ReleaseCandidate
Eval refs
ReleaseManifest
Event history
```

需要图查询时生成 Projection。

### 5.4 Species / Gene Pool / Diversity

V1 仅允许用标签、Registry metadata、兼容信息或 Eval dimension 表达，不建设独立 Species/GenePool/Diversity Domain。它们属于 V2 Planned。

## 6. EvolutionRun 状态机

### 6.1 `EvolutionPhase`

```text
queued | collecting | analyzing | generating | evaluating | selecting | waiting | terminal
```

### 6.2 `EvolutionDisposition`

仅 `phase=terminal` 时非空：

```text
improved
plateau
budget_exhausted
no_valid_candidate
regression
safety_blocked
novelty_exhausted
manual_stop
failed
```

`improved` 只表示本轮找到至少一个满足既定比较标准的候选，不表示该候选已获生产发布。生产状态仍以 `ReleaseManifest` 为准。

## 7. 停止条件

每个 EvolutionRun MUST 绑定预算上限，并至少配置以下停止条件中的两类：

- fitness/quality target reached；
- improvement plateau；
- budget exhausted；
- max candidates / generations；
- no valid candidate；
- regression guard；
- safety blocked；
- novelty exhausted；
- manual stop。

预算耗尽是正常结束原因，不自动表示技术失败。

## 8. Active Evolution Working Set

单次 EvolutionRun 只装入：

- 当前 Trigger；
- 与当前 mutable scope 相关的最小证据摘要；
- baseline GenomeManifest；
- 少量相似成功/失败实验引用；
- 必要的 Eval/Governance 约束引用。

必须限制：

- 最大条目数；
- 最大 Token；
- 最大时间窗或相关性阈值；
- superseded / duplicate 排除；
- Archive / Cold Store 策略。

历史总量与模型 Active Context 必须解耦。

## 9. Evaluator 与 Candidate Funnel

默认顺序：

```text
Schema / Contract Check
  -> Deterministic Eval
  -> Statistical Eval
  -> Regression / Security Hard Checks
  -> Cheap Model Judge if needed
  -> Strong Model Judge if needed
  -> Human Review if needed
  -> Release Gates
```

发生确定性 hard failure 后，默认不继续消耗更昂贵 Judge Token。

V1 不要求对每个 Candidate 做全生态评测；Ecosystem Fitness 属于 V2。V1 只要求把直接可观测的共享资源成本、fan-out、延迟和回归纳入现有 Eval。

## 10. Evolution Strategy

V1 Strategy Registry MAY 支持：

- `llm_guided_sparse_mutation`；
- `genetic_search`；
- `bayesian_optimization`；
- `self_reflection`；
- `workflow_topology_search`；
- `tool_creation_search`；
- `human_guided`。

V1 默认推荐 `llm_guided_sparse_mutation` 或其他局部搜索；Population Search、生态级 Evolution 和 Meta Evolution 不属于 V1 Required。

## 11. Governance Kernel

以下能力不属于 V1 mutable surface：

- tenant / identity / delegation root；
- PDP/PEP 与权限模型；
- Tool Gateway enforcement；
- Secret/Credential 管理；
- Audit 完整性和保留；
- Eval holdout / threshold root / Judge 权限边界；
- Release Authority；
- Budget Enforcement；
- 数据删除、法律保留与 kill switch。

改变 Governance Kernel 必须走独立治理变更，不属于同一自动递归链。

## 12. Minimum Semantic Surface

任何新增 Evolution Canonical Object 的提案 MUST 先证明：

1. 有独立生命周期；
2. 需要独立 Semantic Owner；
3. 有独立状态迁移或并发控制；
4. 必须跨模块形成稳定契约；
5. 现有对象 + ref、Projection、Registry metadata 或 Eval dimension 无法表达。

不能证明时，必须优先降级，而不是新增 `XXXRecord / XXXManifest / XXXPolicy / XXXGenome`。

## 13. V2/V3 延后能力

以下内容保留在未来架构文档中，但不是 V1 实施或验收要求：

### V2 Planned

- Species / Population / Elite；
- Gene Pool；
- Capability Transfer 正式生命周期；
- Local + Ecosystem Fitness；
- Diversity / Monoculture Risk；
- 生态级资源归因与 Funnel Evaluation。

### V3 Research

- Meta Evolution；
- Dynamic Species / Niche；
- Ecosystem Topology Evolution；
- Pareto Frontier；
- Evolution Debt / Systemic Risk 模型；
- ModelEvolutionPort。

详细代际边界见 `docs/00-总览/06-UEAF架构代际与实施范围.md`。

## 14. V1 不变量

1. 当前 Release 永不被原地自改；
2. Candidate 最终仍使用既有 ReleaseCandidate / Eval / Release Governance；
3. Candidate 无权修改自己的 Eval root、Budget Enforcement、Release Authority 或 Governance Kernel；
4. Subject/Builder/Judge/Release Authority 逻辑隔离；
5. 无 Trigger 时稳定生产的演化强模型调用应接近零；
6. Active Working Set 有界；
7. EvolutionRun 必须可终止；
8. V1 不为 V2/V3 概念预建独立服务、数据库或状态机。
