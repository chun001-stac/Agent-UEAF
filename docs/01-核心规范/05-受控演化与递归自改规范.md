# UEAF 受控演化与递归自改规范

版本：`0.1.0-draft`  
规范状态：Draft

## 1. 范围

本文定义 UEAF 中“受控自我递归进化（Controlled Recursive Self-Improvement）”的规范语义、对象、状态、事件、端口和不可变边界。该能力用于把真实运行经验转化为可验证的候选改进，但不得让正在运行的 Agent 直接修改自身当前版本，也不得让候选控制自己的评测、发布、身份、权限或审计边界。

本文是现有核心规范的扩展：公共元数据、对象所有权、状态机、事件、端口、发布和审计语义仍以 `01-统一术语与对象模型.md`、`02-状态机与终态规范.md`、`03-跨模块契约与事件规范.md` 和 `04-端口与适配器规范.md` 为基础。

## 2. 核心原则

1. **进化产生候选，不修改当前运行体。** 任意自我修改 MUST 产生新的 `CandidateRelease` 或等价候选工件；当前 `ReleaseManifest` 不得被原地改写。
2. **Experience 不是 Prompt。** 原始 Trace、Metric、Log、Eval、Action、成本和业务反馈首先作为结构化证据存在，只有被筛选的少量信息才进入模型上下文。
3. **进化是事件驱动而非持续思考。** 没有有效 `EvolutionTrigger` 时，生产运行不得为了“持续进化”额外调用模型。
4. **Evaluator 优先确定性。** 能由程序、统计或规则验证的维度不得默认交给大模型 Judge。
5. **能力提升必须同时考虑成本。** Token、费用、延迟、复杂度和回归风险属于 Fitness 的一部分，不能被“准确率提升”自动抵消。
6. **记忆必须压缩和淘汰。** 历史证据可增长，但 Active Evolution Working Set MUST 有界。
7. **遗传算法只是策略之一。** UEAF 规范演化协议，不绑定 Genetic Algorithm、RL、Bayesian Optimization 或任一单独优化算法。
8. **Subject 与 Judge 分离。** 被优化对象、候选生成者、评测者和发布裁决者必须逻辑隔离。
9. **递归存在硬边界。** Agent 可以被 Evolution Agent 改进，Evolution Strategy MAY 被更高层优化，但 Governance Kernel 不得由同一递归链自主修改。

## 3. 演化平面

UEAF 新增逻辑上的 `Evolution Plane`。它不是新的 Runtime，也不进入每次低风险模型调用的热路径。

```text
Production Runtime
    -> Structured Evidence
    -> Trigger / Aggregation
    -> Experience Consolidation
    -> Evolution Strategy
    -> MutationProposal
    -> CandidateRelease
    -> Module 08 Evaluation & Gates
    -> Canary / Release
    -> Production Feedback
    -> next cycle
```

Evolution Plane 的 Semantic Owner 只拥有演化领域对象，不拥有 `TaskState`、`RunRecord`、`ActionRecord`、`MemoryRecord`、`EvalResult`、`ReleaseDecision` 或 `ReleaseManifest`。

## 4. Canonical 对象

### 4.1 `EvolutionTrigger`

表示“为什么现在值得启动一次演化”，而不是证明需要改动。

最小字段：

```yaml
evolution_trigger_id: string
subject_ref: string
trigger_type: anomaly | failure_cluster | cost_drift | quality_drift | new_model | new_tool | new_business_requirement | scheduled_review | human_request
window_ref: string
evidence_refs: [string]
threshold_profile_ref: string
severity: low | medium | high | critical
observed_at: timestamp
expires_at: timestamp
```

低置信单次异常 SHOULD 聚合后再触发。稳定生产系统在没有有效 Trigger 时 SHOULD 产生接近零的额外演化 Token。

### 4.2 `EvolutionExperience`

`EvolutionExperience` 是演化域对已有证据的结构化引用和归纳，不复制完整 Trace 或 Prompt。

```yaml
evolution_experience_id: string
subject_ref: string
source_refs: [string]
pattern_type: success | failure | cost | latency | safety | robustness | novelty
scope: object
observation: object
confidence: number
occurrence_count: integer
first_seen_at: timestamp
last_seen_at: timestamp
lifecycle: candidate | validated | active | consolidated | superseded | archived | deleted
supersedes: [string]
```

它与模块 04 的 `MemoryRecord` 不同：`MemoryRecord` 面向 Agent 在业务任务中的受治理跨会话记忆；`EvolutionExperience` 面向版本改进、实验选择和搜索历史，不得被默认注入业务 Agent 上下文。

### 4.3 `EvolutionLesson`

多个 Experience 经过验证和归纳后 MAY 合并为 `EvolutionLesson`，表达“在什么条件下，什么改法为什么有效或无效”。

```yaml
evolution_lesson_id: string
subject_scope: object
condition: object
conclusion: object
supporting_refs: [string]
contradicting_refs: [string]
confidence: number
status: active | superseded | archived | invalidated
```

已被稳定 Tool、Policy、Workflow、Router 或 Skill 编译吸收的 Lesson SHOULD 从 Active Working Set 退出。

### 4.4 `AgentGenome`

`AgentGenome` 是一个不可变、内容寻址的 Agent 候选能力描述，不等于正在运行的 Agent 实例。

```yaml
agent_genome_id: string
generation: integer
parent_genome_refs: [string]
model_route_ref: string
prompt_bundle_ref: string
context_policy_ref: string
memory_policy_ref: string
toolset_ref: string
workflow_ref: string
routing_policy_ref: string
skill_bundle_ref: string
runtime_compatibility_ref: string
evolution_policy_ref: string
integrity_ref: string
```

Genome 只允许引用已注册、可验证的版本化工件。改变任一 Gene 必须形成新的 Genome ID。

### 4.5 `MutationProposal`

记录“为什么改、改哪里、预计改善什么、风险是什么”。

```yaml
mutation_proposal_id: string
subject_genome_ref: string
trigger_ref: string
experience_refs: [string]
strategy_ref: string
mutable_gene_scope: [string]
change_summary: object
hypothesis: string
expected_gain: object
expected_cost: object
risk_refs: [string]
created_by: string
```

默认 SHOULD 采用 sparse mutation，只修改与当前证据相关的少量 Gene；全 Genome 无目标随机变异仅可作为显式策略。

### 4.6 `CandidateRelease`

`CandidateRelease` 是 Evolution Plane 交给模块 08 的候选，不是生产发布授权。

```yaml
candidate_release_id: string
agent_genome_ref: string
mutation_proposal_ref: string
baseline_release_ref: string
evaluation_suite_ref: string
evolution_budget_ref: string
lineage_ref: string
artifact_refs: [string]
integrity_ref: string
```

其最终发布仍必须经过模块 08 的 `QualityGateDecision`、模块 07 的 `SecurityGateDecision`、模块 09 的 `OperationalReadinessDecision` 和 `ReleaseDecision`。

### 4.7 `EvaluationSuite`

`EvaluationSuite` 只负责组合引用模块 08 已拥有的 `EvalCase`、`EvalDataset`、`EvalConfig`、确定性检查、统计检查和人工复核要求，不创造第二套 Eval 语义。

```yaml
evaluation_suite_id: string
eval_dataset_refs: [string]
deterministic_check_refs: [string]
statistical_check_refs: [string]
model_judge_refs: [string]
human_review_policy_ref: string
regression_baseline_refs: [string]
cost_profile_ref: string
```

候选不得修改用于评估自身的 Suite、阈值、保留集答案或 Judge 权限。

### 4.8 `EvolutionBudget`

```yaml
evolution_budget_id: string
max_model_calls: integer
max_input_tokens: integer
max_output_tokens: integer
max_amount: object
max_candidates: integer
max_generations: integer
max_strong_model_calls: integer
max_wall_time_ms: integer
```

预算耗尽是正常停止条件，不自动表示技术失败。

### 4.9 `FitnessRecord`

Fitness MUST 是多维记录，禁止只保存单一总分。

```yaml
fitness_record_id: string
candidate_ref: string
baseline_ref: string
capability_delta: object
quality_delta: object
safety_delta: object
robustness_delta: object
input_token_delta: object
output_token_delta: object
amount_delta: object
latency_delta: object
complexity_delta: object
regression_risk: object
verdict: better | worse | mixed | inconclusive
source_eval_refs: [string]
```

实现 MAY 计算 `EvolutionROI` 或 `IntelligenceEfficiency`，但原始分项 MUST 保留，不能用加权总分掩盖安全硬失败。

### 4.10 `LineageGraph`

记录 Genome、Mutation、Candidate、Release、失败实验和已知分支关系。历史可归档，但生产必须能从当前 `release_id` 追溯到 Genome、父版本、Mutation、Eval 和发布证据。

## 5. EvolutionRun 状态机

`EvolutionRun` 的当前阶段与最终处置 MUST 分离。

### 5.1 `EvolutionPhase`

```text
queued | collecting | analyzing | generating | evaluating | selecting | waiting | terminal
```

- `collecting`：聚合结构化证据；
- `analyzing`：形成 Failure/Success Cluster 与改进假设；
- `generating`：产生有限数量 Candidate；
- `evaluating`：通过模块 08 及确定性/统计检查获取证据；
- `selecting`：比较候选与基线并产生提交发布的建议；
- `waiting`：等待人工复核、外部评测、配额或依赖；
- `terminal`：本轮演化结束，不再生成新候选。

### 5.2 `EvolutionDisposition`

仅 `phase=terminal` 时非空：

```text
improved
plateau
budget_exhausted
no_valid_candidate
regression
safety_blocked
novelty_exhausted
manual_stop
failed
```

`improved` 只表示本轮找到至少一个通过既定比较标准的候选，不表示该候选已获生产发布；生产状态仍以 `ReleaseManifest` 为准。

## 6. 停止条件

每个 EvolutionRun MUST 至少配置以下停止条件中的三类，并始终包含预算上限：

- `fitness_target_reached`；
- `improvement_plateau`：连续 N 个候选/代次提升低于阈值；
- `budget_exhausted`；
- `max_generations_reached`；
- `no_valid_candidate`；
- `regression_guard_triggered`；
- `safety_blocked`；
- `novelty_exhausted`：新候选与已验证搜索历史高度重复；
- `manual_stop`。

EvolutionRun 结束后 Agent 可继续正常生产运行；新的有效 Trigger MAY 启动下一次 EvolutionRun。进化是间歇性生命周期，不是永久运行的后台思考循环。

## 7. Experience 压缩与记忆生命周期

演化记忆 SHOULD 遵循以下压缩链：

```text
Raw Evidence refs
  -> Episode / Pattern
  -> EvolutionExperience
  -> EvolutionLesson
  -> Strategy / Skill / Policy / Tool / Workflow
  -> AgentGenome
```

推荐生命周期：

```text
candidate -> validated -> active -> consolidated -> superseded -> archived -> deleted
```

### 7.1 Active Working Set

- MUST 有容量、Token、条目数或时间窗上限；
- 默认只包含与当前 Trigger、Gene scope 和目标环境相关的 Lesson/Experience；
- 已被更高层 Skill/Policy/Tool 吸收且无独特反例的记录 SHOULD 归档；
- 低置信、长期未使用、重复、被新证据否定的记录 MUST 可失效或删除；
- 删除与法律保留仍受全局数据生命周期规则约束。

因此“总历史存储可增长”与“模型每次看到的进化上下文增长”必须解耦。

## 8. Evaluator 层级

同一指标存在多种验证方式时，默认优先级为：

```text
Deterministic Evaluator
  -> Statistical Evaluator
  -> Small / Cheap Model Judge
  -> Strong Model Judge
  -> Human Review
```

只有前一层不能可靠回答时才升级。Coding 场景优先使用测试、类型检查、静态分析和基准；量化场景优先使用 OOS、泄漏检查、回撤、稳定性和统计检验；业务 Agent 优先使用真实完成率、SLA、重开率、费用和人工升级事实。

## 9. Evolution Strategy

UEAF MUST 把搜索/优化算法定义为可替换策略。实现 MAY 支持：

- LLM-guided sparse mutation；
- Genetic / Evolutionary Search；
- Bayesian Optimization；
- Reinforcement Learning；
- Self-reflection / Critique；
- Population Search；
- Tool/Workflow/Topology Search；
- Human-guided Evolution。

策略只能产生 `MutationProposal` 和 Candidate，不得越过 Eval、Safety、Release 或权限边界。

## 10. Immutable Constitution / Governance Kernel

以下能力默认属于不可由同一递归链自主修改的 Governance Kernel：

- tenant / identity / delegation root；
- PDP/PEP 与权限模型；
- Tool Gateway 强制副作用边界；
- Secret/Credential 管理；
- Audit 完整性和保留；
- 评测保留集、阈值根、Judge 权限边界；
- Release Authority 与 Manifest 签名；
- EvolutionBudget Enforcement；
- kill switch、数据删除与法律保留；
- 本规范定义的“Candidate 不能原地修改当前版本”规则。

如果需要修改 Governance Kernel，必须进入独立的人类/治理变更流程和新的规范或 ADR，不属于自动递归进化。

## 11. 职责分离

最低逻辑角色：

```text
Evolution Subject
  -> Proposer / Builder
  -> Candidate
  -> Evaluator / Judge
  -> Security / Operational Gates
  -> Release Governance
```

- Subject 与 Judge MUST 使用不同执行身份和权限上下文；
- Candidate MUST NOT 写入自身 Eval 证据；
- Judge MUST NOT 修改 Candidate；
- Candidate/Proposer MUST NOT 读取保留集答案；
- Release Governance MUST NOT 让候选自己签发 `ReleaseDecision` 或 `ReleaseManifest`。

## 12. 事件

至少定义以下事件：

- `ueaf.evolution.triggered`
- `ueaf.evolution.run_started`
- `ueaf.evolution.experience_validated`
- `ueaf.evolution.lesson_consolidated`
- `ueaf.evolution.mutation_proposed`
- `ueaf.evolution.candidate_generated`
- `ueaf.evolution.candidate_evaluated`
- `ueaf.evolution.candidate_selected`
- `ueaf.evolution.candidate_submitted_to_release`
- `ueaf.evolution.run_terminal_committed`

所有事件遵循公共 `EventEnvelope`、幂等、顺序和 outbox 规则。Trace/Metric 异常本身不是 `ueaf.evolution.triggered`，必须由 Evolution Trigger Owner 根据阈值和证据提交。

## 13. 端口

```text
ExperienceIngestPort(evidence_refs) -> EvolutionExperience[]
EvolutionTriggerPort(signal_window) -> EvolutionTrigger | no_trigger
EvolutionStrategyPort(trigger, lessons, genome, budget) -> MutationProposal[]
CandidateBuildPort(mutation, genome) -> CandidateRelease
EvolutionEvaluationPort(candidate, suite) -> FitnessRecord
LineagePort(candidate_or_release) -> LineageGraphRef
EvolutionBudgetPort(evolution_run_id) -> BudgetSnapshot
PromotionRequestPort(candidate_ref, evidence_refs) -> ReleaseCandidateRef
```

端口实现可以是确定性规则、小模型、强模型或外部优化器，但对外必须保持同一 UEAF 契约。

## 14. 框架级不变量扩展

1. 任何 Agent 不得直接修改自身当前 `ReleaseManifest`；所有自改产生新 Candidate。
2. Candidate 不得修改用于评估自身的 EvaluationSuite、阈值根、保留集答案、Release Authority 或预算执行器。
3. Evolution Subject、Proposer/Builder、Evaluator/Judge 和 Release Authority 必须逻辑隔离。
4. 所有 EvolutionRun 必须有预算和明确终态；不存在无限代、无限 Token 的规范模式。
5. 能力提升不能单独构成晋升理由；成本、延迟、复杂度、回归和安全必须同时评估。
6. 原始经验不得默认进入模型上下文；Active Evolution Working Set 必须有界。
7. 稳定生产在没有有效 Trigger 时不得主动消耗强模型 Token 进行持续自评。
8. Genetic Algorithm 不是 UEAF 的固定实现；Evolution Strategy 必须可替换。
9. 递归优化不得越过 Governance Kernel。
