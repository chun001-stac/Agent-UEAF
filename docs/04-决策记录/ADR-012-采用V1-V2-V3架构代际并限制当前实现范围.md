# ADR-012：采用 V1/V2/V3 架构代际并限制当前实现范围

- 状态：Accepted
- 决策日期：2026-08-14

## 背景

UEAF 已形成 Runtime、治理、受控演化以及生态共同进化的完整长期设计。若把所有未来概念同时解释为当前实现要求，会导致 Canonical Object、Registry、状态机、评测、配置和服务数量快速膨胀，增加维护与交付风险。

另一方面，直接删除 Species、Gene Pool、Ecosystem Fitness、Meta Evolution 等设计又会损失长期架构方向。

## 决策

UEAF 采用三个架构代际：

1. **V1 — Unified Agent Runtime + Controlled Evolution Kernel**：当前实现目标；
2. **V2 — Adaptive Agent Ecosystem**：未来计划；
3. **V3 — Recursive Adaptive Ecosystem**：研究与远期架构。

V1/V2/V3 是架构能力代际，不替代对象/API/Event/Schema 自身的 SemVer。

### V1 Evolution Kernel

V1 只新增以下核心 Canonical Object：

- `EvolutionTrigger`；
- `EvolutionRun`；
- `GenomeManifest`；
- `MutationProposal`；
- `EvolutionAuthorityPolicy`。

V1 必须优先复用现有 UEAF 对象：

- 候选使用模块 10 `ReleaseCandidate`；
- 评测使用模块 08 `EvalConfig` / `EvalRun` / `EvalResult` 与 Gate；
- 预算使用现有 Budget 语义并增加演化用途约束；
- 发布使用 `ReleaseDecision` / `ReleaseManifest`；
- Lineage、Fitness、Experience/Lesson 等优先作为 Projection、内部记录、Registry metadata 或 Eval dimension。

### V2/V3

V2 保留 Species、Gene Pool、Capability Transfer、Population、Ecosystem Fitness、Diversity 等正式设计，但不属于 V1 当前验收范围。

V3 保留 Meta Evolution、Dynamic Species/Niche、Ecosystem Topology Evolution、Pareto、Evolution Debt、ModelEvolutionPort 等研究方向，不得驱动 V1 实现复杂度。

## Minimum Semantic Surface

新增 Canonical Object 前必须证明其具有独立生命周期、独立 Semantic Owner、独立状态迁移或跨模块稳定契约需求。若现有对象 + ref、Projection、Registry metadata 或 Eval dimension 足以表达，则不得新增新的 Canonical Object。

## 后果

- V1 的实现与维护范围显著收缩；
- V2/V3 的长期架构仍保留并可继续讨论；
- 文档必须明确 Architecture Generation、Maturity 和 Implementation 状态；
- 未来将某项 V2/V3 能力提升到 Current 前需要新的 ADR 或本 ADR 修订；
- 现有演化文档需要把 V1 一等对象与未来概念重新分层。

## 重审条件

- V1 已稳定运行且真实规模证明 Species/Gene Pool/Ecosystem Fitness 需要成为独立领域；
- V1 的统一 `GenomeManifest` 无法覆盖必要的独立生命周期；
- 当前复用对象导致跨模块语义严重耦合；
- V2 正式进入实施阶段。
