# ADR-004：模块化单体优先，按证据拆分服务

- 状态：Accepted
- 决策日期：2026-08-14

## 背景

UEAF V1 包含十一个功能模块（01–11），但模块数量不等于部署服务数量。初期拆成大量服务会放大分布式事务、状态一致性、部署和运营成本。

## 决策

首个参考实现采用模块化单体和少量独立基础设施：

- Gateway/API 进程；
- Runtime Worker 进程；
- Control Plane 进程；
- PostgreSQL 或等价状态存储；
- 持久队列；
- 独立 Audit/Telemetry 管道。

模块通过内部端口保持边界。出现独立扩缩、信任域、合规、故障域、数据驻留或团队所有权证据后，再拆成服务。

## 后果

- 首个纵向切片更快形成；
- 事务边界和调试路径更清晰；
- 需要防止模块通过共享数据库绕过端口；
- 拆分前必须已有稳定契约和负载数据。

## 必须独立的逻辑边界

即使共进程，State/Event、Action、Audit、Secret/Credential 和 Knowledge/Memory 仍必须保持独立访问策略和所有权。

## 重审条件

- 某模块容量曲线与其他模块显著不同；
- 需要独立数据驻留或网络隔离；
- 单点故障影响不可接受；
- 团队发布节奏或合规责任需要独立；
- 经容量和故障演练证明拆分收益高于分布式成本。
