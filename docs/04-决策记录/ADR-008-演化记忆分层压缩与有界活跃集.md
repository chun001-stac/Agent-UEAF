# ADR-008：演化记忆采用分层压缩与有界 Active Working Set

- 状态：Accepted
- 决策日期：2026-08-14

## 背景

持续运行的 Agent 会产生大量 Trace、Metric、Eval、Tool、成本、反馈和失败记录。如果把所有历史都保存成文本 Memory，并在每次演化时通过向量检索大量塞回 Context，存储、检索和 Token 会持续膨胀，最终让系统“经验越多、运行越重”。

同时，完全删除历史又会导致重复犯错、重复搜索和无法解释版本 Lineage。

## 决策

UEAF 将“总历史存储”与“Active Evolution Working Set”分离，并采用分层压缩：

```text
Raw Evidence refs
  -> Episode / Pattern
  -> EvolutionExperience
  -> EvolutionLesson
  -> Strategy / Skill / Policy / Tool / Workflow
  -> AgentGenome
```

其中：

- Raw Evidence 继续由原始领域和 Evidence Plane 持有；
- Evolution Plane 主要保存引用、聚类、统计和归纳结果；
- 重复 Experience 必须可合并；
- 已被更高层 Skill/Tool/Policy/Workflow 吸收的 Lesson SHOULD 退出 Active Set；
- 失败实验通过 Lineage/Archive 保留，默认不进入模型上下文；
- Active Working Set 必须有条目数、Token、时间窗或相关性上限。

推荐生命周期：

```text
candidate -> validated -> active -> consolidated -> superseded -> archived -> deleted
```

## Memory Domain 边界

模块 04 的 `MemoryRecord` 继续表示业务 Agent 可跨会话使用的受治理记忆；模块 11 的 `EvolutionExperience` / `EvolutionLesson` 只用于版本改进和搜索历史。两者不得混为一个无限 Memory 池，也不得因为某条 EvolutionLesson 存在就自动注入业务模型上下文。

## 后果

- 历史数据库可持续增长，但模型可见上下文保持有界；
- 经验可以被“编译”为低 Token 的 Tool/Policy/Workflow；
- 需要后台 Consolidation、Archive、失效和删除流程；
- 需要保存 supporting/contradicting refs，避免压缩后丢失适用边界；
- 失败实验仍能阻止未来重复搜索，而无需常驻 Context。

## 被否决方案

### 所有经验永久保存为自然语言 Memory

否决。Token 和检索噪声随历史增长。

### 只按时间 TTL 删除

否决。高价值长期规则可能被误删，重复/失效经验反而可能长期保留。

### 只保留最新 Genome，删除失败历史

否决。会失去 Lineage、审计和避免重复探索的能力。

## 重审条件

- 出现新的外部记忆机制能证明在近零 Context 成本下可靠使用全部历史；
- 法律/监管保留策略要求更严格的删除或长期保留；
- 某业务域证明 Experience 压缩造成不可接受的信息损失。
