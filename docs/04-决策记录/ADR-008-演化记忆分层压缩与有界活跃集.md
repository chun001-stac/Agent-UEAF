# ADR-008：演化记忆采用分层压缩与有界 Active Working Set

- 状态：Accepted
- 决策日期：2026-08-14

> 术语收敛说明：本 ADR 的“历史与 Active Working Set 解耦、分层压缩、失败实验保留”决策继续有效。早期 `EvolutionExperience`、`EvolutionLesson`、`AgentGenome` 不再被解释为 V1 新的跨模块 Canonical Object；按 ADR-012 与当前 V1 核心规范，它们分别作为内部记录/Projection/metadata 表达，Genome 统一为 `GenomeManifest`。

## 背景

持续运行的 Agent 会产生大量 Trace、Metric、Eval、Tool、成本、反馈和失败记录。如果把所有历史都保存成文本 Memory，并在每次演化时通过向量检索大量塞回 Context，存储、检索和 Token 会持续膨胀，最终让系统“经验越多、运行越重”。

同时，完全删除历史又会导致重复犯错、重复搜索和无法解释版本 Lineage。

## 决策

UEAF 将“总历史存储”与“Active Evolution Working Set”分离，并采用分层压缩：

```text
Raw Evidence refs
  -> Episode / Pattern Projection
  -> Experience / Lesson internal metadata
  -> validated reusable Artifact / Profile / Policy / Skill / Tool / Workflow
  -> GenomeManifest refs
```

其中：

- Raw Evidence 继续由原始领域和模块 09/08/05 等既有语义所有者持有；
- 模块 11 主要保存引用、聚类、统计、诊断/attempt metadata 与必要的归纳结果，不复制原始真相源；
- 重复 Pattern/Experience SHOULD 合并；
- 已被更高层 Artifact/Profile/Policy/Skill/Tool/Workflow 稳定吸收的 Lesson SHOULD 退出 Active Working Set，只保留 provenance 与失效条件引用；
- 失败实验通过 parent/provenance refs、Mutation、Eval、Release 和 Archive Projection 保留，默认不进入模型上下文；
- Active Working Set 必须有条目数、Token、时间窗或相关性上限。

内部记录 MAY 使用以下生命周期作为实现参考：

```text
candidate -> validated -> active -> consolidated -> superseded -> archived -> deleted
```

该生命周期不是新的跨模块 Canonical Object 状态机。

## Memory Domain 边界

模块 04 的 `MemoryRecord` 继续表示业务 Agent 可跨会话使用的受治理记忆；模块 11 的 Experience/Lesson/Pattern 只用于版本改进、novelty、重复搜索抑制和 Working Set 构建。

两者不得混为一个无限 Memory 池，也不得因为某条 Evolution Lesson/Pattern 存在就自动注入业务模型上下文。

## 可复用资产桥梁

V1 允许把已验证经验编译为既有版本化资产：

```text
validated Mutation / production feedback
  -> stable capability/config extraction
  -> Artifact / Profile / Policy / Skill / Tool / Workflow registration
  -> provenance + compatibility metadata
```

其他 Agent 后续 MAY 通过普通 `MutationProposal(mutation_type=transfer)` 引用该已注册资产并重新执行目标侧 Eval。

这不是 V2 Gene Pool：V1 不做自动跨 Agent 发现、自动传播、Species/Population 或 Ecosystem Fitness。

## 后果

- 历史数据库可持续增长，但模型可见上下文保持有界；
- 经验可以被“编译”为低 Token 的 Tool/Policy/Workflow/Profile/Artifact；
- 需要后台 Consolidation、Archive、失效和删除流程；
- 需要保存 supporting/contradicting/provenance refs，避免压缩后丢失适用边界；
- 失败实验仍能阻止未来重复搜索，而无需常驻 Context；
- V1 不因经验压缩新增 Experience/Lesson/Lineage 真相源。

## 被否决方案

### 所有经验永久保存为自然语言 Memory

否决。Token 和检索噪声随历史增长。

### 只按时间 TTL 删除

否决。高价值长期规则可能被误删，重复/失效经验反而可能长期保留。

### 只保留最新 Genome，删除失败历史

否决。会失去 Lineage、审计和避免重复探索的能力。

### 把 Experience/Lesson 升级为新的 V1 Canonical Object

否决。V1 通过内部记录、Projection、Registry metadata 与既有 refs 已足以表达，不满足新增语义表面积的必要性。

## 重审条件

- 出现新的外部记忆机制能证明在近零 Context 成本下可靠使用全部历史；
- 法律/监管保留策略要求更严格的删除或长期保留；
- 某业务域证明 Experience 压缩造成不可接受的信息损失；
- V2 正式进入 Current，经验/能力迁移形成独立生命周期和跨模块稳定契约。
