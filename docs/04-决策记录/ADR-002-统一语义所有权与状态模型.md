# ADR-002：统一语义所有权与正交状态模型

- 状态：Accepted
- 决策日期：2026-08-14

## 背景

分布式 Agent 系统容易让 Gateway、Runtime、Orchestrator、Tool Gateway 和生产平台分别维护一套 Run 状态，并把等待阶段、技术运行阶段和业务终态放在同一枚举中。

## 决策

每种权威事实只有一个 Semantic Owner。物理 Store、State Writer 和 Projection 必须与 Semantic Owner 分开描述。

Run 使用正交字段：

- `RunPhase`：运行处于哪个技术阶段；
- `WaitReason`：如果等待，等待什么；
- `CompletionDisposition`：结束后业务语义是什么；
- `ErrorEnvelope`：失败来源、可重试性和结果确定性。

TaskState、RunRecord、WorkflowRun、NodeRun、ActionRecord 和 Business Fact 使用不同状态机。

## 后果

- API、事件、恢复和评测能够使用同一终态语义；
- 局部工具拒绝不必自动变成整个 Run 被拒绝；
- 生产平台提供持久化和租约，但不能重定义领域状态；
- 需要维护明确的局部状态到根 Run 的投影表。

## 重审条件

不重审“唯一 Semantic Owner”原则。具体状态枚举可通过新契约版本演进。
